页面状态稿 · 5 屏

封存 / 有流水 / 首拉骨架 / 网络失败 / 空流水

本页状态机有 5 态：commerceSealed（:34，判据 !isCommerceOn("coin")） → 开启后 loading（余额 -- + 骨架 3 行）→ loadFailed（余额 -- + 重试条 + 空文案） → transactions.length>0（两条流水）→ 其余（余额真值 + 「暂无流水记录」）。 页头是页面自绘的深绿带（navigationStyle: custom，无原生栏、无 tabbar）。 F01 是当前默认态（commerce.coin 缺 key 即封存）；F02–F05 画的是开关开启态。全部五屏内容均在 812px 内，无裁切。

20px · --c-text-primary · 非素材缺口
与实况的已知差异 + 数值口径（画板不修，登记在此）：
  • 默认态是封存，F02–F05 画的是开关开启态。判据 market/wallet/index.vue:34 commerceSealed = !appConfig.isCommerceOn("coin") —— 与 shop/detail 不同，本页走子闸： app-config.ts:74-76 先取 commerce.coin，缺则回退裸 key coin，两者皆缺即封存； 且总闸 commerce.enabled !== true 时无视子闸一律封存（:67）。 封存态 onShow 直接 return（:74），余额与流水两条请求都不发；本页不重定向，白卡是真实渲染分支。
  • 余额 ¥800.00 与两条流水 = mock 种子：stores/coins.ts:117-121（余额为 0 时置 80000 分）与 :220-241（DEBIT 500 分「解锁私信」、CREDIT 80000 分「签到奖励」）。 real 模式走 GET /wallet/balance + GET /wallet/transactions?page=0&size=20， 以后端钱包真值为准 ⇒ 画板金额是演示种子口径。注意种子自相矛盾： 两条流水的 balanceAfter 分别写 79500 / 80000，而余额位恒显 80000（种子未做流水回放）—— 画板按页面实际取值（800.00）画，不替种子圆账。
  • 「充值 ¥100」= 请求体常量：amountCents: 10000（:100），文案 wallet.recharge 逐字； 成功 toast 走 wallet.rechargeSuccess 插值 → 「充值成功 +¥100」。该入口仅 useMock() || isDev 出现， F05 画的就是 real 形态（无充值钮）。
  • 交友币 ≠ 积分 ≠ VIP：本页账本走 /wallet/*（交友币），shop 页积分条走签到（pointsBalance）， vip 三页走 /vip/orders。三套金额不得互相校验。
  • BASE_PROBLEM（base 缺档，本页按 scss 真值 1:1 落字面量）： --c-brand-bg-tint-strong（scss:880 = rgba(61,201,148,.12)；wallet:334 的 .vue 兜底写 .35 属过期字面量，按已知机制 §2 不采信）、 --c-overlay-text-secondary（scss:750 = rgba(255,255,255,.85)）、 --r-2xl（两个登记处均无定义，运行时靠 32rpx 兜底 —— 台账「令牌体系」一节已登记为断引用）。
  • 同域三页卡缘不成档（在册）：本页余额卡左右 --sp-4=8px、明细区同 8px， 而页头/封存卡走 --page-padding=16px ⇒ 余额卡比自己的封存卡向左越出 8px。R9-L14-D16 只收了封存卡那一半，画板照实况画。
  • 本页在 market 分包、navigationStyle: custom：无原生导航栏、无 tabbar； 无上一页时 goBack 兜底 switchTab /pages/profile/index（:123）。
