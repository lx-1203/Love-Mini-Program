页面状态稿 · 3 屏

real 首拉中（骨架） / 混合态（领取 + 已完成 + 去完成） / 全部未完成（首进）

本页状态机有 3 态：模板级 v-if="loadingRealTasks && realTasks === null"（骨架）对 v-else（列表），列表内每行再按 !task.claimable && isTaskClaimed(task) 与 taskStatusText 的 claimable → 领取 / claimed → 已完成 / 否则 → 去完成 三分配出两种整页形态。 概览卡与页头完成度不在 v-if 链内，加载屏也照样渲染——因为 tasks = realTasks ?? localTasks， 首拉期它按本地四档兜底算出「0/4 · 0 积分 · 0%」，与 F03 同值。三屏均一屏装下，无视口裁切。

14px · --c-brand-800
与实况的已知差异（画板不修，登记在此）：
  • 积分与百分比不是评分位：§3.3 留空的是合拍度/匹配度/共同点这类需要后端真值的评分。本页 progressPercent 是本页四行积分的纯函数（55/175→31%），任何审阅者都能从画面上的四个数字复算一遍，故照常回填；画板不出现任何「算不出来」的数字。
  • 加载屏的概览卡有值：概览卡在 v-if 链之外，首拉期 tasks 回落 localTasks ⇒ F01 的「0/4 · 0 积分 · 0%」与 F03 同值。若画板把 F01 的概览卡画成空白骨架，即为与源码不符。
  • 四行任务名/说明/积分全部逐字取 i18n：profile.taskProfile(Desc) / taskCheckin(Desc) / taskFirstPost(Desc) / taskVerify(Desc) / taskPoints「+{n} 积分」。积分数值 50/5/20/100 取自源码 localTasks 常量，不是画板编的。
  • 「领取」的反馈是 toast：taskClaimSuccess「领取成功！+{n} 积分」/ taskClaimFailed「领取失败，请重试」由 uni.showToast 渲染，几何非本页 CSS，故不占屏、不进 §01。
  • 令牌缺口：.task-item__status--go 与 .album-add-btn 等处的 --c-brand-800 深绿实底在 base 已登记，无缺口；本页未遇到需要替身的未登记档。
  • 本页在 profile-extra 分包，无 tabbar、无原生导航栏——页头是页面自己画的 baseline 行。
