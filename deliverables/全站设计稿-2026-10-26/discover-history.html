与实况的已知差异 / 源码缺陷登记（画板不修，按源码画）：
  • 错误态与加载态无样式：.history-loading、.history-error、.history-error__text、 .history-error__retry、.history-error__retry-text 五个类名在本页 <style> 段内 0 命中。 于是「重试」不是按钮，是一段继承页面字号的裸文本（画板如实画成带下划线的裸文本以标出可点区，真机无任何视觉提示）。 同分包 segment / people 的失败重试都是胶囊件——本页是四页里唯一没给重试件样式的。 错误文案本身也不走 i18n：兜底串 "加载推荐失败，请稍后重试" 硬写在 stores/discover/actions/fetch.ts:235， 画板照源码字面画。
  • 挽回限流两套口径：按钮文案是 discoverHistory.rewindLabel「挽回（每日限1次）」、门是布尔 hasRewoundToday， 但 store 的超额报错写的是 本次会话挽回次数已用完（最多${MAX_UNDO_COUNT_PER_SESSION}次），常量实测 = 3 （stores/discover/constants.ts:88）。日限 1 与会话限 3 同时存在，画板只呈现 UI 侧的「每日限1次」，不替产品裁定哪套是对的。
  • 统计栏恒渲染：它不在 v-if 链内，加载/错误/空三态下必然显示 0 / 0 / 0。 三格数字都有真值源（historyCards.length、historyCards.filter(direction==='right').length、passedCards.length）， 按登记表通用规则第 0 条属「照真值画」，不是留空位；F01–F03 的 4/2/2 与帧内卡片逐条对得上。
  • 渐变字只在 H5 生效：.page-title 与 .stat-num 的 background-clip: text 都写在 // #ifdef H5 里，#ifndef H5 分支分别落 --c-text-primary 与 --c-brand-800（R10-L06-D15 / D16 的可达性收口）。 本页真机是微信小程序 ⇒ 画板按纯色档画。
  • 令牌缺登记（BASE_PROBLEM · 本页剩一枚）：本页 SCSS 头用到 --c-tint-green-50（#E8F5E9，页底渐变起点）、 --c-neutral-400（$text-tertiary 别名，已跳过徽标字 / 签名行 / 挽回提示行）、 --c-tint-gray-50（#F3F4F6，$border-light 别名，挽回件与提示行的分隔线）三枚。 前两枚已在本次出图期间补进 board-base.css（实测 :233 / :241，值与真源一致），画板已改为直接引用； --c-tint-gray-50 仍未登记，画板按 §1 暂以已登记的最浅线档 --c-border-light（#EEF2F0）代画，差 5/2/1。
  • 页面内私有别名：本页把 $text-secondary 定义成 --c-neutral-500（#6B7571）， 与全站 --c-text-secondary（#4A524E）不同值；同分包另三页直接用 --c-text-secondary。 画板按本页真值取 --c-neutral-500，并在此登记为跨页不一致。
  • 页头标题档位：源码 38rpx（=19px）落 §1.3 阶梯外，画板取 --fs-3xl 18px。
  • 无分数位：本页不显示任何匹配度/合拍度/共同点数值——卡片快照里就没有该字段， 挽回成功后的匹配结果归 discover/matching 与 discover/match-success 两页。
  • 演示正文：卡片 headline / bio 是用户自填字段的演示读数（真值位存在，内容随账号）， 不是产品文案，也不参与 i18n 逐字口径；bio 两行截断（-webkit-line-clamp: 2 + mp 端 max-height: 3.2em 兜底）。
  • 本页在 discover-extra 分包，无 tabbar、无原生导航栏。
