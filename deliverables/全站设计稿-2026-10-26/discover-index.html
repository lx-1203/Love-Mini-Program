与实况的已知差异 / 留空依据（逐条）：
  • 右下匹配度绿圆环——画板不画，且该位不存在。理想图此处为「92% 匹配度」绿色细环， 产品裁定 P1-2 已撤除，后端无真分字段，画板按留空画。源码依据三处，全部实测命中： ① components/match/MatchCard.vue:120-126 注释「匹配度徽章随 §4.3 撤除 … 后端补真分列前不显示任何百分比，就绪后在此原位重建徽章」，其后紧跟一个无默认内容的空槽 <slot name="match-score" />；② 同文件样式段 「原 .match-card__score / __score-ring / __score-ring-inner / __score-value / __score-label 五段 … 样式一并删除」， 五条类名在 apps/client/src 全库 0 命中；③ 组件文件 components/common/XunmiMatchRing.vue 仍在盘上，但 grep -rn "XunmiMatchRing" apps/client/src 只命中该文件自身， 无任何 import / 标签 / 渲染条件 ⇒ 它是未被引用的死件（且其 --ring-pct 从未绑定）。 保留的让位痕迹：MatchCard.vue 的 .match-card :deep(.match-info){max-width:60%} 注释自陈「匹配度环已撤除，此 60% 上限保留不动」——所以 F01 卡面标签换行、简介两行折行是正确形态， 不是排版失误；右下留白即该 60% 上限让出来的带。回归判据：任何一屏出现百分比或圆环 = 退稿。
  • 人名。理想图为「星野」，不在画板规范 §3.4 演示真名池（小满 / 周岚 / 阿辰 / 星辰 / 小溪）内， 按真名池落「星辰」（F02 落「周岚」）。校名沿用理想图真校名「北京大学 · 设计学院」。
  • 左上距离胶囊底色。理想图是粉底白字，源码 MatchCard.vue 的 .match-card__distance 用 --c-overlay-bg-solid（= rgba(255,255,255,.9) 白底） + --c-love 粉字。按 §10「帧与源码冲突时以源码为准」画成白底粉字。
  • 配额行「今日剩余 10 次」。理想图没有这一行，它是源码新增的横切元素 （index.vue:356-360，仅登录渲染）。10 不是编造： remainingCount = dailyLimit + extraQuota − viewedCards.length， DAILY_LIMIT_TOTAL = 10（stores/discover/constants.ts:45）、首屏未看卡 ⇒ 实算 10。 游客态（F03）该行不渲染，与理想图一致。
  • tabbar 第三项文案。理想图写「寻觅」，pages.json:432 实值写「匹配」， useTabBar(2) 选中它。按源码画「匹配」。
  • NotLoggedWaiting 的宿主。登记表注把 等待页面.png / 未登录等待页面.png 记为「寻觅页内嵌态」， 实测 pages/discover/index.vue 并未引用该组件（全库唯一挂载点是 subpackages/discover-extra/likes/index.vue:668）。寻觅页自己的游客态是 F03 「卡片可预览 + 登录提示胶囊」。F04 按登记表要求出屏，画成整页顶替、不带 tabbar （其真实宿主是分包页），并在此登记宿主口径待主控裁定。
  • MatchScopeTabs 未接线。任务书点名的 components/match/MatchScopeTabs.vue 在 apps/client/src 内 0 引用（分段由 index.vue 页内自绘的 discover-header__tabs 承担），故本画板不画该组件，F01/F02 的分段按页内实现画。
  • 性别♂圆底色值。源码 MatchInfo.vue 硬写 #54A0FF，两个令牌登记处均无该档； 画板用最近的已登记档 --c-secondary-blue-400（#5B7FFF）替身，仅出现在 §02 面板， 主屏 F01–F03 的人设均为♀，不受影响。源码侧裸色值属全站 R2b-L01-D07 同类问题，不在本页修。
  • base 缺档 --c-overlay-bg-solid。该令牌在 theme/design-variables.scss:742 有真值（rgba(255,255,255,.9)），board-base.css 未登记， 画板以 --c-bg-container（不透明白）替身，差异仅为照片透过胶囊的 10% bleed。
  • 演示计数口径。本页无「好友头像行 / 共同点 / 匹配进度」类真值位； 卡片上的 2.3km、0.8km、25、24 属演示人设数据（随 mock 池），非后端真值，也不参与任何分数裁定。
  • 哭脸吉祥物素材的烧录小字已抹除（2026-10-27，本条关闭）。原状：assets/demo/mascot_cry.png 图内嘴下一行约 6px 的烧录中文标注（素材生成残留，非画板加注），F07 空态与 F08 错误态都会带到 （EmptyState 的 mascot="sad" 无条件传入，index.vue:340-345）。 处置：不重生成，按实测几何（角色本体止于第 58 行、59..64 全透明、题注为第 65..71 行列 29..41） 把第 65..71 行整带 alpha 归零，画布仍 72×72、角色一个像素没动；四处真源（包内 / uploads / full-static 备份 / 本画板 demo 副本）已同步为同一 sha256，app-assets-seed.sql 的 size 元数据 跟着改成新字节数。F07、F08 已按新素材重拍。但这不是孤例：同一批 72×72 吉祥物素材里 mascot_hug/party/phone/sleepy/surprised/tearful 与 sad.png 的底段几何与 cry 逐像素同型（行 64..71、高 7..8、宽 7..14），已目检 hug 与 sad 确认同样烧字 ⇒ 系统性素材缺陷，余下几枚待逐张目检后同法处理。
