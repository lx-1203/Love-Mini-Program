01

页面状态稿 · 7 屏

空表单 / 记录空态 / 填写中 / 图片满额 / 上传失败 / 提交中 / 提交成功

本页状态机有 7 态，来自这些实际分支： ① :class="{ 'chip--active': activeType === item.value }"（三枚类型 chip，默认 activeType = "feedback"）； ② v-if="errorMessage" 的表单错误条； ③ v-if="canAddImage"（= !isUploading && attachments.length < 3）决定「＋相机」格在不在； ④ v-for="(url, idx) in form.attachments" 的缩略图 + .image-cell__remove； ⑤ isSubmitting ? common.submitting : common.submit 的 CTA 文案档； ⑥⑦ 记录卡 v-if="submissions.length === 0" 的 EmptyState（hide-sub）与 v-for 的行列表； ⑧ handleRemoveImage() 内的 uni.showModal：系统弹窗、非页面 v-if 分支，故不占屏，在 §02 逐字段枚举。 页头是 AppShell 的白胶囊返回 + 标题 + 副标题（fixed 默认 true ⇒ 吸顶），不是渐变带； 整页高约 1000px，帧即视口 375×812，滚动位与裁切区间只写在题注 .d 里、不写进画面。

24px / 14px / 60px · 白叉压 --c-overlay-mid
与实况的已知差异（画板不修，登记在此）：
  • 反馈两页的衔接（本域口径）：本页 goHistory() → uni.navigateTo("/subpackages/profile-extra/feedback/history")（跨分包：support → profile-extra）； 行点击 goDetail(id) → 同一 URL 带 ?id=，历史页 loadQueryId() 在 300ms 后自动 toggleExpand(id)。 历史页 goBack() 是 navigateBack（回本页，页面栈与表单值都保留），失败才 switchTab 到「我的」。 两页共用 feedbackStore.submissions，本页提交成功即把新记录 unshift 进列表 ⇒ F07 的新行同时出现在历史页。完整对偶见 feedback-history.html §04。
  • 「上传中」在画面上不存在（缺陷，登记不圆场）：canAddImage = !isUploading && len < 3 使 v-if="canAddImage" 的加格在上传中整块消失， 模板里的 .image-cell__spinner 分支与 .image-cell--uploading 类永不渲染 ⇒ 用户点完相机只见＋格凭空消失、无任何进度反馈。已在 §02 存档。
  • 必填校验失败与真失败同串（缺陷）：!title || !content 守卫弹的是 feedback.submitFailed「提交失败，请稍后重试」， 与接口失败文案一字不差 ⇒ 用户无从知道是自己没填。画板如实照画，不改成「请填写标题与内容」。
  • 正文占位取 feedback.labelContent「反馈内容」＝字段名本身；源码注释里给的完整引导句「请描述遇到的问题或建议，10-500 字」需要新增键 feedback.placeholderContent，尚未落 locale。 且该句的「10-500 字」与真值 FEEDBACK_CONTENT_MAX = 5000（计数显示 0/5000）口径互相矛盾——两处都属并行车道，画板按源码实际值画。
  • 三个输入项的字段名都只挂在 <label class="sr-only"> 上，画面上没有可见标签，标题框的 placeholder 就是「标题」二字；这是可达性口径问题，不在本页修。
  • 标题框未传 maxlength：微信 <input> 不写 maxlength 时按 140 字静默截断且无提示（正文 textarea 传了 5000），画面上看不出这条隐形上限。
  • 移除确认弹窗的标题与正文都是同一句「移除」（uni.showModal 无说明句），点缩略图走系统 previewImage 全屏层：两者都不是页面 v-if 分支，故不占 §01 屏，只在 §02 枚举。
  • 演示数据口径：列表两行逐字取 services/mocks/fixtures.ts 的预置记录（标题/摘要来自 mockData.submissions.title1|2 / reply1|2， submittedAt 为 ISO 串，时间显示按 utils/time 'full' 预设算成 YYYY-MM-DD HH:mm）；F07 新增行的摘要取 mockData.submissions.queueReply、状态取 createSubmission 写死的 submitted。 表单里正在输入的标题/正文是演示人设输入串（非盘上真值、非真值位），画板上无任何分数/百分比。
  • 「选填微信号」的已填态在盘上无真值可取 ⇒ 各屏一律保持 placeholder 档，不编造微信号。
  • page { background: --c-bg-container }（R16 纯白口径）被 AppShell .shell 的 --c-bg-page 覆盖，实测页面底与吸顶头带、吸底条同为 #EEF7F2 连成一片。
  • 系统弹窗（uni.showModal）确认钮在真机是微信原生蓝，base 未登记该档 ⇒ 画板按站内主操作档 --c-brand 画替身（见回报 BASE_PROBLEM）。
  • 本页在 support 分包，无 tabbar、无原生导航栏（AppShell 传 :show-tab-bar="false"）；画板若出现 tabbar 即为错。
  • 动效与机型环境项不入静态画板：chip/按钮的 press-feedback 缩放、脉冲、键盘弹起（cursor-spacing="20"）、吸底条安全区（画板按 34px 系统几何留位）。
