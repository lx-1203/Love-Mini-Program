# 寻觅 · 全站设计稿画板 作者规范 v1

> 适用范围：`deliverables/全站设计稿-2026-10-26/` 下的所有 `<page>.html`
> 样板（唯一视觉基准）：[campus-certification.html](./campus-certification.html) 与它的出图 `frames/campus-certification/F01.png`
> 共享骨架：[assets/board-base.css](./assets/board-base.css) —— **只读，禁止在画板任务里修改**

## 0. 为什么用 HTML 画板而不是文生图

既有 19 张理想效果图（`素材/理想效果图/`）每一张都是清晰中文 UI 文字 + 精确组件几何。
文生图模型在中文 UI 标签上必然出错字/伪字/繁体混排，目检只能退稿不能纠错。
HTML 画板的文字与令牌都是真值，可复现、可 diff、可重出图——所以新基准一律走这条路。

## 1. 硬规格（出图后会被机器检查）

| 项 | 值 | 来源 |
|---|---|---|
| 画框 CSS 尺寸 | **375 × 812** | `.phone` 类，不得改 |
| 出图 deviceScaleFactor | 2.273 | `scripts/qa/shoot-design-board.mjs` |
| 出图实际像素 | **852 × 1846** | 与语料 `附近的首页.png` / `兴趣圈列表.png` / `匹配成功页面.png` 逐字相同 |
| 面积 | 1.573 Mpx | 语料 19 张全部落在 1.572–1.573 Mpx（= 1024×1536 的像素面积） |
| 换算 | rpx ÷ 2 = px | 750rpx = 375px |
| 令牌 | 只用 `board-base.css` 里已登记的 `--c-*` / `--fs-*` / `--sp-*` / `--r-*` / `--s-*` | 真值源 `apps/client/src/theme/design-variables.scss` v4.0.0 |

**禁止**：页内私有色值（`#xxx` 字面量）、`px` 硬写尺寸而不用令牌、自创圆角/阴影。
唯一例外：状态栏/信号格这类系统件的几何值。

## 2. 画板结构（照样板的四节，顺序不得变）

```
cover      品牌行 + h1 + 一段说明 + meta chips（路由/分包/状态数/画框/出图规格/令牌源/此前有无基准）
§01        页面状态稿 · N 屏     —— 每屏一个 <figure class="frame">，题注 <b>F01</b> + .t 状态名 + .d 备注
§02        组件状态规范          —— 每类交互件的全状态枚举，「缺一不可」
§03        设计令牌              —— 只列本页实际用到的档位，不抄全量色板
§04        素材依赖 + 与实况的已知差异（note 块）
footer     日期 + 出图规格
```

## 3. 内容纪律（这一节是验收重点）

1. **文案逐字取自 i18n**：`apps/client/src/i18n/locales/zh-CN.ts` 里该页 key 的实际值。
   不许自己编一句"看起来像"的文案。找不到 key 就去看模板里的 `t('...')` 路径。
2. **状态枚举取自源码的 `v-if` / 三元分支**，不是想象。画之前先把该页的状态机数清楚，
   在 §01 的 `sec__sub` 里写明"本页状态机有 N 态，来自 `<条件表达式>`"。
3. **不捏造数据**：分数类（合拍度/匹配度/共同点）按产品裁定不回填，画板上也不许出现凭空的百分比；
   需要占位就用 `—` 或空骨架，并在 §04 的 note 里写明为什么留空。
4. **演示人设用真名池**：小满 / 周岚 / 阿辰 / 星辰 / 小溪；学校用真校名（北京大学 等）。
5. **不放示例证件图/网图**：用户上传位用灰底占位（`assets/placeholder-student-card.svg` 同形态）。
6. **帧即视口**：超出 812px 的内容裁掉，**裁切说明写在题注 `.d` 里，不写进画面**。
   画面里出现"↓ 视口裁切"这类注记 = 退稿（它会污染像素比对）。
7. **tabbar 只在主包五页出现**（home / nearby / discover / messages / profile）。
   分包页画了 tabbar = 退稿。
8. **子包页无原生导航栏**：页头是页面自己画的渐变带/紧凑返回，按该页源码实际形态画。

## 4. 图标

`board-base.css` 已全局设 `svg { fill:none; stroke:currentColor }`（lucide 描边风格）。
- 描边图标：`<svg><use href="#i-xxx"/></svg>`，不要写 `fill="currentColor"`（会被全局规则覆盖成不可见）。
- 需要实心的（信号格 / wifi / 电池 / 实心圆点）：加 `class="ico--fill"`。
- 图标不够用时，在本页 `<defs>` 里补 lucide 风格 symbol，**不要改 base**。

  发现 base 有问题就在回报里写 `BASE_PROBLEM: <一句话>`，由主控统一改。

## 7. 已有理想图的 14 页：额外两条

这 14 页的画板除上面全部规则外，还必须读 [理想图登记表-14页.md](./理想图登记表-14页.md)，它逐页写明两件事：

1. **哪些位必须留空**——理想图里有分数/百分比/待回复计数/好友头像行，但产品裁定真值就绪前不显示。
   这些位画成空骨架，并在 §04 note 逐条写
   `理想图此处为 <值>，产品裁定真值就绪前不回填，画板按留空画`。
   **照抄理想图的数字 = 退稿**：那等于把"必须伪造数字"写进永久基准。
2. **哪些处已按裁定偏离理想图**——附近页（保留「附近的人」分区）、校园圈（不画好友头像行）、
   个人页（严格六段）三处**以裁定为准，不以图为准**。

其余部分（分区顺序、组件形态、密度、间距、色值、字阶、文案）**照图**，
且 §01 第一屏要能与该 PNG 逐分区对上；对不上只允许两种原因——第 1 条的留空、第 2 条的裁定偏离。
第三种差异就是画错了。

动手前先用 Read 打开对应的那张 PNG 亲眼看，不要凭登记表或代码注释推断图里长什么样。

## 8. 照片位不许留灰占位

理想图的照片位是**真演示素材**，画板如果放灰色占位块，就永远判不了封面裁切、图片密度、蒙层与文字压图关系——
而这三样正是像素级比对的主要对象。所以：

- 头像 / 照片墙 / 活动封面 / 圈子封面这类位，**必须引用盘上真实演示素材**，不许用灰块或图形占位。
- 可用素材（2026-10-26 由 `ls assets/demo` 实测生成，共 **63 件**，直接相对路径引用；
  **不要凭记忆写档名**——本节上一版写 `post-1..9` 而实际只有 1–8，害得代理引用断链）：
  - 人设全套：`xiaoman-avatar.png`、`xiaoman-photo-1..4.png`
  - 人格头像：`person-01.png … person-12.png`（`people/` 系，方形场景照）、
    `person-01-avatar.png … person-09-avatar.png`（`avatars/` 系，圆形头像）
  - 竖版人像：`p1.jpg … p9.jpg`
  - 帖子配图：`post-1.jpg … post-8.jpg`、`post-placeholder.jpg`、`campus-library.jpg`
  - 圈子封面：`circle-{photo,travel,music,sports,food,reading,sky,gaming,pets}.png`、
    `circle-cover-{photography,travel,music,sports}.jpg`、`campus-circle-cover.jpg`
  - 吉祥物：`mascot_default.png`、`mascot_smile.png`（干净）、
    **`mascot_cry.png` 底部烧有「哭泣」中文字，是出货素材的既有缺陷，画板可用但须在 §04 登记**
  - 插画：`login-illustration.jpg`、`reg-hero-illustration@3x.jpg`、`reg-success-illustration@3x.jpg`
- 池里没有的（如某页专属插画），写 `NEED_ASSET: <源路径>` 交主控补，不要自己往 `assets/demo/` 放文件。
- **引用方式**：把要用的素材复制一份到 `deliverables/全站设计稿-2026-10-26/assets/demo/`，
  画板里用相对路径 `assets/demo/<file>`。不要 `../../apps/...` 跨目录引用——画板要能独立打开。
- 复制动作由**主控统一做**（`assets/demo/` 是共享载体）；代理需要新素材时在回报里写
  `NEED_ASSET: <源路径>`，不要各自往 `assets/demo/` 里塞文件。
- 无对应真素材的位（如用户上传后的预览），才允许用灰底占位，并在 §04 note 写明为什么没有真素材。

## 9. 大文件页面的读取纪律（2026-10-26 一个代理因此零产出）

有个代理试图通读 957 行源文件，烧完额度一个字都没落盘。所以：

1. **先定位再读**：`grep -n "^<template>\|^</template>"` 拿到边界，只读 template 段。
   样式值用定点 grep 取，不通读 `<style>`；`<script>` 只在需要状态条件时定点看。
2. **第 5 步就必须落盘**：先 Write 出只含 §01 两屏的第一版，再用 Edit 增量补完。
   不许"读完再一次性写完整的"。
3. 回报里必须说清**实际读了哪几段**——这既是我复核的依据，也能暴露你有没有在猜。

## 12. 平台原生件不是画板能画的（2026-10-26 由 C5+C15 触发）

`uni.showModal` 的确认钮蓝（微信原生 `#576B95`）、`uni.showToast` 的黑浮层、系统权限弹窗、
微信胶囊按钮——这些是**平台表面**，两个令牌登记处里都没有它们，画板也**画不准**（真机上由微信渲染）。

处置：
- 不要为它们新增令牌，也不要凭印象画一个"看起来像"的蓝钮——那会造出一个永不成立的基准。
- 需要表达该状态时，在 §02 组件状态规范里用**表格行**记录「原生弹窗：标题/正文/取消/确认四件，
  由 `uni.showModal` 承担，样式不受工程控制」，帧里不出现。
- 若某屏的唯一内容就是原生弹窗，该屏不出帧，改在题注写明「本态为原生件，无自绘版面」。
