01

页面状态稿 · 9 屏

锁定 2 态 / 骨架 / 三分组各有·各空

本页状态机是两层串联： 第一层 v-if="!isUnlocked"（= sessionStore.isProfileComplete）整页换成 LockScreen， 第二层在解锁后按 loading → 三分组空态 → 三分组列表 的 v-if / v-else-if 链走。 status 各态的实际渲染条件（本页查清）： ① pending 只进「待处理」列表（pendingSignals = filter(status === "pending")）， 该列表的卡片没有状态标签节点，只有倒计时 + 拒绝/接受两钮 ⇒ getStatusLabel("pending")（「待处理」）在本页永不渲染； ② accepted 进「已接受」列表，渲染 .signal-card__status-tag--accepted「已接受」且「开聊」按钮（v-if="activeTab === 'accepted'"）； ③ declined 与 ④ 契约外的历史值 expired 合并进「已拒绝」列表 （String(s.status) === "declined" || s.status === "expired"）， 两者共用同一卡片形态但标签样式不同档（declined/expired 都是灰底中性），且都不出「开聊」； ⑤ getStatusLabel 的 default 分支把未知 status 原样上屏（无兜底文案）。

与实况的已知差异（画板不修，登记在此）：
  • status 各态渲染条件已在本页查清：个人页 likes 画板确认那页不渲染 status ⇒ 本页是唯一消费方。statusPending「待处理」这一枚标签文案在本页不可达（pending 卡片无标签节点，且 CSS 无 --pending 档），可达的「待处理」三字来自另一枚键 tabPending。这不是画板遗漏，是源码形态。
  • expired 不在契约 likes.yaml 的 status enum 内，源码把它作为历史数据兜底并入「已拒绝」分组 ⇒ 「已拒绝」Tab 一屏内可能同时出现「已拒绝」与「已过期」两枚标签（F08 即为此态）。emptyExpiredTitle/Desc 两枚 i18n 键在本页无渲染入口（无 expired Tab）。
  • 加载态只有骨架（SkeletonBlock variant="list" :rows="3"）；heartSignals.loadingText「加载中...」仅作为 label 传给读屏，画面上不出字。画板如实不画该文字。
  • 倒计时读数与进度条宽度都是 演示值（79% / 「5小时12分钟」）：二者由同一个 expiresAt 派生（countdownWidth() 与 updateCountdowns()），上线时随真实信号变化，非真值。
  • LockScreen 的「当前完善度 N%」在 F02 画成 — 且进度条不填充：该数由 profileStore.basicProfile.profileCompletion（服务端权威值）回退 sessionStore.profileCompletion 加权算出，画板无会话真值，按 §3.3 留空并标口径；文字行与条共用同一 v-if="showProgress" 判据，故二者必须同时留空、不许只留一个。
  • LockScreen 关闭钮底色：源码原写 var(--c-overlay-white-bg-mid, rgba(255,255,255,0.6))，该令牌在两个登记处均未定义（本条曾按缺令牌上报 BASE_PROBLEM）。2026-10-27 令牌断引用收口已把源码改成等值已登记档 --c-overlay-bg-strong（rgba(255,255,255,.6)），画板同步改用同一档 ⇒ 本条不一致关闭，替身 0.25 作废。
  • LockScreen 的三条权益行图标同形（三枚锁）：R15-L02-D13 给默认三条各配了 heart / graduation-cap / message 三枚异型图标，但判据是 benefitIcons[index] || lockIconSrc，而 benefitIcons 在宿主传了 benefitsOverride 时恒为空数组（LockScreen.vue:132-136）——本页正是覆盖方（lockBenefits 三条）⇒ 三行全部回落到锁形。画板按实况画三枚同形锁，不是画错；要让三行图标可辨，得改组件的覆盖口，属组件车道。
  • 本页在 tools 分包、navigationStyle: custom：页头由页面自画（粉绿渐变带 + 白圆返回键），无原生导航栏、无 tabbar——画板若出现 tabbar 即为错。
  • 门槛吃 likesPageRequirements（与「喜欢与访客」同口径），未完善资料时整页被 LockScreen 顶掉，不存在「锁定层 + 列表」同屏的形态。
