01

页面状态稿 · 6 屏

0 选 / 2 选未达标 / 3 选达标 / 5 选上限 / 保存中 / 保存成功

本页状态机有 6 态，来自这些实际分支： ① canSave = interestCount >= 3 与 :disabled="!canSave || saving" ⇒ CTA 的灰/亮两档（0 选、2 选都是灰）； ② TagSelector 内 v-if="selectedTags.length > 0"（chips）与 v-else（tagSelector.emptyTip）； ③ v-if="totalCount > 0" 的「清空」件； ④ 组计数 {{ (modelValue[group.key] ?? []).length }}/{{ group.max }} 的 0/5 · 2/5 · 3/5 · 5/5 档； ⑤ 达上限再点 → uni.showToast(tagSelector.maxReached)； ⑥ CTA 文案三元 saving ? common.loading : interestSelect.save + 成功 toast interestSelect.saved。 页面无原生导航栏、也不是 AppShell：页头是本页自绘的白圆返回钮（独占一行）+ 标题 + 副标题； 整页高约 541px（含吸底留位），一屏装得下，故各屏都是 scrollTop=0，无裁切。

04

素材依赖 · 本页在 setup 域中的位置 · 与实况的已知差异

十枚标签图标走工程既有素材；本页无照片位

config/profile-tags.ts · 十枚 interest 图标

opt.icon 逐条指向 /static/assets/icons/common/{book,trend-up,music,clapperboard,plane,camera,gamepad,cooking-pot,pencil,star}.svg， 渲染 28rpx=14px、色 --c-text-secondary。画板用同语义的 lucide 描边替身，不新增素材。

14px × 10 枚 · 与文字 gap 3px
ICONS_COMMON.BACK

页头返回箭头（common/back，40rpx=20px）压在 64rpx 白圆底上；R6-B66/D22 前是「‹」字符。 本页没有任何照片/头像位，故 §8 的真素材要求不产生 NEED_ASSET。

20px · 圆底 32px --c-bg-container
本页在 setup 域 / 注册链中的位置（源码实测）：
  • 本页不在 5 步注册链上。链是 ① setup/profile → ② setup/campus（仅学生）→ ③ setup/schedule → ④ setup/recommend-pref → ⑤「完成」= /pages/discover/index； 本页模板里没有 SetupProgress 实例（已 grep 证：同域只有 profile:753 / campus:221 / schedule:133 / recommend-pref:181 四处）， 入口唯一：pages/profile/index.vue:839 的「我的 → 兴趣选择」（openAppPath）。
  • 上一步 / 下一步：上一步是「我的」Tab（pages/profile/index）；下一步没有——保存成功后 600ms navigateBack()（栈=1 时兜底 switchTab 回「我的」）。 对照：同域 setup/profile 有两态入口（?entry=edit 编辑态与向导态），本页只有编辑型一条。
  • 因此本页没有进度条分母可对——不存在「写 5 实际 4」的问题，但也意味着用户从「我的」进来时看不到自己在链上的任何位置（与向导四页的观感不连续，属全站口径，登记不修）。
  • 缺陷 · 「至少 3 个」的提示不可达：:disabled="!canSave || saving" + 组件内 @tap="!disabled && emit('primary')" ⇒ 0–2 选时点击被吞，handleSave() 的 interestSelect.minThree「至少选择 3 个兴趣」永不触发（灰档无解释句）。 这与同域 campus 的 R11-L12-D09（撤 :disabled、改常亮 + toast 定位）是同一类问题的相反解法：三页里 interest 与 schedule/campus 的 CTA 可达性口径不一致。画板如实照画灰态。
  • 缺陷 · 保存中的文案是「加载中...」：CTA 在 saving 时取 common.loading（:144），而此刻用户做的是「保存」不是「加载」； 同域 campus 用的是 setup.campus.saveSaving「保存中...」。画板按源码现值画，不替它改成「保存中」。
  • 缺陷 · 两个计数同屏重复：已选区的 已选 N/5（tagSelector.selectedCount）与分组头的 N/5（字面拼接、不走 i18n） 在本页恒等（只渲染一组）⇒ 同一屏出现两处同值计数；且分组头那串是硬拼的，英文环境也不会翻译。
  • 缺陷 · 已选区两串文字连成一句：.tag-selector__selected-header 的 gap 只有 --sp-1=1px， 而左串是「已选标签」、右串是 selectedCount「已选 N/5」⇒ 画面上读作「已选标签已选 0/5」，「已选」重复两次且几乎不隔空。 画板如实按 1px 间距画（F01–F06 同面），不替它加间距、不改文案。
  • 缺陷 · 组配置 min:1 是死值：TagSelector 明确不校验 min（注释「取消不阻止，提交时由父组件校验」）， 实际门槛是页面的 canSave >= 3 与副标题的「至少 3 个」——三处数字（1 / 3 / 3）里只有页面的 3 生效。
  • 回填口径：onLoad 拉 getBasicProfile()，把 interestTags 回填进 selected；失败静默（catch 空注释「静默」）⇒ 已有兴趣可能显示为空而无任何提示。画板 F01 即该分支的可见形态。
  • 全量 PUT 语义：保存前先再拉一次全量资料、合并 interestTags 后整体提交（MP-R2-INTEREST-002），拉取失败时提示「网络错误」并不提交； 该分支只在 toast 层可见，画板在 §02 toast 表登记，不另立屏。
  • 本页在 setup 分包，无 tabbar、无原生导航栏（navigationStyle=custom，页头自绘）；画板若出现 tabbar 即为错。
  • page { background: --c-bg-container }（R16 纯白口径）被 .interest-page 的 --c-bg-page 覆盖 ⇒ 实测页面底与吸底条同为 #EEF7F2 连成一片。
  • toast 浮层底取 --c-text-primary（base 无黑色浮层档，就近取最深墨色，与 setup-schedule.html 同口径）； 状态栏高度取画板口径 44px（--statusbar 在 DevTools 恒 0，MP-R9-STATUS-005 已登记）。
  • 不入静态画板的动效项：chip 按压缩放、lightHaptic 反馈、600ms 返回延时、吸底条 safe-area（画板按 34px 机型几何留位）。
