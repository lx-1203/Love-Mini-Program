01

页面状态稿 · 4 屏

内容态上下两视口 / 游客态 / 空态

本页状态机分两大支：来自 isUnlocked = sessionStore.isLoggedIn || useMock()（:67）—— 未解锁走 v-else 游客骨架（F03）；解锁后走 PageStateContainer， pageState = loading | error | empty | content（:172-181，条件表达式逐条见 §02 表）。 本画板画 4 屏：F01/F02 = content 的上、下两个视口（帧即视口，812px 以下裁掉），F03 = 游客态，F04 = empty； loading / error 为容器通用态（Skeleton / ErrorState），不占屏、在 §02 枚举。 内容区各分区块的显隐条件（第二摘要卡 waitingReplyCount > 0、助手活动区 assistantActivityCount > 0、正在升温 warmPeople.length > 0、活动推荐 activityRecommendations.length > 0）逐条标注在 §04。

真值位留空 + 与理想图/实况的已知差异（逐条）：
  • 「正在等待回复」第二摘要卡——按裁定不出现。理想图此处为「正在等待回复 · 2 个聊天正在继续 · 去回复」第二卡，源码显隐条件是 v-if="waitingReplyCount > 0"（:496）；waitingReplyCount = dashboard?.todayHeart.waitingReplyCount ?? likes.likes.length - likes.mutualLikes.length（:83），游客态无此真值、条件不成立，该卡是条件渲染不出现的——产品裁定真值就绪前不回填，画板按留空画（整卡不出现，第一卡保持半屏宽，右半留空）。这就是登记表第 7 行点名的真值位。
  • 理想图第一卡副标文案是「3 个人想认识你」，源码文案为 {{ likedMeCount }} 人喜欢了你（:489，i18n messages.likedMeCount 同值）——按源码画；「3」沿用理想图演示计数，演示计数、非真值。
  • 理想图助手卡活动第二行是「周末露营活动开始报名啦~」，该硬编码文案已按 MP-R1-PAGES-MESSAGES-INDEX-011 从源码删除（现取 dashboard.assistant[0].title，:553）；画板按在册演示落点「城市露营计划」画（i18n activities.sample.cityCamp.title，与助手会话详情右屏同一活动）。「2 场活动」「角标 2」为演示计数，非真值。
  • 理想图演示人设「小林 / 小雨 / 小周 / 阿杰」不在画板规范 §3.4 真名池（该批假用户已于 2026-09-03 从源码移除，见 :124-128 注释）；画板按真名池换名为 阿辰 / 小满 / 周岚 / 小溪，分区结构、组件形态、状态档位均照图不变。
