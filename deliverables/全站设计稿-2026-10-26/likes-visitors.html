与实况的已知差异 / 源码缺陷登记（画板不修，按源码画）：
  • 恒 false 死分支（本页唯一一处）：featureFlags.membershipEnabled 在 config/feature-flags.ts:40 硬编码 false（Phase Feedback6「会员先不上线」）， 于是 .exposure-bar「提升曝光」条永不渲染，连带 handleUnlock() 的 VIP 免费放行分支、 goToExposure() 的跳转分支全部不可达（只剩「会员功能暂未开放」toast 那条路，而入口本身看不见）。 故 F01–F07 一律不画该条，也不为它留空骨架。
  • 配置缺省恒 false（不是代码死分支）：commerceCoinOn = isCommerceOn("coin") 要求 commerce.enabled === true 且子闸为 true，而 switches 初值是空对象（缺省即封存，与全站其它开关「缺失默认开放」相反）。 ⇒ 解锁条与金币标签在后端未下发开关时同样不渲染。本页两态都画：F03 = 开关开，其余屏 = 缺省封存。
  • 金币解锁标签既无独立样式、参数也空转：模板写 class="list__tag list__tag--coin"， 但 .list__tag--coin 在本页 <style> 段 0 命中 ⇒ 它与「年龄 / 同城」两枚同色同形，付费提示毫无区分； 且 likesVisitors.tagUnlockHint 的真值是「解锁后查看完整资料」，不含 {coins} 占位符， 模板却传了 { coins: unlockCost }——单价永远上不了标签。画板按实况画成三枚同形标签。
  • 令牌缺登记（BASE_PROBLEM）：.list__lock 的叠层底取 --c-overlay-white-bg-strong-mid（rgba(255,255,255,.35)）， 该令牌在 design-variables.scss:918 有值但 board-base.css 未登记；源码自带同值 inline fallback， 画板按 fallback 值画，需主控把该档补进 base 后改为引用令牌。
  • 概览栏只有一格是 R12-L07-D01 的撤承诺结果（ProfileStatsView 无 visitorsCount、 原「今日浏览量」是把喜欢数夹进浏览量的假读数）。画板按撤除后形态画单格，不画三格、也不给撤掉的两位留骨架。
  • 演示计数口径：F01–F03 的「今日访客 3」= visitors.filter(v => v.isNew).length， 与「我的访客」badge 同源同值（3）；「喜欢我的」badge 6 = likedBy.length = F01 帧内行数。 帧内行数与计数逐条对齐，不出现只有数字没有对应行的情况。
  • 打码头像的圆形轮廓会被模糊糊掉：源码把 border-radius: --r-full 与 filter: blur(14rpx) 写在同一个 .list__avatar--blur 节点上（圆角先裁、模糊后作），于是圆边被糊成软方角、内容溢出到圆外一圈。 画板按同一写法复现（F03 三个打码位），不改法——真要收口得把 blur 挪到内层图、外层只裁圆，属源码侧改动。
  • 行内正文（headline）是用户自填字段的演示读数；时间 M/D 由 formatTime() 从 likedAt / visitedAt 派生 （iOS 解析坑已在 R4-00019 修，两页同源）。
  • 本页在 discover-extra 分包，无 tabbar、无原生导航栏（navigationStyle: custom，返回件由页面自绘）。
