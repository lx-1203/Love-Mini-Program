页面状态稿 · 9 屏

预检索 2 / 用户 3 / 学校 2 / 标签 2

本页状态机有 9 态，来自两级 v-if / v-else： 外层 v-if="!searchStore.isSearching && searchStore.posts.length === 0"（index.vue:322） 决定「预检索区」还是「结果区」；结果区内再按 activeTab 三分（:434 / :459 / :504）。 注意分组顺序：胶囊条按 users / tags / schools 排（标签在中间）， 而模板分支是 users → schools → v-else(标签)（学校在前、标签兜底），两轴顺序不一致，按源码各自形态画。 预检索区另有一档「热搜」分支（v-if="hotSearches.length > 0"）： 热搜条目是后端 /api/v1/search/hot 的榜单数据、mock 档恒 0 条（stores/search.ts:69）， 按 §3.3「不捏造数据」不在 §01 造一份榜单，其条目形态在 §02 以骨架枚举并标口径。

与实况的已知差异（画板不修，登记在此）：
  • 热搜不造榜：热搜区（v-if="hotSearches.length > 0"）在 mock 档恒不渲染（stores/search.ts:69 直接置空数组），后端 /api/v1/search/hot 亦无数据。名次号 + 词条是一份有承诺的榜单，按 §3.3 不在 §01 造数据，改在 §02 以形态枚举并把词条位写成 —。此为在册数据缺口（源码注释自登记 NEEDS-DATA），非画板遗漏。
  • 搜索历史上限 10 条（HISTORY_LIMIT，本机 storage），F01 的三条 chip 是演示值，词条取自仓内既有标签名与校名（#校园日常 / #找搭子 / 北京大学），未新造词。
  • 分组顺序两轴不一致：胶囊条是 用户 / 标签 / 学校，模板分支是 用户 → 学校 → v-else(标签)。F08 的「标签分组」在源码里是 v-else 兜底分支，不是显式判据——若将来新增第四分组，它会静默接走帖子列表。
  • 「校园主页 / 收起」两枚尾件文字是模板内硬编码中文（未接 i18n，index.vue:478）；预检索名录下那行说明「预检索起点，与所选分组无关」同样硬编码（R14-L07-D20 的在册口径）。
  • 用户分组没有错误态：runTabSearch() 的 catch 把 users 置空数组，接口失败与零结果在画面上同一形态（都落 search.noResult）。画板不为它补一枚错误屏。
  • 结果行样式源码写 background: #ffffff（index.vue .user-row, .school-row）——是硬编码色值而非令牌，与同页其它处的 --c-bg-container 同值不同源；画板用 --c-neutral-0 落地，该 R6 类问题留源码车道。
  • 热搜前 3 名次号取 var(--color-primary, #ff6b81)：--color-primary 在两处令牌登记处均无定义（派发台账 已列为断引用），实际由兜底 #ff6b81 生效 ⇒ 画板用同值已登记档 --c-romance。
  • 吸顶搜索栏右端预留 calc(var(--capsule-right,7px) + 85px) 给微信胶囊，故本页不画胶囊、右侧留白属正常形态；帧内可见的「取消」按钮被该预留带挤在胶囊左侧。
  • 「校园主页」内联预览不是内联的：.campus-preview 是 v-for 之后的同级节点（index.vue:480），故无论展开哪一行，预览块恒落在整张学校列表的末尾，不贴着被点的那一行（F06/F07 按此画）。尾件写「收起」时，用户视线里那一行下方仍是下一条学校——属源码形态，画板如实保留，登记待裁定。
  • NEED_ASSET：默认头像真身是 apps/client/src/static/assets/default-avatar.jpg（IMAGE_PATHS.DEFAULT_AVATAR），未 staged 到 assets/demo/ ⇒ §02「两者皆空」那一格的头像位暂以灰圆承形，等主控补素材后替换。本页其余头像/配图位均已引用盘上真素材，无灰块。
  • 本页在 tools 分包、navigationStyle: custom：返回是页面自画的 44px 圆钮（R10-P2-008 补），无原生导航栏、无 tabbar。
