01

页面状态稿 · 7 屏全流程

默认 → 填写中 → 校验错误 → 提交中 → 成功 / 失败 → 契约对齐变体

主链路六态 + 一屏「后端契约对齐变体」。表单卡上提 32px 骑压插图下缘形成层次；插图左上留白区正好承载标题组。

⚠ 与现有后端契约的一处硬冲突，落地前必须拍板： 现有 POST /v1/auth/register（services/auth.ts · registerUser）要求 nickname 与 birthDate 必填，且出生日期用于 3-N 未成年人保护（后端校验未满 18 周岁返回 403 MINOR_NOT_ALLOWED）。 本稿主链路（01–06）按需求只保留手机号 / 验证码 / 密码 / 协议四要素，直连现后端会被 400 拒绝。
  • 方案 A（推荐）：注册页只收账号四要素，昵称与出生日期后移到「完善资料」第一步（即流程图的 02 基础资料），后端把这两项改为可选或拆两段式接口。
  • 方案 B（零后端改动）：直接采用 07 变体，注册页内补昵称与出生日期，一次注册到位。
