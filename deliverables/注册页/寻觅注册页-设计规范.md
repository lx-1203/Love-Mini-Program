## 1. 页面定义与信息架构

### 1.1 页面职责

注册页只做一件事：**用最少的步骤拿到一个可登录的账号**。昵称、头像、兴趣、认证全部后移到「完善资料」流程（对应资料填写 12 步的 02 基础资料及之后）。

### 1.2 结构总览（375 × 812）

| 区块 | 尺寸 / 位置 | 说明 |

| 标题组 | 左 24 · 上 104 | 眉题 9.5px / 主标 26px / 副标 12.5px |
| 顶部插图 | 375 × 240 · 顶部全出血 | 底部 52px 渐隐过渡到页面底色，消除图片与底色的硬接缝 |

### 5.1 输入框 Field

高 48px（`--btn-height-md` 96rpx）· 圆角 12px · 内边距 0 14px · 图标 18px 左置 · 间距 10px。

| 状态 | 底色 | 边框 | 图标/文本 |
|---|---|---|---|

| filled | `#F7FAF9` | `1px #EEF2F0` | 文本 `#1A1E1C` 500 |
| error | `#FEF5F6` | `1.5px #E5454D` + 光环 | 图标转红 + 下挂行内错误 |
| disabled | 原色 55% 透明 | 不变 | 禁输入禁聚焦 |
| clearable | — | — | 有内容且聚焦时显示 15px 清空按钮 |

### 5.2 验证码按钮 SmsButton

高 32px · 圆角 999px · 内边距 0 12px · 字号 12px/700。

| 状态 | 样式 | 规则 |
|---|---|---|
| idle | `#36C99A` / 白字 | 手机号格式通过才可点；否则点按抖动 + Toast「请先输入正确的手机号」 |
| sending | `#D1F5E7` / `#1F8D6A` + 转圈 | 请求期禁止重复点击 |
| countdown | `#EEF2F0` / `#9AA39F` | 60s 递减；以时间戳为基准（页面隐藏仍计时，回前台刷新） |
| disabled | `#EEF2F0` / `#9AA39F` | 提交中 / 表单锁定时禁用 |

### 5.3 密码可见性与强度

- 眼睛 20px，`#C2CAC6`，聚焦转 `#6B7571`；切换只改显示，不改值与光标位。
- 强度条 3 格，高 4px、间距 4px，实时刷新。

| 档 | 判定 | 条色 | 文案色 |
|---|---|---|---|
| 弱 | `len<8` 或仅数字/仅字母 | `#E5454D` | `#E5454D` |
| 中 | `len≥8` 且含字母+数字 | `#F59E0B` | `#B87400` |
| 强 | `len≥10` 且含大小写或符号 | `#36C99A` | `#1F8D6A` |

### 5.4 勾选框与协议

- 框 16×16 · 圆角 4px · 边框 `1.5px #DDE3E0`；选中 `#36C99A` + 白色对勾（10px）。
- 进入页面**一律未勾选，不预选**（合规要求）。
- 未勾选点注册：勾选框红框 + 光环、协议行转红、勾选框左右抖动 4px × 2 次、Toast 提示。
- 《用户协议》《隐私政策》各自跳内嵌 webview，**点击不得改变勾选状态**。

### 5.5 主按钮

高 48px · 圆角 12px · 字号 15px/700 · 字距 0.4px。

| 状态 | 样式 | 说明 |
|---|---|---|
| disabled | `#DCE5E2` 纯色 / 白字 / 无阴影 | 表单不完整时；仍可点按，给出「哪里没填对」Toast |
| enabled | 135° 渐变 `#36C99A→#55D5A7` + 品牌阴影 | 按下 `scale .98` + 透明度 .92，100ms |
| loading | 透明度 .72 + 白色转圈 | 全表单锁定、验证码按钮禁用；**最短展示 400ms** 防闪烁 |
| 防重复 | — | loading 期忽略一切点击；同一手机号 60s 内仅一次注册请求 |

### 5.6 反馈

| 类型 | 样式 | 时长 |
|---|---|---|
| 成功 Toast | 黑底 92% / `#7CF0C4` 图标 / 12.5px | 1500ms（`--d-toast-short`） |
| 失败 Toast | 黑底 92% / `#FF9A9F` 图标 | 2000ms（`--d-toast-normal`） |
| 行内错误 | `#E5454D` 12px + 13px 警示图标 | 常驻，该字段重新输入才清除 |

> 分层原则：**行内错误管「哪个字段错了」，Toast 管「整次操作的结果」**；两者同时出现时行内优先。

## 6. 交互逻辑与状态机

### 6.1 校验规则

| 校验项 | 规则 | 触发时机 |
|---|---|---|
| 手机号 | `/^1[3-9]\d{9}$/`；输入自动格式化为 `138 8888 8888` | 失焦 + 提交前；**输入中只清错误不报错** |
| 验证码 | 6 位纯数字；仅数字键盘；自动跳下一位 | 提交前 |
| 密码 | 8–20 位，须含字母 + 数字；禁空格与全角 | 实时（强度条）+ 提交前 |
| 确认密码 | 与密码全等 | 密码框失焦后实时比对 |
| 协议 | 必须勾选 | 仅提交时校验（不在输入中打扰） |

### 6.2 验证码链路

```text
点击「获取验证码」
  → 手机号未过格式校验 → 字段抖动 + Toast，不发请求
  → 通过 → 按钮转 sending → POST /v1/sms/send-code
      → 成功 → Toast「验证码已发送至 138****8888」→ 进入 60s 倒计时
      → 失败 → Toast 具体原因（频控 / 网络异常）→ 回到 idle，可立即重试
```

倒计时用**时间戳基准**（`endTime = Date.now() + 60000`），页面隐藏不中断，回前台按剩余时间刷新 —— 避免小程序切后台后 `setInterval` 被冻结导致的假倒计时。

### 6.3 注册链路

```text
点击「注 册」
  → 逐项校验（手机号 → 验证码 → 密码 → 确认密码 → 协议）
      → 任一失败 → 定位到首个错误字段：红框 + 行内错误 + 抖动 + 键盘拉起，流程终止
  → 全部通过 → 按钮 loading，全表单锁定（最短展示 400ms）
  → POST /v1/auth/register
      → 成功 → 写入 token/refreshToken → 跳「注册成功页」
      → 失败 → 按错误码分支：
          PHONE_ALREADY_REGISTERED → 手机号字段 error + Toast「已注册」+ 出现「用这个手机号登录」次级按钮
          SMS_CODE_INVALID          → 验证码字段 error + Toast「验证码不正确或已过期」
          MINOR_NOT_ALLOWED (403)   → Toast「未满 18 岁暂无法注册」
          网络/超时                  → Toast「网络异常，请稍后重试」，表单解锁、已填内容保留
```

**失败后不得清空用户已填内容** —— 只解锁表单与按钮，密码框重新置为密文。

## 7. 错误文案规范

统一句式：**说清哪里错 + 怎么改**；不用「输入有误」这类无信息量的说法。

| 场景 | 文案 |
|---|---|
| 手机号为空 | 请输入手机号 |
| 手机号格式错误 | 手机号格式不正确，请输入 11 位手机号 |
| 未填验证码点获取 | 请先输入正确的手机号 |
| 验证码为空 | 请输入短信验证码 |
| 验证码位数不足 | 验证码为 6 位数字 |
| 验证码错误/过期 | 验证码不正确或已过期，请重新获取 |
| 发送频控 | 发送过于频繁，请稍后再试 |
| 密码为空 | 请设置登录密码 |
| 密码过短 | 密码至少 8 位，需包含字母和数字 |
| 密码纯数字/纯字母 | 密码需同时包含字母和数字 |
| 密码含空格/全角 | 密码不能包含空格或全角字符 |
| 确认密码不一致 | 两次输入的密码不一致 |
| 协议未勾选 | 请先阅读并勾选同意《用户协议》和《隐私政策》 |
| 手机号已注册 | 该手机号已注册，可直接登录 |
| 未满 18 岁 | 未满 18 岁暂无法注册 |
| 网络异常 | 网络异常，请检查网络后重试 |
| 服务异常 | 服务暂时不可用，请稍后重试 |

```text
   ├─ reg-bg-atmosphere@3x.jpg          768×1664  整页背景氛围图
   └─ reg-decor-elements@3x.jpg         1024×1024 装饰元素总览（白底）
```

素材画布：`寻觅注册页-素材.miora`（项目根目录，4 件同源归档）。

### 8.2 命名规则

```text
reg-{用途}-{可选修饰}@{倍率}.{ext}
```

- 页面前缀 `reg-` 固定，避免与全站素材撞名；
- 倍率以 375px 设计稿为 1x 基准：页头插图显示 375×240，成图 1250×800 ≈ 3.3x，记 `@3x`；
- 格式统一 JPEG（主体为摄影级渐变插画，JPEG 体积显著小于 PNG；小程序主包有 2MB 门禁，JPEG 更安全）。

### 8.3 落地到工程时的去向（供下轮参考）

| 素材 | 目标路径 |
|---|---|
| 页头 / 成功 / 背景插图 | `apps/client/src/static/assets/images/register/`，并在 `config/images.ts` 的 `IMAGE_PATHS.REGISTER` 下注册常量 |
| 变更同步 | 依 `素材资产管理规范.md` 三处同步：`src/static` + `static-local-backup/full-static` + api `app-assets`，real 模式需 `media_asset` 注册 |

### 8.4 图标（非 AI 生成）

| 图标 | 用途 | 风格 |
|---|---|---|
| mobile / message / lock / shield-check | 四个字段前缀图标 | lucide 24×24 · 1.8 描边 |
| eye / eye-off | 密码可见性 | 同上 |
| check / check-circle / alert / x | 勾选 · 成功 · 警示 · 清空 | 同上 |
| chevron-left | 返回 | 同上 |
| user / cake | 变体页昵称 / 生日 | 同上 |

> 结论：**小尺寸 UI 图标一律走 SVG 体系**。AI 生成图标在 36rpx 下必虚、且多张之间风格会漂；工程已有 `IMAGE_PATHS.ICONS_EMOJI` 同源资产，直接复用。本 HTML 设计稿内的所有图标即此套 SVG 的真实渲染，源码 `<symbol>` 区块可直接摘用。

## 9. 关键决策记录

| # | 决策 | 理由 |
|---|---|---|
| 1 | 注册只收账号四要素，资料后移 | 与「打造我的恋爱名片」12 步流程衔接；注册页越长流失越高 |
| 2 | 表单卡骑压插图 32px | 建立层次；插图左上留白正好承载标题组，不额外占高度 |
| 3 | 密码规则收紧到 8–20 位含字母+数字 | 实名交友产品的合理下限；客户端更严、后端更松在安全上兼容 |
| 4 | 主按钮 disabled 态仍可点 | 置灰不可点会让用户不知道「哪里没填对」；点按给出定位提示的转化更好 |
| 5 | 倒计时用时间戳基准 | 小程序切后台 `setInterval` 冻结，`setInterval` 递减会出现假倒计时 |
| 6 | 配色沿用工程令牌，不采用流程图板近似色 | 一个令牌一个值，避免后续全局换色漏改 |
| 7 | 本轮零代码改动 | 用户拍板「先出设计稿」，素材不落入 `src/static`（避开 prepare-static 风险） |
