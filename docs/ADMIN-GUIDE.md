## 0. 后台重构说明（v2.0.0）

> 后台已参照 eladmin 架构完成重构，本手册各章节描述的**操作目标不变**（用户管理、内容审核、活动上下架、论坛分域、商业模式等），但**页面入口、菜单结构、权限模型已升级**。使用前请先阅读本节。

### 0.1 新后台（apps/admin）

- **入口**：默认端口 `5177`（本地开发）/ 生产环境见部署配置
- **技术形态**：Vue3 + Vite，eladmin 风格布局（深色侧边栏 + 动态菜单 + 多标签页 + 面包屑）
- **核心能力**：
  - **动态菜单**：菜单由后端下发（`GET /v1/admin/menus/current`），按当前登录角色自动渲染
  - **角色权限**：`SUPER_ADMIN`（超级管理员，全量）/ `ADMIN`（校区管理员，仅本校区数据）
  - **多租户数据隔离**：校区管理员只能看到/操作本校区的用户、活动、论坛、商业数据，越权返回 403
  - **分域独立页面**：论坛（村落动态/兴趣圈/校园圈/评论）、商业模式（VIP/兑换码/钱包/红包/商城）各自独立菜单页
  - **活动上下架**：活动列表页支持发布/下架/编辑/报名查看/CSV 导出
- **登录**：超级管理员账号由部署配置注入——首次部署通过环境变量 `ADMIN_OPENID` / `ADMIN_INITIAL_PASSWORD_HASH` 初始化（见 `.env.example`，哈希生成方法见其中注释），不使用任何公开测试账号；校区管理员账号由超级管理员在「系统管理 → 管理员管理」中创建并绑定高校

### 0.2 旧后台回退（apps/admin-legacy）

- **入口**：端口 `5178`，仅作**回退备份**保留
- 如新后台出现 P0 问题，可用旧后台临时顶替；两者共用同一后端 API 与数据库
- 日常运营请使用新后台（apps/admin）

### 0.3 模块与页面入口映射

| 本手册章节 | 新后台菜单路径 |
|------------|----------------|
| 用户管理 | 用户内容 → 用户管理 / 校园认证 / 举报 / 反馈 / 敏感词 |
| 内容审核 | 论坛 → 村落动态 / 兴趣圈 / 校园圈 |
| 活动管理 | 活动 → 活动管理 / 活动报名 |
| 商业模式 | 商业 → VIP / 兑换码 / 钱包 / 红包 / 商城 |
| 系统配置 | 系统 → 高校管理 / 菜单 / 角色 / 字典 / 审计日志 / 在线用户 |

## 2. 账号与权限

### 2.1 登录

1. 访问 https://admin.campuslove.example.com
2. 输入用户名与密码
3. 点击「登录」

**安全提示**：
- 密码长度 ≥ 12 位，包含大小写字母、数字、特殊符号
- 密码每 90 天强制更换（运营侧约定，系统当前不强制）
- 登录失败时页面提示「账号或密码错误」；账号被禁用时提示「账号已被禁用」
- 当前无 TOTP 二次验证与异地登录邮件提醒，请通过强密码与账号禁用机制保障安全

### 2.2 账号管理（仅超级管理员）

#### 2.2.1 创建管理员账号

1. 进入「系统配置 → 管理员列表」
2. 点击「新增管理员」
3. 填写：姓名、手机号、角色、初始密码、管辖校区（校区管理员必填）
4. 创建后账号即刻可用，使用初始密码登录（当前无邮件通知，请线下告知初始密码）；
   建议首次登录后修改密码

#### 2.2.2 修改权限

1. 进入「系统配置 → 管理员列表」
2. 找到目标管理员，点击「编辑」
3. 调整角色或自定义权限
4. 保存后立即生效

#### 2.2.3 禁用账号

1. 进入「系统配置 → 管理员列表」
2. 找到目标管理员，点击「禁用」
3. 确认禁用原因
4. 账号立即无法登录，已建立的会话自动失效

#### 2.2.4 重置密码

1. 进入「系统配置 → 管理员列表」
2. 找到目标管理员，点击「重置密码」
3. 重置后使用新初始密码登录（当前无邮件通知，请线下告知新密码）；
   建议登录后立即修改密码

## 3. 仪表盘（Dashboard）

### 3.1 实时数据

#### 3.1.1 核心指标

- **DAU**：今日活跃用户数
- **新增用户**：今日新注册用户
- **匹配数**：今日匹配成功对数
- **消息量**：今日发送消息总数
- **帖子数**：今日新发话题/表白/树洞
- **举报数**：今日待处理举报
- **反馈数**：今日新增反馈

#### 3.1.2 趋势图表

- 7 天 / 30 天 DAU 趋势
- 7 天 / 30 天新增用户趋势
- 7 天匹配成功率
- 7 天消息量趋势
- 各校区用户分布饼图
- 各时段活跃度热力图

### 3.2 业务监控

#### 3.2.1 关键指标

- **匹配成功率**：互相喜欢 / 总喜欢次数
- **消息响应率**：收到消息后 24 小时内回复率
- **VIP 转化率**：VIP 用户 / 总用户
- **留存率**：次日 / 7 日 / 30 日留存
- **平均使用时长**：人均日使用时长

#### 3.2.2 异常告警

- DAU 同比下降 > 20%
- 匹配成功率下降 > 5%
- 举报数激增 > 50%
- 错误率 > 1%
- API P99 > 2s

异常告警显示在 Dashboard 顶部红色横幅，点击查看详情。

### 3.3 系统健康

- **API 状态**：UP / DOWN（来自 `/actuator/health`）
- **数据库连接**：正常 / 异常
- **Redis 连接**：正常 / 异常
- **磁盘使用率**：百分比
- **JVM 内存**：使用率
- **慢查询数**：近 1 小时慢查询数

## 4. 用户管理

### 4.1 用户列表

#### 4.1.1 查看用户

路径：用户管理 → 用户列表

**搜索条件**：
- 用户 ID
- 昵称（模糊匹配）
- 手机号
- 学校
- 注册时间范围
- 状态（正常 / 已封禁 / 待审核）
- VIP 状态（VIP / 普通）
- 认证状态（已认证 / 未认证）

**列表字段**：
- 用户 ID
- 头像
- 昵称
- 性别
- 学校
- 注册时间
- 最后活跃时间
- VIP 状态
- 认证状态
- 账号状态
- 操作（查看 / 编辑 / 封禁）

#### 4.1.2 查看用户详情

点击用户进入详情页，可查看：

- **基本信息**：昵称、性别、生日、学校、校区、入学年份
- **认证信息**：学生证照片、邮箱、认证时间
- **照片墙**：所有上传的照片
- **个人视频**：上传的视频
- **匹配历史**：历史匹配对象列表
- **聊天记录**：仅查看元数据（不含内容），需更高权限
- **发布内容**：话题、表白、树洞列表
- **举报记录**：被举报与举报他人记录
- **登录记录**：最近 30 次登录 IP 与设备
- **VIP 记录**：购买记录、消费记录

### 4.2 用户操作

#### 4.2.1 封禁用户

1. 在用户详情页点击「封禁」
2. 选择封禁原因：
   - 色情低俗
   - 政治敏感
   - 谩骂侮辱
   - 广告引流
   - 诈骗
   - 人身攻击
   - 骚扰
   - 其他
3. 选择封禁时长：
   - 7 天
   - 30 天
   - 永久
4. 填写封禁说明（必填，≥ 20 字）
5. 是否通知用户（默认通知）
6. 点击「确认封禁」

**封禁效果**：
- 用户立即被踢下线
- 无法登录小程序
- 个人主页对他人不可见
- 已发布内容仍保留（除非单独删除）

#### 4.2.2 解禁用户

1. 在用户详情页点击「解禁」
2. 填写解禁说明
3. 点击「确认解禁」

**解禁效果**：
- 用户可正常登录
- 个人主页恢复可见
- 历史数据保留

#### 4.2.3 重置资料

如用户资料违规（如头像违规），可重置：

1. 在用户详情页点击「重置资料」
2. 选择重置项：头像 / 照片墙 / 个人视频 / 个人简介
3. 填写重置原因
4. 点击「确认重置」

重置后相关内容清空，用户需重新上传。

### 4.3 校园认证审核

#### 4.3.1 待审核列表

路径：用户管理 → 认证审核

显示所有待审核的学生认证申请。

#### 4.3.2 审核流程

1. 查看用户提交的学生证照片
2. 核对信息：
   - 学校是否与注册学校一致
   - 姓名是否与昵称匹配（仅参考）
   - 学号格式是否合理
   - 有效期是否未过期
3. 点击「通过」或「拒绝」
4. 拒绝需填写原因（如：学生证模糊、学校不一致、已过期）

#### 4.3.3 审核标准

**通过条件**（全部满足）：
- 学生证清晰可辨
- 学校名称与注册一致
- 在有效期内
- 包含本人姓名与学号

**拒绝条件**（任一触发）：
- 照片模糊无法辨认
- 学校不一致
- 已过期
- 非学生证（如身份证、驾照）
- 疑似伪造

#### 4.3.4 审核时效

- 提交后 24 小时内审核完成
- 超时未审核系统自动提醒
- 紧急申请（VIP 用户）优先处理

## 5. 内容审核

### 5.1 审核列表

#### 5.1.1 待审核内容

路径：内容审核 → 待审核

显示所有机审疑似违规的内容，按严重程度排序。

**内容类型**：
- 话题动态
- 表白墙
- 树洞
- 评论
- 用户头像
- 用户照片墙
- 用户个人视频

**违规类型**：
- 色情低俗
- 政治敏感
- 谩骂侮辱
- 广告引流
- 暴力血腥
- 违法犯罪
- 其他

#### 5.1.2 审核操作

1. 查看内容详情
2. 点击「通过」或「删除」
3. 删除需选择违规类型
4. 是否处罚用户（默认不处罚，严重违规勾选）
5. 是否通知用户（默认通知）

### 5.2 已发布内容管理

#### 5.2.1 搜索已发布内容

路径：内容审核 → 内容列表

支持按用户、类型、时间、关键词搜索。

#### 5.2.2 删除内容

1. 找到目标内容
2. 点击「删除」
3. 选择违规类型
4. 填写删除原因
5. 是否处罚用户
6. 点击「确认删除」

#### 5.2.3 加精 / 置顶

优质内容可加精或置顶：

1. 找到目标内容
2. 点击「加精」或「置顶」
3. 选择置顶时长（1 天 / 3 天 / 7 天）
4. 点击「确认」

### 5.3 审核规范

详见 `docs/content-moderation-standards.md`（如存在），核心要点：

- **色情低俗**：暴露、性暗示、色情描述 → 删除 + 永久封禁
- **政治敏感**：涉政、辱华、煽动 → 删除 + 永久封禁 + 上报
- **谩骂侮辱**：人身攻击、侮辱性语言 → 删除 + 警告/封禁
- **广告引流**：二维码、微信号、外链 → 删除 + 警告
- **暴力血腥**：暴力描述、血腥图片 → 删除 + 封禁
- **违法犯罪**：诈骗、传销、违禁品 → 删除 + 永久封禁 + 报警

## 6. 举报处理

### 6.1 举报列表

路径：举报处理 → 举报列表

**举报类型**：
- 用户举报
- 内容举报
- 消息举报

**优先级**：
- 紧急（诈骗、人身威胁）：1 小时内处理
- 严重（色情、政治）：4 小时内处理
- 一般（广告、骚扰）：24 小时内处理

### 6.2 处理流程

1. 查看举报详情（举报人、被举报人、举报类型、举报描述、证据截图）
2. 查看被举报内容/用户历史
3. 判断是否违规
4. 处理操作：
   - **驳回**：举报不成立，通知举报人
   - **警告**：通知被举报人，记录警告
   - **删除内容**：删除违规内容
   - **封禁用户**：根据严重程度选择时长
   - **永久封禁**：严重违规
5. 通知双方处理结果

### 6.3 举报统计

- 每日举报数趋势
- 举报类型分布
- 处理时效统计
- 误判率（申诉成功率）

### 8.2 词库操作

3. 选择分类
4. 选择处理方式：

#### 8.2.2 批量导入

## 12. 应急响应

### 12.1 紧急下线

#### 12.1.1 微信小程序下线

1. 登录微信公众平台
2. 进入「版本管理」
3. 找到当前线上版本
4. 点击「撤回审核」（如仍在审核）或「回退版本」（如已发布）
5. 用户下次冷启动生效

#### 12.1.2 API 服务停服

```bash
# 停止 API 服务（保留数据库与缓存）
docker compose stop api

# 启用维护页面（nginx 切换）
sudo nginx -s reload -c /etc/nginx/nginx-maintenance.conf
```

#### 12.1.3 全站维护

```bash
# 停止所有应用服务
docker compose stop api admin client

# 启用维护页面
sudo nginx -s reload -c /etc/nginx/nginx-maintenance.conf

# 通知用户（站内信 + 推送）
# 通过 Admin 后台发送全站公告
```

### 12.2 数据恢复

详见 `docs/DR/restore-procedure.md`，核心步骤：

1. 停止写入流量（启用维护页面）
2. 恢复最近备份：`gunzip -c /backup/campus_love-XXX.sql.gz | mysql -u root -p campus_love`
3. 验证数据完整性
4. 重启 API 服务
5. 关闭维护页面

### 12.3 安全事件响应

#### 12.3.1 账号泄露

1. 立即强制所有 Admin 重新登录
2. 修改疑似泄露账号密码
3. 检查审计日志，确认是否有异常操作
4. 通知安全团队

#### 12.3.2 数据泄露

1. 立即隔离受影响系统
2. 启动应急响应流程（详见 `docs/DR/DRP.md`）
3. 评估泄露范围
4. 通知法务与合规团队
5. 按法规要求通知用户与监管

#### 12.3.3 DDoS 攻击

1. 启用云服务商 DDoS 防护
2. 临时调整 WAF 规则
3. 监控系统负载
4. 必要时切换至备用 IP

### 12.4 客服应急

#### 12.4.1 大规模客诉

- 客服 Lead 启动应急小组
- 统一口径回复（FAQ 更新）
- 每小时同步处理进度
- 必要时启动全站公告

#### 12.4.2 媒体危机

- 立即通知 PR 团队
- 统一对外发声渠道
- 准备声明稿
- 监控舆情
