## 0. 后台重构说明（v2.0.0）

> 后台已参照 eladmin 架构完成重构，本手册各章节描述的**操作目标不变**（用户管理、内容审核、活动上下架、论坛分域、商业模式等），但**页面入口、菜单结构、权限模型已升级**。使用前请先阅读本节。

### 0.1 新后台（apps/admin）

- **入口**：默认端口 `5177`（本地开发）/ 生产环境见部署配置
- **技术形态**：Vue3 + Vite，eladmin 风格布局（深色侧边栏 + 动态菜单 + 多标签页 + 面包屑）
- **核心能力**：
  - **动态菜单**：菜单由后端下发（`GET /v1/admin/menus/current`），按当前登录角色自动渲染
  - **角色权限**：`SUPER_ADMIN`（超级管理员，全量）/ `ADMIN`（校区管理员，仅本校区数据）
  - **多租户数据隔离**：校区管理员只能看到/操作本校区的用户、活动、论坛、商业数据，越权返回 403
  - **分域独立页面**：论坛（村落动态/兴趣圈/校园圈/评论）、商业模式（VIP/兑换码/钱包/商城）各自独立菜单页
  - **活动上下架**：活动列表页支持发布/下架/编辑/报名查看/CSV 导出
- **登录**：超级管理员账号由部署配置注入——首次部署通过环境变量 `ADMIN_OPENID` / `ADMIN_INITIAL_PASSWORD_HASH` 初始化（见 `.env.example`，哈希生成方法见其中注释），不使用任何公开测试账号；校区管理员账号由超级管理员在「系统管理 → 管理员管理」中创建并绑定高校

### 0.2 旧后台回退（apps/admin-legacy）

- **入口**：端口 `5178`，仅作**回退备份**保留
- 如新后台出现 P0 问题，可用旧后台临时顶替；两者共用同一后端 API 与数据库
- 日常运营请使用新后台（apps/admin）

### 0.3 模块与页面入口映射

| 本手册章节 | 新后台菜单路径 |
|------------|----------------|
| 用户管理 | 用户内容 → 用户管理 / 校园认证 / 举报 / 反馈 / 敏感词 |
| 内容审核 | 论坛 → 村落动态 / 兴趣圈 / 校园圈 |
| 活动管理 | 活动 → 活动管理 / 活动报名 |
| 商业模式 | 商业 → VIP / 兑换码 / 钱包 / 商城 |
| 系统配置 | 系统 → 高校管理 / 菜单 / 角色 / 字典 / 审计日志 / 在线用户 |

## 2. 账号与权限

### 2.1 登录

1. 访问 https://admin.campuslove.example.com
2. 输入用户名与密码
3. 点击「登录」

**安全提示**：
- 密码长度 ≥ 12 位，包含大小写字母、数字、特殊符号
- 密码每 90 天强制更换（运营侧约定，系统当前不强制）
- 登录失败时页面提示「账号或密码错误」；账号被禁用时提示「账号已被禁用」
- 当前无 TOTP 二次验证与异地登录邮件提醒，请通过强密码与账号禁用机制保障安全

### 2.2 账号管理（仅超级管理员）

#### 2.2.1 创建管理员账号

1. 进入「系统配置 → 管理员列表」
2. 点击「新增管理员」
3. 填写：姓名、手机号、角色、初始密码、管辖校区（校区管理员必填）
4. 创建后账号即刻可用，使用初始密码登录（当前无邮件通知，请线下告知初始密码）；
   建议首次登录后修改密码

#### 2.2.2 修改权限

1. 进入「系统配置 → 管理员列表」
2. 找到目标管理员，点击「编辑」
3. 调整角色或自定义权限
4. 保存后立即生效

#### 2.2.3 禁用账号

1. 进入「系统配置 → 管理员列表」
2. 找到目标管理员，点击「禁用」
3. 确认禁用原因
4. 账号立即无法登录，已建立的会话自动失效

#### 2.2.4 重置密码

1. 进入「系统配置 → 管理员列表」
2. 找到目标管理员，点击「重置密码」
3. 重置后使用新初始密码登录（当前无邮件通知，请线下告知新密码）；
   建议登录后立即修改密码

## 3. 仪表盘（Dashboard）

### 3.1 当前功能（2026-08 现状）

Dashboard 提供 **4 张统计卡片**与**近 30 日匹配趋势列表**，数据来自 `GET /v1/admin/stats` 聚合接口：

**统计卡片**：
- **总用户数**：全站注册用户总数
- **今日活跃用户**：今日有活跃行为的用户数
- **总匹配数**：累计匹配成功对数
- **今日互动量**：今日互动行为总数

**匹配趋势**：近 30 日每日匹配数量列表（按日期倒序展示）。

页面支持手动刷新；任一子接口失败时对应卡片降级显示，并在页面顶部给出错误提示。

### 3.2 规划中的指标能力

> ⚠️ 规划中（未实现）：以下指标面板当前**未实现**，Dashboard 暂不提供：
> - DAU / 新增用户 / 消息量 / 帖子数 / 举报数 / 反馈数等 7 天、30 天趋势图表
> - 匹配成功率、留存率、VIP 转化率、平均使用时长等业务监控指标
> - 异常告警横幅（DAU 同比下降、错误率、API P99 等阈值告警）
> - 系统健康面板（API/DB/Redis 状态、磁盘、JVM 内存、慢查询）
>
> 系统运行状态可另行通过运维侧监控查看：`/actuator/health` 健康检查端点与 Prometheus + Grafana 监控面板（见 `docs/CI-CD.md`）。

## 4. 用户管理

### 4.1 用户列表

#### 4.1.1 查看用户

路径：用户管理 → 用户列表

**搜索条件**：
- 用户 ID
- 昵称（模糊匹配）
- 手机号
- 学校
- 注册时间范围
- 状态（正常 / 已禁用）
- 认证状态（已认证 / 未认证）

**列表字段**：
- 用户 ID
- 头像
- 昵称
- 性别
- 学校
- 注册时间
- 最后活跃时间
- 认证状态
- 账号状态
- 操作（查看 / 编辑 / 禁用 / 启用）

#### 4.1.2 查看用户详情

点击用户打开详情弹窗，可查看：

- **基本信息**：用户 ID、昵称、手机号、个人简介、所属校区、认证状态、资料完善度、关注/粉丝数、注册时间

> ⚠️ 规划中（未实现）：用户详情暂不提供匹配历史、聊天记录（含元数据）、登录记录（最近 30 次 IP 与设备）、照片墙、个人视频、举报记录、VIP 记录等扩展信息。发布内容请在论坛对应模块查看，举报记录请在「举报处理」模块查看。

### 4.2 用户操作

#### 4.2.1 禁用用户

当前后台仅提供「禁用 / 启用」两级状态控制（`POST /v1/admin/users/{id}/disable|enable`），**不支持封禁时长与封禁原因分级**：

1. 在用户列表找到目标用户，点击「禁用」
2. 在确认弹窗中确认操作（仅区分「禁用」/「启用」，无时长、原因选项）
3. 确认后用户账号状态变为「已禁用」

**禁用效果**：
- 用户无法登录小程序（登录时提示账号已禁用）
- 已发布内容默认保留（如需删除请在论坛内容模块单独处理）

> ⚠️ 规划中（未实现）：封禁时长（7 天 / 30 天 / 永久）、封禁原因分类（色情低俗 / 政治敏感 / 谩骂侮辱 / 广告引流 / 诈骗 / 人身攻击 / 骚扰 / 其他）、封禁说明与通知用户等能力尚未实现。

#### 4.2.2 启用用户

1. 在用户列表找到已禁用用户，点击「启用」
2. 在确认弹窗中确认操作
3. 确认后用户账号状态恢复为「正常」

**启用效果**：
- 用户可正常登录
- 历史数据保留

#### 4.2.3 重置资料

> ⚠️ 规划中（未实现）：重置用户资料（头像 / 照片墙 / 个人视频 / 个人简介）功能尚未实现。用户资料违规时，当前可联系用户要求其自行修改，或在用户管理中编辑资料字段。

### 4.3 校园认证审核

#### 4.3.1 待审核列表

路径：用户管理 → 认证审核

显示所有待审核的学生认证申请。

#### 4.3.2 审核流程

1. 查看用户提交的学生证照片
2. 核对信息：
   - 学校是否与注册学校一致
   - 姓名是否与昵称匹配（仅参考）
   - 学号格式是否合理
   - 有效期是否未过期
3. 点击「通过」或「拒绝」
4. 拒绝需填写原因（如：学生证模糊、学校不一致、已过期）

#### 4.3.3 审核标准

**通过条件**（全部满足）：
- 学生证清晰可辨
- 学校名称与注册一致
- 在有效期内
- 包含本人姓名与学号

**拒绝条件**（任一触发）：
- 照片模糊无法辨认
- 学校不一致
- 已过期
- 非学生证（如身份证、驾照）
- 疑似伪造

#### 4.3.4 审核时效

- 提交后 24 小时内审核完成
- 超时未审核系统自动提醒
- 紧急申请（VIP 用户）优先处理

## 5. 内容审核

### 5.1 审核列表

#### 5.1.1 待审核内容

路径：内容审核 → 待审核

显示所有机审疑似违规的内容，按严重程度排序。

**内容类型**：
- 话题动态
- 表白墙
- 树洞
- 评论
- 用户头像
- 用户照片墙
- 用户个人视频

**违规类型**：
- 色情低俗
- 政治敏感
- 谩骂侮辱
- 广告引流
- 暴力血腥
- 违法犯罪
- 其他

#### 5.1.2 审核操作

1. 查看内容详情
2. 点击「通过」或「删除」
3. 删除需选择违规类型
4. 是否处罚用户（默认不处罚，严重违规勾选）
5. 是否通知用户（默认通知）

### 5.2 已发布内容管理

#### 5.2.1 搜索已发布内容

路径：内容审核 → 内容列表

支持按用户、类型、时间、关键词搜索。

#### 5.2.2 删除内容

1. 找到目标内容
2. 点击「删除」
3. 选择违规类型
4. 填写删除原因
5. 是否处罚用户
6. 点击「确认删除」

#### 5.2.3 加精 / 置顶

优质内容可加精或置顶：

1. 找到目标内容
2. 点击「加精」或「置顶」
3. 选择置顶时长（1 天 / 3 天 / 7 天）
4. 点击「确认」

### 5.3 审核规范

详见 `docs/content-moderation-standards.md`（如存在），核心要点：

> 注：当前系统仅支持「禁用 / 启用」与内容删除（见 4.2.1），「封禁时长 / 永久封禁」为规划中能力，下述处置动作按实际可执行项（删除内容、禁用账号）执行。

- **色情低俗**：暴露、性暗示、色情描述 → 删除 + 禁用账号
- **政治敏感**：涉政、辱华、煽动 → 删除 + 禁用账号 + 上报
- **谩骂侮辱**：人身攻击、侮辱性语言 → 删除 + 警告/禁用账号
- **广告引流**：二维码、微信号、外链 → 删除 + 警告
- **暴力血腥**：暴力描述、血腥图片 → 删除 + 禁用账号
- **违法犯罪**：诈骗、传销、违禁品 → 删除 + 禁用账号 + 报警

## 6. 举报处理

### 6.1 举报列表

路径：举报处理 → 举报列表

**举报目标类型**（当前支持）：
- 用户（USER）
- 帖子（POST）
- 评论（COMMENT）
- 话题（TOPIC）

> ⚠️ 规划中（未实现）：消息举报暂未实现，当前仅支持上述四类目标。

**优先级**（运营约定）：
- 紧急（诈骗、人身威胁）：1 小时内处理
- 严重（色情、政治）：4 小时内处理
- 一般（广告、骚扰）：24 小时内处理

### 6.2 处理流程

1. 查看举报详情（举报人、被举报人、举报目标类型、举报描述、处理意见）
2. 判断是否违规
3. 处理操作（`POST /v1/admin/reports/{id}/handle`，处理结果 HANDLE / REJECT）：
   - **处理（HANDLE）**：认定违规，可填写处理意见；如需删除违规内容请在论坛对应模块操作，如需禁止该用户请在用户管理中「禁用」
   - **驳回（REJECT）**：举报不成立
4. 反馈处理结果（处理状态：PENDING / HANDLED / REJECTED）

> ⚠️ 规划中（未实现）：处理举报时直接内嵌「警告 / 删除内容 / 按时长封禁 / 永久封禁」等一键操作尚未实现。

### 6.3 举报统计

> ⚠️ 规划中（未实现）：每日举报数趋势、举报类型分布、处理时效统计、误判率（申诉成功率）等统计报表尚未实现。

## 12. 应急响应

### 12.1 紧急下线

#### 12.1.1 微信小程序下线

1. 登录微信公众平台
2. 进入「版本管理」
3. 找到当前线上版本
4. 点击「撤回审核」（如仍在审核）或「回退版本」（如已发布）
5. 用户下次冷启动生效

#### 12.1.2 API 服务停服

```bash
# 停止 API 服务（保留数据库与缓存）
docker compose stop api

# 启用维护页面（nginx 切换）
sudo nginx -s reload -c /etc/nginx/nginx-maintenance.conf
```

#### 12.1.3 全站维护

```bash
# 停止所有应用服务
docker compose stop api admin client

# 启用维护页面
sudo nginx -s reload -c /etc/nginx/nginx-maintenance.conf

# 通知用户（站内信 + 推送）
# 通过 Admin 后台发送全站公告
```

### 12.2 数据恢复

详见 `docs/DR/restore-procedure.md`，核心步骤：

1. 停止写入流量（启用维护页面）
2. 恢复最近备份：`gunzip -c /backup/campus_love-XXX.sql.gz | mysql -u root -p campus_love`
3. 验证数据完整性
4. 重启 API 服务
5. 关闭维护页面

### 12.3 安全事件响应

#### 12.3.1 账号泄露

1. 立即强制所有 Admin 重新登录
2. 修改疑似泄露账号密码
3. 检查审计日志，确认是否有异常操作
4. 通知安全团队

#### 12.3.2 数据泄露

1. 立即隔离受影响系统
2. 启动应急响应流程（详见 `docs/DR/DRP.md`）
3. 评估泄露范围
4. 通知法务与合规团队
5. 按法规要求通知用户与监管

#### 12.3.3 DDoS 攻击

1. 启用云服务商 DDoS 防护
2. 临时调整 WAF 规则
3. 监控系统负载
4. 必要时切换至备用 IP

### 12.4 客服应急

#### 12.4.1 大规模客诉

- 客服 Lead 启动应急小组
- 统一口径回复（FAQ 更新）
- 每小时同步处理进度
- 必要时启动全站公告

#### 12.4.2 媒体危机

- 立即通知 PR 团队
- 统一对外发声渠道
- 准备声明稿
- 监控舆情
