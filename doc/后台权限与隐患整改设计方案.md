# 后台权限模型接管 · 存量权责整改 · 已知隐患治理 设计方案

> 状态：待批准 | 前置：管理后台可用化 11 阶段已完成并全门通过
> 本方案覆盖四件事：①角色×圈层正交鉴权 ②真大区重排 ③三处存量权责 ④六项已知隐患。

---

## 0. 一句话现状

后台已经能用，但**"圈层"目前只是导航**：`AdminDataScope` 只按 `users.campus_name` 隔离，
`circle_layer`（25 节点树）与 `admin_layer`（管理员↔圈层绑定）两张表建好且接口齐全，
却没有任何一处数据查询读它们。`views/system/CircleLayers.vue` 页面上那张
"聊天内容/上传图片/帖子/临时聊天 × 全量/本区域/本校"权限矩阵，是**设计口径而非已生效实现**。

本方案的第一目标就是让那张矩阵变成真的。

## 1. 角色 × 圈层正交（规格文档 §1 的"正交规则"）

### 1.1 模型

| 轴 | 承载 | 语义 | 现状 |
|---|---|---|---|
| 功能角色 | `users.role` + `roles` 表 | 能做什么（读/审/发/配） | 已生效（SUPER_ADMIN / ADMIN / AUDITOR） |
| 圈层 | `admin_layer(admin_id, circle_layer_id, roleCode)` | 能看谁 | 表与接口在，**无人读取** |

目标：任一角色可绑任一圈层节点，例 `华东大区 · 审核员`、`公司级 · 超级管理员`。
数据可见 = 圈层前缀交集；可执行操作 = 角色权限集。两轴独立校验，缺一不可。

### 1.2 改造点（按依赖顺序）

1. **`AdminLayerRepository` 补查询**：按 `adminId` 取其全部 `circle_path`（join `circle_layer`）。
   现有方法只能按 admin 或按 layer 单边查。
2. **新增 `AdminScopeService`**（不改 `AdminDataScope` 的公开签名，避免 33 个 controller 全改）：
   - `currentPrefixes(): List<String>` — 当前登录管理员的可见圈层前缀集合；
     SUPER_ADMIN 或未绑定任何圈层的账号 → `[C1]`（全平台，保持现网行为不变）；
     绑定了节点的账号 → 其节点 path 列表。
   - `assertInScope(String ownerCirclePath)` — 不在任一前缀下 → 403。
   - **fail-closed**：绑定了节点但 path 解析失败 → 拒绝，不回退成全局。
3. **内容侧过滤键**：`posts.owner_circle_path`（已回填 250/267）、`private_messages.owner_circle_path`
   （已回填 3813/3818）、`users.circle_path`（264/280）。
   剩余 NULL 行统一视为"未归属"，**只有持有 C1 前缀的人可见**（避免未归属数据被下放给校区管理员）。
4. **列表接口接入**：先做帖子、用户、私信、图片四个高频列表（各加一个可选前缀 IN 过滤），
   其余 controller 二期。每接一个都要配一条"越权必须 403/0 行"的负例。
5. **`admin_layer.roleCode` 与 `users.role` 的一致性**：两处都可写角色，是双主。
   决策：**`users.role` 为唯一权威**，`admin_layer.roleCode` 降级为"该绑定下的备注"，
   并在 `AdminLayerController` 写入时校验二者一致，不一致 400。
6. **UI 说明（你要求的"对应的管理员要进行说明"）**：
   - `CircleLayers.vue` 权限矩阵加一行醒目说明：哪些行已生效、哪些仍是设计口径；
   - 每个列表页顶部显示"当前数据域：华东大区（C1/R1）· 角色：审核员（只读）"；
   - 管理员管理页每行展示其绑定的圈层，未绑定的显式标"全平台"而不是留空。

### 1.3 为什么不让 `AdminDataScope` 直接改读 admin_layer

`getCurrentAdminCampusName()` 返回单个校区名，被 33 个 controller 以字符串方式使用；
圈层是**多前缀**语义，改成集合会波及全部列表签名。故新增 service 并行，旧口径继续有效，
迁移期两套并存、逐个接口切换，每切一个都有负例兜底。

## 2. 真大区重排

现树地理是错的（北京大学、清华大学挂在"华东大区"，复旦、上海交大挂在"华南大区"），
且我上一轮临时塞了 `其他区域 (C1/R9)` 兜住 14 所学校。

方案：新增迁移按行政区划重排——
`C1/R1 华北`（北京 5 校 + 天津南开）、`C1/R2 华东`（上海 3 校 + 南京 2 + 杭州浙大）、
`C1/R3 华南`（广州 2）、新增 `C1/R4 华中`（武汉 2）、`C1/R5 西南`（成都川大）、
`C1/R6 西北`（西安交大）、`C1/R7 东北`（哈尔滨工业大学）。

**关键约束**：`circle_path` 是 `users.circle_path` / `posts.owner_circle_path` /
`private_messages.owner_circle_path` 的外键式引用值，**改 path 等于改所有已回填数据**。
因此迁移必须：先改 `circle_layer` 的 `parent_id`/`circle_path`，再按 name→新 path
级联 UPDATE 三张引用表，且整体包在"备份三列 → 应用 → 校验行数不变"三步里。
`北校区`/`南校区` 两个垃圾值不重排，保持未归属并单独列出待人工确认。

## 3. 管理员看他人图片（含 PII 边界）

现状：`MediaAccessController` / `MediaAccessService` 的 `hasAdminRole()` 只认 `ROLE_ADMIN`，
AUDITOR 拿到的是 `ROLE_AUDITOR` → 审核员看不到任何用户上传图（连帖子配图都 401）。

分两级放开，**不是一刀切全放**：

| 资产 | 谁能看 | 理由 |
|---|---|---|
| 帖子配图、头像、相册 | SUPER_ADMIN / ADMIN / AUDITOR | 审核动作本身需要看图，这是审核员的核心职责 |
| 学生证、身份证正反面、半身照（认证材料） | 仅 SUPER_ADMIN | 同一 controller 同一道判断，放开=把 PII 交给只读账号；这类材料的复核频率远低于内容审核 |

实现：`media_asset.category` 与上传路径已能区分材料类型，把 `hasAdminRole()` 拆成
`canReadContentMedia()` / `canReadVerificationMedia()` 两个判断，各走各的角色集。
若你要求认证材料也放开，只需把第二个判断的角色集加上 ADMIN/AUDITOR——这是本方案里
唯一一处"我按更保守的方式实现、但你可以一句话改判"的地方。

## 4. 三处存量权责

1. **`api/feedback.ts` 声称接口已实现，实际后端无该映射** → 前端 `GET /v1/admin/feedback`
   永远 404。补 `AdminFeedbackController`（列表 + 处理动作 + 校区隔离），或把页面标注为"后端未实现"。
   建议补接口：反馈页是运营真会用的。
2. **`ProfileConfig.vue` 前后端都通，但库里没有菜单行** → 真实环境完全进不去。
   补一条 menus 行并绑角色。
3. **603 全局配置 / 601 通知配置 / 602 匹配配置 绑给了 ADMIN 与 AUDITOR，
   但所有 `PUT` 要求 `hasRole('SUPER_ADMIN')`** → 非超管打得开、改不动、点了才报错。
   这正是"权责不统一"。修法二选一：解绑（只读也不给），或放开写权限。
   建议**解绑到 SUPER_ADMIN**，并把这三页从"权限"组移出，避免"看得见却动不了"。

## 6. 真实验收矩阵

### 6.1 分账号（角色 × 圈层，覆盖正交两轴）

| 账号 | 角色 | 绑定圈层 | 应看到 | 不应看到 |
|---|---|---|---|---|
| 超管 | SUPER_ADMIN | C1（全部） | 一切 | — |
| 华北审核员 | AUDITOR | C1/R1 华北 | 华北各校帖子/用户/私信元信息/帖子配图 | 任何写操作、认证材料、公告发布 |
| 华东校区管理员 | ADMIN | C1/R2/S? 某校 | 本校帖子/用户/私信元信息、可审核可发帖 | 他校数据、系统配置 |
| 华中区域管理员 | ADMIN | C1/R4 华中 | 华中全部学校数据（下钻） | 华北/华东数据 |
| 无绑定账号 | ADMIN | 无 | 明确提示"未绑定管辖范围" | 不得默认全平台可见 |

每个账号跑同一套断言：登录 → 列表行数 → 越权目标必须 403/0 行 → 写操作按角色 200/403。
**每一格都要能变红**：越权断言必须配"超管同请求成功"的对照组。

### 6.2 设备腿

小程序以 **非 mock** 打包连 real，真机操作：登录演示号 → 发帖带图 → 收私信 → 看官方号公告；
后台侧同 ID 回读，断言标题/作者/图片数/类目三处一致，并断言后台建的帖在小程序可见。
证据落 `reports/audit/round-<n>/`。

### 6.3 门禁脚本（新增/扩展）

- `verify-admin-auditor.mjs` 扩成多账号矩阵（现为单 AUDITOR）
- `verify-admin-scope.mjs`：越权读必须 403/0 行（新）
- `check-admin-i18n.mjs`、`verify-admin-writes.mjs`、`verify-admin-post-detail.mjs` 保持
