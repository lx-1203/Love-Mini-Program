## 五、EmojiPanel 处理建议（产品决策）

> `components/chat/EmojiPanel.vue` 含 32 个系统 emoji 表情，是聊天输入法的"表情选择器"。与一般装饰性 emoji 性质不同——它**本身就是用户要发送的字符内容**。

### 方案对比

| 维度 | 方案 A：保留 32 系统 emoji | 方案 B：32 个 SVG 全部替换 | 方案 C：吉祥物 + SVG 混合 |
|------|---------------------------|---------------------------|---------------------------|
| 工作量 | 0（不动） | 1-1.5 人日（下载 32 个 + 集成） | 0.5-1 人日（吉祥物 15 个 + 下载 17 个） |
| 资源成本 | 0 资源 | +32 SVG（~30KB 总量） | +17 SVG（~15KB）+ 复用现有 mascot |
| 用户体验 | 跨端一致/熟悉 | 视觉统一/品牌化，但用户需重新学习每个表情含义 | 部分熟悉（吉祥物） + 部分新 |
| 微信兼容性 | 优（系统 emoji 跨端稳定） | 优（SVG 跨端稳定） | 优 |
| 维护成本 | 0 | 中（每新增表情需补 SVG） | 中 |
| 品牌一致性 | 低（系统表情非品牌化） | 高（统一 SVG 风格） | 极高（吉祥物表情强化品牌） |
| 与"全部 SVG 化"硬性要求一致 | ❌ 不一致 | ✅ 完全一致 | ✅ 部分一致 |

### 产品建议

**推荐方案 B（主推）** 或 **方案 C**（如果设计师能赶上）。

**理由**：
1. 用户硬性要求是"全部 emoji 替换为标准 SVG"，方案 A 不符合要求。
2. 方案 B 最彻底——32 个标准 line-style 表情 SVG，跨端一致，与小程序整体设计语言统一。
3. 方案 C 品牌感最强，但 32 个表情中只有 15 个吉祥物能复用，剩余 17 个仍需下载。**适合品牌升级阶段**，不一定适合本次"全量替换"。

### 实施建议

**方案 B 具体执行**：
1. **来源**：freesvglab 搜索 "emoji face line" / "smiley outline"，筛选 24×24、stroke 风格、与品牌色兼容的成套图标（如需付费/找不到，可改用 iconfont.cn）。
2. **备用**：Iconify API 提供 `noto-emoji` / `twemoji` SVG 版本（24×24 可缩放），免费可商用。
3. **命名**：`static/assets/icons/emoji/face-01-smile.svg` ... `face-32-celebrate.svg`（数字前缀便于排序）。
4. **集成**：将 EmojiPanel.vue 的 `EMOJIS: string[]` 改为 `EMOJIS: { key: string; src: string }[]`，模板中 `<text>{{ emoji }}</text>` 改为 `<image :src="emoji.src" />`。
5. **测试**：`emit('select', emoji)` 改为 `emit('select', '[' + key + ']')` 之类的占位符（**这是关键产品决策点**——SVG 表情图发送到聊天后是图片 URL，而 emoji 是 Unicode 字符，发送语义不同）。

> **关键风险点**：方案 B/C 涉及聊天消息格式变更（emoji 字符 → 图片 URL），需后端配合存储图片消息类型，且老消息兼容。**建议本轮先只替换"装饰性 emoji"（43 个文件），EmojiPanel 单独排期讨论**。

### 产品最终建议

- **本轮（2026-08-25）**：执行 §二 的 43 个文件装饰性 emoji 替换，**EmojiPanel.vue 暂不动**。
- **下轮（待 PM/设计师决策）**：EmojiPanel 走 A/B/C 方案讨论，输出单独的 `emoji-panel-redesign-prd.md`。
- **在 EmojiPanel 文件头注释中**记录此决策（避免工程师误操作）。
