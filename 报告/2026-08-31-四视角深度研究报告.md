## 一、产品与市场概述（现状摘要）

### 1.1 功能全景
本项目是一款**面向校园学生（18–26 岁）的恋爱社交微信小程序**，核心闭环为「注册 → 完善资料 → 推荐位浏览 → 喜欢/心动 → 双向匹配 → 私聊 → 线下见面」。当前已实现的完整功能域：

| 功能域 | 能力 | 状态 |
|---|---|---|
| 账号与资料 | 微信登录、个人资料编辑、兴趣标签、相册、实名/学生认证（照片 + 人工审核流） | ✅ 代码闭环 |
| 匹配推荐 | 卡片式滑动（寻觅）、匹配度计算、意图去重、喜欢/跳过、匹配中/匹配成功动效 | ✅ 已实现，本轮补推荐去重 |
| 圈子社区 | 公开 / 学校圈 / 兴趣圈三类，发帖圈选（仅已加入 + 公开 + 学校圈）、帖子审核（pending→approved） | ✅ 本轮闭环审核链路 |
| 社区帖子 | 帖子发布/详情、作者头像跳他人主页、点赞/评论 | ✅ 本轮修复头像跳转 |
| 即时聊天 | 会话列表、私聊、语音消息（真实录音）、未读 | ✅ 真实语音已接 |
| 附近探索 | 基于定位的附近人（真实 getLocation）+ 校园隔离 | ✅ 真实定位已接 |
| 商业化模块 | 金币/钱包、付费解锁（服务端定价）、签到经济、VIP、优惠码、商城与课程报名 | ✅ 代码就绪，支付待资质 |
| 运营后台 | Admin（RBAC 三级圈层、校区隔离、发帖审核、统计） | ✅ 就绪 |

### 1.2 技术栈
- **客户端**：uni-app（Vue 3 + TypeScript）、**mp-weixin 单端**、Pinia、i18n（zh-CN/en-US）、CSS 设计令牌（`--c-*` / `--sp-*` token 体系）。
- **后端**：Spring Boot（Java 17）、MySQL + Redis、Flyway 迁移、Spring Actuator/Prometheus、鉴权 JWT。
- **管理端**：Vue 3 + TS + Vite（`apps/admin`）。
- **工程化**：pnpm workspace、ESLint/Prettier、GitHub Actions（10 Job CI）、Trivy 安全扫描、Gitleaks 密钥扫描、Playwright E2E、Docker Compose/K8s 部署、Prometheus/Grafana/Alertmanager 可观测。

### 1.3 审核链路（已闭环）
帖子发布 → 后台审核（pending → approved）→ 前台可见；实名/学生认证照片 → 后台人工审核。**审核状态机在本轮（round 6）已路由登记并闭环**，前端发帖圈选限定于「已加入三类」而非全量圈子，且发布即进入后台审核队列。

### 1.4 真实能力接入点（差异综述）
| 能力 | 现状 | 待接入的前置条件 |
|---|---|---|
| 真实定位 | ✅ 已接（`uni.getLocation` + 隐私声明） | 微信公众平台接口权限 |

| 真实语音 | ✅ 已接（录音真实；AI 评测模拟） | 可选腾讯云 ASR |

### 1.5 商业化就绪度（沿用 R4 评估口径）
八项核心商业化模块中：**6 项代码侧就绪**（匹配推荐、付费解锁、签到经济、优惠码、校园隔离、监控）、**2 项有条件就绪**（充值、VIP，待微信支付资质）、**4 项功能受阻**（Apple 登录、恋爱认证、视频通话、课程报名支付，均外部服务缺失，非代码缺陷）。前端工程治理度较高：渲染页与理想图 11/11=100% 还原、150 个前后端端点映射对齐、无 `console.log`、无空捕获、ESLint 严格、主题令牌化基本完成；本轮扫描 **无 P0 阻断项**。

## 二、用户视角（User）

### 2.1 核心用户画像（假设/估算）
- **主体**：18–26 岁高校在校生（本科一至四年级为主，兼顾专科与本硕新生），男女大体均衡，约 6:4 偏男生，校园恋爱意愿在高年级更强。
- **动机分层**：主动机「脱单找对象」（~60% 假设）；次动机「拓展同校社交、进兴趣圈」（~30%）；长尾「恋爱经验/破圈娱乐」（~10%）。
- **使用时段**：晚自习后 / 睡前（21:00–24:00）；周五晚与周末提升。
- **网络行为**：重度使用微信生态、偏好轻快视觉（浅绿小清新风格正契合目标人群审美）、对「同校 + 真实身份」信任敏感度高。

### 2.2 用户价值主张
> **「在同校真实的圈子里，遇见心动的人」**
关键卖点：① 校园真实身份背书降低社交恐惧与安全顾虑；② 兴趣圈把配对从「看脸的卡片」扩展到「因共同话题结缘」；③ 审核治理筛掉骚扰与虚假，营造安全氛围；④ 浅绿清新品牌与理想图级还原带来精致产品体验。

### 2.3 任务闭环（已打通）
注册/微信登录 → 完善资料（兴趣标签、相册）→ 进入推荐位浏览卡片（寻觅）→ 右滑喜欢 → 双向喜欢即匹配 → 私聊（文字+语音）→ 发起线下见面（附近/校园圈）。**本轮已把推荐流全局去重、发帖圈选三类、作者头像跳他人主页全部打通**，闭环流畅性显著提升。

### 2.4 体验亮点（已实现）
- **卡片滑动**：寻觅推荐采用沉浸式卡片交互，右滑喜欢/左滑跳过，符合主流婚恋产品肌肉记忆。
- **匹配度**：展示匹配分值，给用户可感知的「被推荐的理由」，降低选择成本。
- **理想图还原**：11/11 页与理想效果图 100% 还原，视觉一致性高，浅绿主题全局统一（本轮完成背景滚动断层修复与理想图对齐）。
- **浅绿品牌**：以 `--c-brand #36C99A` 为主的浅绿体系，清爽、清新、学生感强，差异化于陌陌/探探的暧昧红。

### 2.5 痛点与风险
| 痛点/风险 | 说明 | 缓解方向 |
|---|---|---|
| 安全隐患 | 线下见面、骚扰、涉诈骗风险是校园恋App 最大顾虑；女性隐忧尤重 | 实名认证增强、举报/拉黑、安全提示、见面审核引导 |
| 隐私 | 位置、相册、身份信息收集敏感 | 隐私政策已立；最小化收集、加密存储、脱敏（后端已有访问日志脱敏） |
| 审核过严/体验断裂 | 已加入圈子限定、发帖需后台审核，可能导致「发帖门槛高、内容冷启动慢」 | 审核 SLA 设定（如 24h 内人工审）、轻量自动初审 |
| 社交恐惧 | 首次发起聊天怯场 | 提供破冰话题模板、兴趣共鸣引导、「互相喜欢才可聊」安全感设计 |
| 低活跃冷启动 | 工具型匹配产品初启时无内容，易流失 | 种子数据、同校热度榜、兴趣圈话题驱动 |
| mock 介入生产 | 若误配 production `mode=mock` 会绕过认证门/泄露演示数据（审查 P2） | 构建环境强隔离，real 必须剥离 mock |

### 2.6 用户留存与增长策略建议
1. **冷启动冷层级**：新用户前 7 天刻意设计明显反馈（首周匹配、首周聊天次数门槛），用「同校 + 同兴趣」做首配首聊钩子，拉升 D7 留存（假设目标 ≥ 15%）。
2. **圈层驱动活跃**：以兴趣圈话题与活动（校园线下报名、圈子挑战）制造 UGC 与回访理由，缓解纯匹配型产品活跃回落。
3. **破冰与安全并重**：内置聊天开头模板、见面安全提示卡片，既降社交恐惧又强化安全信任。
4. **校园增长（假设估算）**：按校园布点，优先深耕「一个校区打透」，用校园大使（学生代理）激励拉新，单校打透后复制，边际获客成本递减。

## 三、投资人视角（Investor）

### 3.1 市场规模与 TAM/SAM/SOM 估算
> 以下均为「假设/估算」，用于量级判断，非审计口径。
- **TAM（可及总市场）**：中国高校在校生约 **4400 万人**（教育部口径，本专科在读），若恋爱/交友类 App 渗透率按假设 30% 视为潜在人群，则潜在用户约 **1300 万**。
- **SAM（可服务市场）**：以校园恋App 当前典型渗透（假设首批重点覆盖 Top100 高校、活跃率 ~10%），可服务用户约 **130–200 万**。
- **SOM（可得市场）**：商业化首年以「单校试点 + 区域滚动」，假设覆盖 20 所高校、单校月活跃 3000 人，首年月活约 **6 万人**、年新增下载 15–25 万。

### 3.2 商业模式与收入模型（各为独立假设）
| 收入模型 | 逻辑 | 单位价值假设 | 状态 |
|---|---|---|---|
| 会员（VIP） | 解锁更多推荐/可见谁喜欢我/专属标签 | ¥15–30/月 | ⚠️ 代码就绪，支付未接 |
| 解锁/道具 | 查看谁喜欢我、解锁聊天、礼物/心动道具 | ¥1–6/次 | ✅ 服务端定价闭环 |
| 广告 | B端变现（电商/培训/校园服务） | 千次曝光 ¥20–60 | 未接入，不建议早期 |
| 线下活动 | 校园联谊、兴趣线下局抽成 | ¥9.9–49/场 | 待产品化 |
| 校园服务合作 | 周边商家/驾校/咨询导流分成 | 按 CPS/CPS+ | 待商务 |

### 3.3 单位经济（假设/估算）
- **获客成本**：校园线上精准投放 + 校园大使激励，综合单用户新增获客成本估计 **¥3–8**。
- **单用户生命周期价值（LTV）**：假设付费转化率 3–5%、月均付费 ¥8–15、生命周期 4–6 个月，则估算 LTV **¥2–6**，**第一年收入端承压，LTV/CAC < 1 概率高**——早期应以「增长验证 + 种子付费」为抓手，跑通后再放大投放。
- **关键结论性风险**：恋爱社交品类早期绝大多数入不敷出，投资价值在「用户规模 × 活跃质量」而非当期利润；本轮应先验证**北极星指标（每周配对会话数）能否持续增长**。

### 3.4 竞争力分析
| 产品 | 定位 | 本产品差异化 |
|---|---|---|
| 陌陌/探探 | 陌生人约见、泛交友 | 本产品锁定**校园真实身份**，场景纯净、安全信任更高 |
| Soul | 灵魂社交、兴趣匹配 | 本产品强「同校 + 线下可及」，闭环到线下见面更顺 |
| 青藤之恋 | 高学历高质量婚恋 | 本产品聚焦在校生轻社交，非功利的兴趣圈 + 同校感 |
| 本产品独特牌 | **校园真实身份 + 兴趣圈 + 审核治理** | 三合一，属「恋爱的校园垂直 × 安全可控」空位，细分壁垒在校园运营网络 |

| 品类监管 | 高 | 严密内容审核、举报、未成年人保护（24 岁以下需谨慎交友引导） |

## 五、数据模拟视角（Data）

### 5.1 关键指标体系
- **北极星指标**：**每周配对会话数**（本周内从匹配进入 ≥1 次有效聊天的用户数 × 会话数），单一指标牵引「匹配＋破冰＋活跃」闭环。
- **成功指标（漏斗型）**：
  - 注册转化率（访问 → 完成资料）
  - 资料完整率（≥80% 字段已填）
  - 推荐有效率（查看资料/右滑占浏览卡片比例）
  - 匹配率（双向喜欢 / 右滑数）
  - 回复率（收到首条消息后的回复比例）
  - 周留存 / D7 留存
- **体验/健康指标**：平均匹配耗时、从匹配到首聊时长、圈子发帖审核通过率、举报/拉黑计数。

### 5.2 数据驱动的增长实验建议（A/B）
| 实验 | 变量 | 成功判据 |
|---|---|---|
| 卡片排序 | 推荐算法（兴趣分 vs 距离 vs 活跃度权重） | 匹配率 + 首聊率 |
| 卡片文案 | 破冰文案 / 匹配度解释话术 | 右滑率、回复率 |
| 推荐策略 | 是否同校优先 / 兴趣圈内优先 | 跨校 vs 同校 回复率对比 |
| 冷启动激励 | 新用户首周引导任务奖励 | D7 留存 |

### 5.3 风险评估数据
- **滥用/欺诈**：监控高频右滑、脚本账号、涉钱话术、线下诱导风险，指标化（举报率、封禁率）并设异常阈值。
- **未成年人**：人脸核验接入前，人工认证双轨兜底；**年龄过滤**为高危红线，需最小化采集且逐条审计实名记录（假设未成年人占比若 >5% 则触发合规专项）。
- **内容安全**：发帖审核中转通过率、均值化审核时效（SLA），异常内容触发自动降权。

### 5.4 数据看板建议
- **增长看板**：注册漏斗、留存曲线、北极星趋势（周维度）。
- **匹配效率看板**：推荐有效率、右滑率、匹配率、首聊率。
- **商业化看板**：付费转化率、ARPPU、LTV/CAC、兑换与VIP 解锁量（待支付接入后点亮）。
- **健康/合规看板**：举报率、禁封率、审核 SLA、未成年人过滤命中、错误率/延迟 SLO 余量。

本项目在**工程成熟度与产品体验上已商业化就绪度较高（总评 7.6/10）**，六轮迭代（本版 11/11 页理想图还原、六类问题全修复、审核链路与推荐去重闭环）证明其面向长期商业化的产品力与工程力。剩余阻塞**全部为外部资质与真实支付/实名/短信接入**，非代码缺陷。下一步的价值引擎在于：**以「校园真实身份 + 兴趣圈 + 审核治理」三角差异推进 PMF 试点，用北极星数据验证并滚动放大**——这不仅决定本轮商业化评级能否从 7.6 迈向 9，也决定项目的真实商业天花板。
