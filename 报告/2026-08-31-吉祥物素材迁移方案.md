## 二、现状对比

### 2.1 项目内 `mascot/` 目录现状

路径：`apps/client/src/static/assets/images/mascot/`

- **已存在约 126 个 PNG**，绝大多数与素材语义名一一对应（`mascot_default/smile.png`、`heart_pink.png`、`sprout.png`、`chat_hi.png`、`star.png`、`mascot_extra_10..18.png`、`decor_31..52.png`、`expression_19..30.png`、`utility_53..62.png` 等）。
- **无任何 `.svg`**。V1/V2 矢量源均未进入该目录。
- 存在历史遗留语义文件：`default.png`、`happy.png`、`love.png`、`thinking.png`、`waving.png`、`sad.png`、`logo.png`、`floating.png`、`mascot_ref_01.png` 等（`default.png` 与 `mascot_default.png` 是不同文件，`messages/index.vue` 用的是 `default.png`）。

### 2.2 代码引用方式

1. **`XunmiMascot.vue`（核心组件）** — `components/common/XunmiMascot.vue`
   - `imgSrc = /static/assets/images/mascot/${resolvedMood}.png`（**固定 .png**）。
   - `LEGACY_MAP` 把旧 mood 映射到 V2 文件名；支持 V2 全表情、聊天、导航、头像、装饰、状态、场景。
2. **硬编码直引 `/static/assets/images/mascot/*.png`**：
   - `AssistantCard.vue:17` → `mascot_default.png`
   - `MatchLoading.vue`（匹配等待）→ `star/heart_pink/sparkle/sprout/heart_pink_large/heart_green.png`
   - `messages/index.vue` → `default.png`、`heart_green.png`、`chat_hi.png`、`sprout.png`
   - `official-chat/index.vue` → `mascot_smile.png`（×2）
3. **`config/images.ts`**：
   - `IMAGE_PATHS.ICONS_V2.SPROUT = /mascot/sprout.png`（登录页 logo 小苗，login/index.vue:469）。
   - `POSTERS.LOGIN_ILLUSTRATION` / `POSTERS.NOT_LOGGED_WAITING` 属 posters/，非 mascot/。
4. **`config/emoji-map.ts`**：`MASCOT` 表引 **7 个 SVG**（`mascot_calm/crush/shy/cry/hug/sleep/like.svg`），`EMOJI_BASE='/static/assets/icons/emoji'`；这 7 图**已存在**于 `icons/emoji/`，走 emoji 链路，与 mascot/ 目录解耦。
5. **`EmptyState.vue`**：`mascot` prop → `<XunmiMascot :mood>`。业务使用：`discover/index.vue:248` 传 `mascot="sad"`（→ `mascot_cry`）。
6. **登录/未登录等待**：`NotLoggedWaiting.vue` 与登录页均为整图 posters，未直接用拆分素材。

### 2.3 结论

- **运行时全部消费 PNG**，`mascot/` 内 PNG 与代码引用是「既成事实」，主链路不依赖素材库 SVG。
- **素材库（SVG）与工程（PNG）双份并存**：迁移核心价值是**补齐矢量源到工程内**（可溯源、可放大、统一质量）+ 清理/归一统一路径。

## 三、迁移方案

### 3.1 推荐目标路径（二选一）

**方案 A（推荐，沿用指南既有约定）**
```
apps/client/src/static/assets/images/mascot/
```
- 与 `吉祥物使用指南.md` 声明的部署路径一致；
- `XunmiMascot.vue` 的 `imgSrc` 无需改动（仍拼 `.png`）；
- dev/mock 即时可用。

**方案 B（真机 2MB 门禁 / 后端托管）**
```
后端 app-assets（real 模式经 /api/v1/media/app-assets 托管）
```
- 依据 `config/images.ts` 注释：real 模式下资源直出后端；大图 PNG 可迁后端瘦包。但 `XunmiMascot.vue` 目前硬编码 `/static` 前缀，迁后需同步改组件走 `IMAGE_PATHS/resolveMediaUrl`，改动面大，建议延后。

> **建议**：以方案 A 为主落地；高频大图（如 mascot_default）如需瘦包，再评估迁后端。SVG 源体积极小，直接入库不影响 2MB。

## 五、风险与建议

1. **PNG 无矢量源风险**：代码只消费 PNG，源 SVG 丢失则无法追究分辨率/重绘。**建议**将 V2（纯 SVG）作为「主源」一次性导入工程 `mascot/`，形成「SVG 源 → PNG 交付」单一来源链。
2. **命名混析风险**：`default.png` 与 `mascot_default.png`、`happy/love/thinking/waving/sad` 与 `mascot_*` 并存。**建议**后续统一 `mascot_*` 并废弃旧语义文件（需同步改 `messages/index.vue:255` 等引用点）。
3. **`XunmiMascot` 硬编码 `/static` 前缀**：real（后端 app-assets）模式下不可用；需改 `imgSrc` 走 `IMAGE_PATHS/resolveMediaUrl`，属独立改造，不在迁移范围。
4. **登录 / 未登录等待页**非 mascot 拆分素材，迁移时勿将 posters 图片混入 `mascot/`。
