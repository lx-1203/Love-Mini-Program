## 一、项目信息

| 项 | 内容 |
| --- | --- |
| 项目名称 | 恋爱小程序（snake_case：`love_miniapp`） |
| 文档语言 | 中文 |
| 前端 | uni-app + Vue3 + TypeScript（`apps/client`，微信小程序） |
| 后端 | Java Spring Boot（`apps/api`） |
| 管理后台 | `apps/admin` |

### 原始需求复述（本次增量范围）

1. **修复首页帖子构建错误**：首页下方帖子出现构建问题，导致帖子内容无法正常加载。
2. **修复附近圈层模块**：该模块帖子无法正常显示，点击进入响应迟缓、存在明显卡顿，需优化加载与交互性能。
3. **修复消息聊天气泡尺寸**：我方与对方聊天气泡的长、宽、高不一致，我方气泡显得更粗，需统一双方 UI 尺寸规范。
4. **实现前后端数据同步**：确保所有功能模块的数据能够前后端完整同步，保证数据无错漏、可持久化存储并正常使用。

> 流程基准：注册/登录 → 基础资料 → 实名认证（必须，阻塞核心入口）→ 学生/人脸认证（可选）→ 兴趣偏好 → 恋爱名片 → 首页/附近/匹配/消息。本次增量须保证注册、资料填写等所有环节正常跑通。

---

## 二、产品目标

1. **内容可达**：首页与附近圈层帖子内容稳定加载、正常浏览，任何可见页面不因构建或渲染问题出现空白、报错或无法进入。
2. **体验一致**：消息聊天界面中我方与对方气泡在视觉尺寸规范上完全一致，聊天观感整洁统一。
3. **数据可靠**：全功能模块数据前后端完整同步，可持久化存储、可恢复、无错漏。

---

## 三、用户故事

1. 作为用户，我希望首页下方帖子能正常加载与浏览，以便快速了解校园圈内的新鲜动态。
2. 作为用户，我希望打开附近圈层时页面响应迅速、滚动流畅、点击即达，以便顺畅地发现附近的兴趣圈与帖子。
3. 作为用户，我希望聊天中我方与对方的消息气泡大小规范一致，以便获得整齐、无违和感的聊天体验。
4. 作为用户，我希望注册资料、认证信息、兴趣偏好、发帖与聊天等数据长期保存并在重新登录后完整恢复，以便不被重复填写或丢失。
5. 作为用户，我希望从注册到进入首页的完整流程顺畅无阻，以便首次使用即可体验核心功能。

## 五、验收标准

> 统一性能基线：**所有交互与数据操作响应时间 ≤ 300ms**。测试口径：开发者工具 + 真机（微信基础库最新稳定版），弱网/断网场景单独标注。

### R1 首页帖子构建修复

| 编号 | 验收标准 | 测试方法 |
| --- | --- | --- |
| R1.1 | 首页下方帖子列表正常渲染，无构建报错、无空白占位 | 开发者工具控制台无 error；真机 + 开发者工具各验证 1 次 |
| R1.2 | 帖子列表首屏加载耗时 ≤ 300ms（命中本地缓存时）；远程数据首次可正常展示 | 性能面板打点计时，3 次取均值 |
| R1.3 | 帖子字段完整渲染：作者头像、昵称、圈名、时间、正文、图片（最多 3 张）、点赞/评论/分享数 | 对照 DEV_PAGE_MAP 页面行为逐项核对 |
| R1.4 | 空数据场景显示友好空态文案（"今天还没有新的动态，去附近看看"），不报错 | 清空数据源后刷新页面验证 |

### R2 附近圈层性能优化

| 编号 | 验收标准 | 测试方法 |
| --- | --- | --- |
| R2.1 | 进入附近圈层页面，首屏渲染耗时 ≤ 300ms | 性能面板打点，3 次取均值 |
| R2.2 | 点击圈层/帖子进入详情，跳转响应 ≤ 300ms，无卡顿、无白屏 | 手动点击连续 5 次，逐次计时 |
| R2.3 | 列表滚动流畅，无明显掉帧；图片懒加载生效 | 真机连续滑动 30s 观察；Network 面板确认图片按需加载 |
| R2.4 | 数据加载失败时有明确错误提示与重试入口 | 断网后进入页面验证 |
| R2.5 | 帖子内容正常显示（不空白、不缺失字段） | 对照 R1.3 字段清单核对 |

### R3 消息聊天气泡尺寸统一

**统一后的气泡尺寸规范（双方完全一致，除方向外不得有视觉差异）：**

| 维度 | 规格（我方 / 对方一致） |
| --- | --- |
| 最大宽度 | 气泡容器 ≤ 屏宽 84% |
| 内边距 | 上下 16rpx、左右 24rpx |
| 圆角 | 主圆角 20rpx；我方右上角 4rpx、对方左上角 4rpx（气泡"尾巴"），其余三角统一 20rpx |
| 阴影 | 双方统一启用或统一禁用 box-shadow（消除"我方更粗"观感） |
| 头像 | 直径 64rpx、圆形、白边 2rpx |
| 正文 | 字号 30rpx、行高 1.6；emoji 消息字号 56rpx、行高 1.2 |
| 时间条/送达状态 | 时间条由父页面承载，送达状态图标 20rpx，与现有一致 |

| 编号 | 验收标准 | 测试方法 |
| --- | --- | --- |
| R3.1 | 我方与对方气泡的内边距、圆角档位、阴影、最大宽度完全一致（同一样式 token） | 代码审查：样式统一收敛到共享 token/变量 |
| R3.2 | 双方气泡视觉外轮廓（含阴影）宽度差 ≤ 2rpx | 同屏截图 + 像素级比对 |
| R3.3 | 同屏发送我方与对方各 3 条同长度文本消息，高度差 ≤ 2rpx | 截图量测 |
| R3.4 | 纯文本、emoji、图片、语音、引用消息 5 种消息形态双方渲染尺寸一致 | 逐一截图比对 |
| R3.5 | 头像、时间条、送达状态图标尺寸不变（不因本次修复回归） | 对照现规格核对 |

### R4 前后端数据同步与持久化

| 编号 | 验收标准 | 测试方法 |
| --- | --- | --- |
| R4.1 | 全功能模块（注册、资料、认证、帖子、附近、匹配、消息）读写接口前后端字段一致，无字段丢失 | 逐接口核对请求/响应字段 |
| R4.2 | 写入操作成功后，刷新或重新登录，数据完整恢复 | 造数 → 写操作 → 退出登录 → 重新登录 → 核对 |
| R4.3 | 读操作响应 ≤ 300ms；写操作成功返回 ≤ 300ms（不含外网波动场景） | 接口打点，3 次取均值 |
| R4.4 | 断网/弱网下操作有明确提示，重连后数据可恢复，不产生脏数据 | 断网写操作 → 恢复网络 → 校验数据一致性 |
| R4.5 | 认证信息仅用于身份校验，公开页面不暴露真实姓名、身份证号、学号、手机号、生物识别数据 | 抓包 + 页面核对（敏感信息原则） |

### R5 注册/资料填写流程验证

| 编号 | 验收标准 | 测试方法 |
| --- | --- | --- |
| R5.1 | 全流程跑通：注册/登录 → 基础资料 → 实名认证（必须）→ 学生/人脸（可选，可跳过）→ 兴趣偏好 → 恋爱名片 → 首页/附近/匹配/消息 | 新建测试账号完整走一遍 |
| R5.2 | 实名认证成功后立即解锁首页/附近/匹配/消息核心入口 | 认证成功页操作验证 |
| R5.3 | 任意公开页面仅显示"已认证/学生认证/真人认证"徽章，不显示实名原始数据 | 遍历 20 页公开页面核对 |
| R5.4 | 每一步操作响应 ≤ 300ms | 逐环节打点 |
| R5.5 | 可选认证可跳过，并可通过"我的→认证中心"补做 | 跳过 + 补做两路径验证 |

## 六、UI/UX 要求

1. **气泡一致性**：我方与对方气泡遵循 §五 R3 尺寸规范，仅颜色与方向不同；不得出现"一方比另一方粗/高/宽"的视觉差异。
2. **附近圈层**：加载过程展示骨架屏/加载态，列表滚动流畅，点击有即时反馈，错误态含重试入口。
3. **首页帖子**：加载态、空态、错误态三态完整；构建失败不得导致整页白屏。
4. **全局**：交互反馈（按钮态、跳转、数据变更）须即时可见，总响应 ≤ 300ms。

## 七、待确认问题（Open Questions）

1. **R1 首页帖子构建错误的根因**：是数据源/接口问题、字段映射问题，还是渲染/编译问题？需架构师勘察 `apps/client` 首页帖子链路后定位。
2. **R2 附近圈层卡顿根因**：是接口慢、数据量大，还是渲染性能？是否需引入分页/虚拟列表/懒加载策略？由架构师评估。
3. **R3 气泡规范口径**：以微信风格为准（我方右上角小圆角、对方左上角小圆角、双方阴影一致）是否确认？阴影统一为"启用"还是"禁用"？
4. **R4 数据同步范围**：是否覆盖消息已读回执、离线消息、语音/图片消息等场景？是否需要同步方案设计文档？
5. **R5 流程验证范围**：可选认证（学生/人脸）的"补做入口"与"认证中心"页面是否在本次验证范围内？
6. **性能基线口径**：300ms 是否以"开发者工具 + 真机（中等网络）"为准？弱网场景是否单独放宽阈值？
