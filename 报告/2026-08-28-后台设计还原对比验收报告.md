## 四、本轮发现并修复的偏差（原因 + 修复方案）

| # | 偏差（judge 证据） | 根因 | 修复 |
|---|--------------------|------|------|
| 1 | 用户管理筛选工具栏裸排灰底，未包白卡 | 共享 `.toolbar` 无容器样式 | 共享层给 `.toolbar` 加白卡（1px 边框 + 圆角 8 + 内距 12/16），全站列表页统一对齐 Frame 03/06 |
| 2 | 村落动态/活动管理表格「作者/分类/地点/校区」逐字竖排、行高失控；操作列贴边截断 | 模板沿用 uni-app `<view>` 标签在 Web 端为未知元素默认 `display:inline`，盒模型失效；且 `td` 无 nowrap 时列宽塌缩 CJK 逐字断行 | 全局令牌层补 `view{display:block}` 兜底；`td` 统一 `white-space:nowrap` + 表格 `min-width:880px` + 容器 `overflow-x:auto`（列宽不足横向滚动，行高恒 44px） |
| 3 | 举报管理末列表头「处理时间」被裁切 | 该页本地样式残留 `min-width:1200px` 覆盖共享值，表格 1200 > 容器 1009 且滚动截断 | 移除本地覆盖，回归共享 880px；复验表头 10 列完整显示 |
| 4 | 用户详情弹窗外露英文枚举 `bachelor`/`never` | 详情直出后端原始枚举 | 新增 `educationLabel`/`relationshipLabel` 中文映射（与编辑表单选项一致） |
| 5 | 详情弹窗字段标签整列 cobalt 蓝，违反「主色仅主操作/激活态」 | 局部样式误用主色 | 标签回归三级灰体系 |
| 6 | 详情弹窗「资料完整度: 资料完整度 100%」标签重复 | 值文案 i18n 自带标签 | 详情行值改为纯数值 `100%` |
| 7 | 顶栏混入 App 级语言切换浮层（设计中顶栏右侧仅搜索+头像）；长菜单时当前选中项可能在折叠线以下不可见 | App.vue 浮层无页面区分；无滚动定位 | 语言切换浮层仅保留在登录/403/404 独立页，后台内移入头像下拉菜单；路由变化时选中菜单 `scrollIntoView` |

另有「村居帖子 ↔ 村落动态」用词不一致，已统一 i18n 为「村落动态」。

## 五、过程中发现并修复的产品级缺陷（非视觉、影响全站）

1. **整站 CSS 失效（严重）**：`admin-common.css` 的 `:root` 令牌块被各组件 `<style scoped>` 引入，vue SFC scoped 编译把 `:root` 重写为 `:root[data-v-xxx]`，永远匹配不到 `<html>` → 全部 `var(--admin-*)` 未定义、所有样式声明失效、整站裸奔。
   修复：令牌块抽出为 `styles/admin-tokens.css`，由 `main.ts` 全局引入；共享组件类保留 scoped 引入。
2. **深链/刷新白屏（严重）**：业务路由为登录后动态注册，catch-all 404 兜底初始未注册 → 整页刷新/深链直达业务路径时无匹配路由、守卫直接放行 → router-view 空白。
   修复：`notFoundRoute` 启动即注册（vue-router 4 按路径打分匹配，静态/动态路由恒优先于通配符，不会抢占业务路由）。
3. **深链刷新退回看板**：守卫重入用 `{ ...to, replace: true }` 展开携带 `name:"NotFound"`，vue-router 对同时含 name/path 的 location 按 name 优先解析，再次命中 catch-all → 已知路径回退首页。
   修复：重入改为仅按 `{ path, query, hash, replace }` 解析。
4. **图表绘图区高度为 0**：`.chart-plot` 无显式 display，`<view>` inline 导致 height 失效（与 #2 同根因，一并由 `view{display:block}` 修复）；柱宽补 `max-width:28px + space-around` 防数据点少时过宽。

以上 4 项均已在生产构建 + 真实运行中复验。

## 六、已知有意差异（按真实功能组织，不判缺陷）

1. **侧边栏菜单**：为后端动态菜单驱动的真实功能模块（6 分组 / 36 页面，含 SUPER_ADMIN 专属过滤），非设计稿的 12 个演示项；分组标题样式按令牌 §10.1（12px/500 #8595a4）。
2. **数据**：全部来自真实后端（127 用户 / 圈层种子数据），非设计稿演示数据；趋势图当前仅 2 个数据点（08-25/08-26 真实匹配记录）；举报库暂无数据 → 统计卡为 0、表格空态。
3. **信息架构**：设计稿的「用户详情页」「三栏审核工作台」「列表+详情双栏」在真实产品中对应「列表 + 弹窗处理/详情」交互形态（操作路径更短），组件样式严格对齐同一令牌体系。
4. **KPI 语义**：设计稿「今日营收」在本产品无对应业务，替换为真实可统计的「今日活跃/待处理举报」等指标；未虚构数据。
5. **表格列**：设计稿「注册渠道」列后端无此字段，未虚构；近期注册表展示 用户ID/昵称/状态/注册时间。
