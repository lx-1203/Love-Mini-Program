## 二、模拟短信验证码（复现步骤）

**逻辑**：填入手机号 → 点"获取验证码" → **默认发送成功**（无真实短信网关）→ 输入返回的 mockCode → 即视为已收到短信 → 注册。

```bash
# 1) 发送验证码（模拟：返回 mockCode=123456）
curl -X POST http://127.0.0.1:8080/api/v1/sms/send-code \
  -H "Content-Type: application/json" -d '{"phone":"18600007777"}'
# → {"code":0,"data":{"mockCode":"123456","message":"验证码已发送（模拟短信…）"}}

# 2) 注册（携带 verificationCode）
curl -X POST http://127.0.0.1:8080/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"phone":"18600007777","password":"Test@123456","nickname":"研究账号乙","birthDate":"1998-08-08","verificationCode":"123456"}'
# → 200 { userId: 100002, token: "..." }

# 3) 边界：
#    - 缺 verificationCode → 400「请输入短信验证码」
#    - 错 verificationCode → 400「短信验证码错误」
#    - 验证码一次性（校验通过后 Redis 删除，防重放）
```

**前端入口**：登录页注册表单新增"短信验证码"输入框 + "获取验证码"按钮（60s 倒计时）。APP 端流程：手机号 → 获取验证码 → 输入 mockCode → 注册。

## 三、注册接口异常修复（本次核心修复）

**原问题**：real 模式 `POST /api/v1/auth/register` 任意新手机号均报"该手机号已注册"。

**根因（两处）**：

1. **phone 列 VARCHAR(32) 太短**：AES-GCM 加密手机号后 base64 密文约 52 字符 → INSERT 截断（SQL 1406）→ 被 `DataIntegrityViolationException` 误判为"手机号已注册"。
   - 修复：新增 Flyway 迁移 `V2026.08.26.0001__widen_users_phone_column.sql`（32→64）
2. **AES-GCM 随机 IV 查询缺陷**：注册存密文 A、登录加密生成密文 B（不同）→ `findByPhone(密文)` 永远查不到，手机号登录失败。
   - 修复：注册查重/登录查询改用**确定性 openid 派生键** `"phone:"+SHA-256(phone)`（注册时已用该格式写 openid），保留 AES 加密 phone 存储（R4-00249 安全口径不变），明文 phone 兜底兼容历史数据。

**涉及文件**：`RealAuthService.java`（注册查重 + 登录查询）、`AuthController.java`（RegisterRequest 加 verificationCode）、`SmsCodeService.java`（新建）、`SmsCodeController.java`（新建）、`SecurityConfig.java`（放行 /api/v1/sms/\*\*）、`ErrorMessages.java`（SMS_CODE\_* 常量）、`AuthService.java`/`MockAuthService.java`（签名同步）、`V2026.08.26.0001__widen_users_phone_column.sql`（新建）。
