### 1.1 匹配成功页渲染崩溃（P0，已修复并验证）

- **问题**：`/pages/discover/match-success` 直接打开时渲染空白，控制台持续报
  `Cannot read properties of undefined (reading 'slice')`（Vue runtime-1 错误），页面无法使用。
- **根因**：`src/view-models/match.ts` 的 `buildMatchReasons()` 直接调用 `user.tags.slice(0, 3)`。
  当从寻觅卡片「预览模式」/「URL 直达」进入匹配成功页时，`matchStore.matchedUser` 是仅含
  `{ userId, id, name, photo, avatar }` 的极简对象，**没有 `tags` 字段**，导致 `.slice` 崩溃。
- **修复**（`src/view-models/match.ts`）：
  ```ts
  const userTags = Array.isArray(user.tags) ? user.tags : [];
  const commonTags =
    myTags.length > 0
      ? userTags.filter((tag) => myTags.includes(tag))
      : userTags.slice(0, 3);
  ```
  同时对 `isSameSchool / isSameMajor / commonGround` 保持原有防御。
- **验证**：登录态打开匹配成功页，控制台错误数 **0**；页面正常渲染
  「匹配成功！→ 你和夏言互相喜欢了彼此 → 双头像+爱心 → 共同点进度卡 → 立即聊天/继续探索 → 分享喜悦」。

## 六、基础设施风险与建议（重要）

1. **微信开发者工具稳定性**：项目根目录为整个仓库（含巨型 `node_modules`），
   开发者工具文件监听会触发 `EMFILE: too many open files`，导致模拟器
   `onProxyError /__pageframe__/instanceframe.html`、`routeTo appLaunch timeout`、
   app 无响应、自动化超时。**规避方法**：彻底退出开发者工具 → 删除
   `%LOCALAPPDATA%\微信开发者工具\User Data\<hash>\WeappCache\WeappCompileCache`
   → 重新 `cli open` + `cli auto` → 静置 4-6 分钟等待编译完成后再操作。
2. **建议**：将 `miniprogramRoot` 单独建仓或将项目根收窄，避免监听整个仓库；
   或在 `project.config.json` 的 `packOptions.ignore` 中排除大目录（当前只影响上传）。
