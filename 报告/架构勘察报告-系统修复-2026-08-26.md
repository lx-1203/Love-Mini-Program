## 一、R1 首页帖子构建错误

### 1.1 数据链路（全链路核对）

```
home/index.vue:194  <CommunityFeed :items="viewModel.communityPosts" @select="openPost" />
        │
        ▼
view-models/home-dashboard.ts:84   communityPosts: feed?.communityPosts ?? []
        │
        ▼
stores/home.ts:77   homeFeed.value = data.homeFeed ?? null
        │
        ▼
services/api.ts:358   getHomeDashboard() → GET /api/v1/home/dashboard
        │
        ▼
HomeController.java:37-41   getDashboard() → HomeService.getDashboard(userId)
        │
        ▼
RealHomeService.java:404-424   getHomeFeed(userId) → buildCommunityPosts()
  ├─ RealHomeService.java:621-648   postRepository.findByStatusOrderByLikesCountDesc(active, PageRequest.of(0,2))
  └─ RealHomeService.java:420-422   空时回退 HomeFeedFallbackProvider.fallbackCommunityPosts()（1 条静态数据）
```

### 1.2 字段契约核对（正常）

后端 `record CommunityPostSummaryView`（`HomeController.java:182-193`）：
`id, authorName, authorAvatar, circleName, timeText, content, images, likeCount, commentCount`

前端 `HomeFeedView.communityPosts`（`api-types-supplement.ts:280`）与 `CommunityFeed.vue` 模板引用字段 **完全一致**，mock fixtures（`fixtures.ts:1073-1089`）也完整。**数据层字段无缺失**。

### 1.3 根因候选与定位

**候选 ①（高概率，观感问题）：`timeText` 输出原始 ISO 时间戳，未格式化相对时间**
- `RealHomeService.java:637`：`post.getCreatedAt() == null ? "" : post.getCreatedAt().toString()`
- 前端 `CommunityFeed.vue:27` 直接 `{{ post.timeText }}` 展示
- 影响：real 模式下帖子时间显示为 `2026-08-25T10:30:00` 这类原始时间戳，而 mock 数据是 `"15 分钟前"`（`fixtures.ts:1079`）。用户感知"帖子内容异常/未正常加载"。

**候选 ②（中概率）：`authorAvatar` 为 null 时头像区空白**
- `RealHomeService.java:635`：`author != null ? author.getAvatarUrl() : null`
- `CommunityFeed.vue:21`：`:src="post.authorAvatar || ''"` → 空串 src，头像 56rpx 圆形区域空白
- 若 seed 用户未上传头像，所有帖子作者头像空白，观感为"帖子内容没加载出来"。

**候选 ③（中概率）：未登录场景 `homeFeed` 可能恒 null → 帖子区恒空态**
- `home/index.vue:52-59`：`onShow` 仅在 `!homeFeed.value` 时拉取，若 `onShow` 早于 `bootstrap()` 完成（`userSession` 尚未就绪）会先触发一次请求；`sessionStore.isLoggedIn` 由 watch 兜底（`home/index.vue:63-70`），但该 watch 只在登录态**变化**时触发——未登录用户进入首页时 `homeFeed` 可能保持 null，`toHomeViewModel` 返回空数组，帖子区显示"今天还没有新的动态，去附近看看"。
- 真实请求路径：`getDashboard` 中 `SecurityUtils.getCurrentUserId()` 对未登录用户会走匿名路径（`HomeController.java:39`），`buildCommunityPosts()` 不依赖 userId 仍会查库，理论上有数据；但若 `postRepository.findByStatusOrderByLikesCountDesc` 抛 `DataAccessException`（如 DB 未初始化/表无数据），被 catch 后返回空列表再走 fallback——fallback 一定返回 1 条，所以 real 模式下**至少应显示 1 条**。此路若出现恒空，需抓实际响应体确认。

**候选 ④（低概率，需运行时验证）：模板内方法调用**
- `CommunityFeed.vue:35`：`<image v-for="img in post.images.slice(0, 3)" :key="img" .../>`
- uni-app vue3 编译 mp-weixin 时，WXML 表达式引擎对数组方法调用（`.slice()`）支持有限，若编译期未做表达式预处理会在运行时报错。**佐证**：`nearby/index.vue:415` 同样在模板内调用 `activityStore.activities.slice(0, 3)` 且活动区可正常显示，说明项目编译器对该写法是可用的（风险低），但仍建议在开发者工具中确认 CommunityFeed 编译产物与控制台无 error。

### 1.4 影响范围
- 首页"社区动态"区块（`CommunityFeed`）空态/内容显示异常；
- 不阻断其他模块；但若候选④成立会整页 JS 报错，连带今日推荐/兴趣圈等区块一起挂。

### 1.5 初步修复方向（待正式设计）
1. 后端 `buildCommunityPosts` 的 `timeText` 输出相对时间（或前端统一 `formatRelativeTime`，参考 `stores/village/utils.ts:621` 已有共享实现）；
2. 前端 `authorAvatar` 兜底 `IMAGE_PATHS.DEFAULT_AVATAR`；
3. 首页增加 Feed 级 loading / 错误态（当前仅空态），并保证未登录/异步未就绪时也能正常拉取；
4. 运行时验证 `post.images.slice(0,3)` 编译产物，必要时改为 computed 预切片字段。

## 二、R2 附近圈层模块（加载与交互性能）

### 2.1 模块组成与关系

- `nearby/index.vue`：附近 Tab 首页，分区为 ①附近的人 ②热门兴趣圈 ③校园圈 ④活动 ⑤附近动态（帖子）
- `people.vue`：附近的人 / 同城的人 列表页（`?scope=nearby|city`）
- **"附近圈层" ≠ "circles 兴趣圈"**：附近首页的"热门兴趣圈"数据来自 `circleStore.circles`（`GET /api/v1/circles`）；"附近动态"帖子复用 `villageStore.posts`（村口帖子流），**非独立数据源**。这是数据语义与性能问题的共同源头。

### 2.2 数据请求链与瓶颈量化

**A. 附近首页（`nearby/index.vue`）**

| 请求 | 触发时机 | 条件 | 数据源 |
| --- | --- | --- | --- |
| `getRecommendations({distanceMax:20})` | `onLoad`→`loadNearbyData`→`loadPeoplePreview` | 恒执行 | 后端推荐 |
| 同上 | `onShow` | 仅 `peoplePreview.length===0 && !peopleLoading` | 同上 |
| `fetchActivities()` | `loadNearbyData` | **仅 `getToken()`** | 活动 |
| `villageStore.fetchPosts({},true)` | `loadNearbyData` | **仅 `getToken()`** | 帖子 |
| `circleStore.fetchCircles()` | `loadNearbyData` | **仅 `getToken()`** | 兴趣圈 |

**瓶颈 ①（根因：帖子无法正常显示）**：未登录（或 token 失效）进入附近页，`loadNearbyData` 只执行 `loadPeoplePreview`，`villageStore.posts` 恒空 → "附近动态"显示 `nearby.postsEmpty` 空态。PRD R2.5"帖子内容正常显示"在不登录场景下无法满足。
- 位置：`nearby/index.vue:93-101`（`loadNearbyData`）、`:139-143`（`loadCirclePosts`）

**瓶颈 ②（根因：语义错误）**：`circlePosts = villageStore.posts.slice(0,6)`（`nearby/index.vue:57`）。`villageStore.posts` 是**全局共享的村口帖子流**（`stores/village/index.ts` state），无距离/城市过滤。用户在村口页切换过分类后，附近页展示的是村口最后一次请求的数据，**不是"附近"的帖子**；且首页+附近+村口三处共享同一 store，状态互相污染。

**瓶颈 ③（重复请求）**：`onLoad` 与 `onShow` 双入口触发 `loadPeoplePreview`。`onLoad` 先置 `peopleLoading=true`，`onShow` 因 `!peopleLoading` 短路跳过——但若首次请求失败（`peoplePreview` 仍空、`peopleLoading` 已复位 false），`onShow` 再次触发，无防抖/节流。位置：`nearby/index.vue:70-84`。

**B. 附近的人列表页（`people.vue`）**

- `onLoad`→`load()`：`getRecommendations(scope==='nearby' ? {distanceMax:20} : {})`（`people.vue:40-68`）
- 渲染：`scroll-view` 内 `v-for="item in list"` 全量渲染（`people.vue:154-183`），**无分页、无虚拟列表、image 无 `lazy-load`**。
- 排序：`cards.sort(...)` 对每条执行 `rank()`/`parseFloat()`，量级 O(n log n)，n 为推荐返回条数（登录用户不受 `GUEST_LIST_LIMIT=30` 限制，real 数据量可能更大，`RealRecommendationService.java:449-460`）。
- **瓶颈 ④（点击卡顿）**：`switchScope`（`people.vue:99-103`）无竞态 token、无 AbortController，快速切换"附近/同城"连续发请求，旧响应返回后覆盖新列表（A/B 数据闪烁）。进入页面时无骨架屏，白屏等 `load()` 完成。

**C. 点击进入响应迟缓**

- 点附近的人 → `openUserProfile` → `/pages/profile/other?userId=`（`navigation.ts:255-258`）
- 点帖子 → `/pages/village/detail?id=`（`nearby/index.vue:185-187`）
- `detail.vue` `onLoad` 会串行/并行拉取帖子详情、评论、相似作者，无 loading 骨架，首帧空白等待全部响应 → 感知"点击迟缓"。

**D. 图片渲染约束**
- `nearby-home image { max-width:100%; max-height:400rpx }`（`nearby/index.vue:486-489`）会约束页面内所有 image，与 `PostCard` 的 `aspect-ratio` 九宫格冲突，长图被压缩、大图被限高 → 帖子图片显示异常。

### 2.3 影响范围
- 附近 Tab 帖子区空态/数据错乱；附近的人列表在大数据量下滚动掉帧、点击白屏；
- `villageStore.posts` 全局状态污染村口页与首页社区动态。

### 2.4 初步修复方向
1. **数据隔离**：附近动态改为按距离/城市维度的独立请求（如后端新增 `GET /posts?nearby=1&distanceMax=` 或前端过滤 `distanceText`），不再直接切 `villageStore.posts`；
2. **加载策略**：`people.vue` 增加分页（后端 recommendations 支持 page 语义）或前端截断 + `lazy-load`；`switchScope` 加竞态 token + AbortController（参照 `home.ts:50` 已有模式）；
3. **未登录体验**：附近页未登录时展示"登录查看附近动态"引导而非空态；
4. **跳转体验**：detail 页加骨架屏/首帧即时渲染本地已缓存数据（`villageStore` 有列表数据可先渲染）；
5. **图片规范**：移除或收窄 `nearby-home image` 全局 `max-height`，改用 `PostCard` 内局部样式。

## 三、R3 消息聊天气泡尺寸

### 3.1 渲染链路

`chat-session/index.vue:1701-1733` → `<ChatBubble :sender="row.message.sender" .../>` → `components/chat/ChatBubble.vue`

### 3.2 根因定位：双方气泡样式差异（`ChatBubble.vue`）

| 样式 | 我方 `.bubble--self` | 对方 `.bubble--peer` | 差异影响 |
| --- | --- | --- | --- |
| 背景 | `#36C99A`（品牌绿实心） | `var(--c-bubble-other)` = `#FFFFFF`（`design-variables.scss:140`） | 颜色对比，深色视觉膨胀 |
| **阴影** | **继承 `.bubble` 的 `box-shadow: var(--s-sm)`**（`ChatBubble.vue:259`）；`--s-sm = 0 2rpx 8rpx rgba(15,23,42,0.04)`（`design-variables.scss:201`） | **`box-shadow: none`**（`ChatBubble.vue:283`） | **我方气泡四周有 8rpx 模糊阴影，外轮廓明显比对方"粗"** ← 核心根因 |
| 圆角 | `20rpx 20rpx 4rpx 20rpx`（右上"尾巴"4rpx，主圆角 **20rpx**） | `0 24rpx 24rpx 24rpx`（左上直角 0，主圆角 **24rpx**） | 主圆角档位不一致（20 vs 24） |
| padding | `var(--sp-3) var(--sp-4)` = 12rpx 16rpx | 同左（共享 `.bubble`） | 一致 |
| 最大宽度 | `.bubble-wrap { max-width: 84% }`（`:212`） | 同左 | 一致 |
| 头像 | 64rpx 圆 + 2rpx 白边（`:240-247`） | 同左 | 一致 |

**结论**：我方气泡"更粗" = **阴影残留**（self 有、peer 无）+ **主圆角档位不一致**（20 vs 24）+ **深色实心**三者叠加的视觉差异。padding/max-width/头像规格本已一致。

### 3.3 影响范围
- 聊天页全部文本/emoji/图片消息的气泡观感不对称；
- 与 PRD §五 R3 的验收口径（同一样式 token、外轮廓宽度差 ≤2rpx）冲突。

### 3.4 初步修复方向
1. `.bubble--self` 显式补 `box-shadow: none`（与 peer 统一禁用阴影；若产品要求统一启用，则给 peer 也加同档阴影）；
2. 主圆角统一收敛到同一 token（建议按 PRD 取 20rpx，尾巴 4rpx 保留方向差异：self 右上、peer 左上）；
3. padding 按 PRD 调整为上下 16rpx / 左右 24rpx（新增 token 或统一两处）；
4. 抽公共变量（如 `--bubble-padding`、`--bubble-radius-main`、`--bubble-shadow`）到 `design-variables.scss`，消除 self/peer 两处分写。

## 四、R4 前后端数据同步（抽查：帖子 / 附近 / 消息）

### 4.1 帖子链路字段不一致（重点）

**列表接口：`GET /api/v1/posts`** → `PostListResponse`（`PostSummaryView` 数组）

- `stores/village/utils.ts:112-153` `mapToPostItem`：
  - `content: raw.summary` ← 后端摘要字段（非全文）
  - **`images: []` ← 固定空数组，忽略后端列表响应中的图片**（`PostSummaryView` 若含 `images` 字段则属主动丢弃；若不含则属后端列表不返回图片）
- **后果**：村口/附近/首页社区动态等所有列表卡片（`PostCard.vue:172` `v-if="post.images.length > 0"`）**永远不显示图片**，仅详情页（`mapDetailToPostItem`，`utils.ts:158-184`，`images: data.images`）有图。这是 R2"帖子内容不完整/异常"的高概率根因之一。
- **修复方向**：核对 `PostSummaryView`（`village/PostSummaryView.java`）是否含 `images`；若含，`mapToPostItem` 透传；若不含，后端列表查询补充图片 URL（限制数量）。

**详情接口：`GET /api/v1/posts/{id}`** → `PostDetailView`，映射正常（`utils.ts:158-184`）。

**列表 vs 详情摘要截断**：`summary` 与 `content` 语义不同，列表页正文被截断，属预期设计但需在字段契约中明确。

### 4.2 附近 / 推荐链路

- 前端 `getRecommendations`（`api.ts:862-873`）→ `GET /api/v1/recommendations`，query 拼装与后端参数一一对应（`api.ts:84-122`）；
- 后端 `RecommendationController.java:212-282`：参数校验、隐私字段过滤（`PrivacyFieldFilter.sanitize`）、未登录走 guest 流（`GUEST_LIST_LIMIT=30`，`RealRecommendationService.java:489`）——**链路完整，无明显字段漂移**；
- 已知风险：登录用户推荐列表无条数上限（`RealRecommendationService.java:449-460` 仅 filter 不截断），数据量大时响应体大 + 前端全量渲染（对应 R2 卡顿）。

### 4.3 消息链路

- 会话列表 `fetchSessions`、消息列表 `fetchSessionMessages`、发送 `sendMessage`（`stores/messages.ts:510/599/812`）均有竞态 token 防护；
- 持久化：后端会话/消息落库（`chat` 包），前端 store 无本地持久化，重登后依赖后端恢复——符合预期；
- 已读回执：`markTempChatSessionRead` 等端点存在（`api.ts:397-405`）；**普通会话的已读回执链路未见端到端确认，需在正式设计阶段核对**。

### 4.4 数据同步问题汇总

| 问题 | 位置 | 影响 |
| --- | --- | --- |
| 列表接口不返回/不透传图片 | `PostSummaryView` / `mapToPostItem` | 列表帖子无图 |
| 列表正文用 `summary`、详情用 `content` | `utils.ts:112/158` | 列表与详情字段语义不同，未在契约标注 |
| `villageStore.posts` 全局共享无维度隔离 | `stores/village/index.ts` state | 附近/首页/村口数据互相污染 |
| 首页 `communityPosts.timeText` 原始时间戳 | `RealHomeService.java:637` | 与消息模块相对时间格式不一致 |
| 未登录场景部分受保护请求被跳过 | `nearby/index.vue:96-100` | 附近动态/活动/兴趣圈空态 |

### 5.3 认证规则要点（供 QA 验证）

- 注册强制出生日期，未满 18 岁返回 `403 MINOR_NOT_ALLOWED`（前端 `login/index.vue:231-233` 有专门文案分支）；
- 资料硬门槛 = `profileCompleted` 单字段（`session.ts:376-388`，已与 session-guard/page-access 对齐）；
- 未登录 `LockScreen` 引导 → 登录 → `consumePendingLoginRedirect` 自动进资料完善页（`navigation.ts:157-188`）；
- 敏感信息：推荐列表/他人主页经 `PrivacyFieldFilter.sanitize` 白名单过滤（`RecommendationController.java:274/281/378`），公开页不暴露手机号/身份证/学号。

### 5.4 链路风险点

1. **`login/index.vue:216` 登录后 `refreshSession()` 是 fire-and-forget**（`.catch()` 不 await），跳转发生在 1.5s 定时器后（`:223-227`），存在会话窗口竞争；虽注释说明"守卫自愈"，建议 QA 验证弱网下登录后首屏行为；
2. `bindSchool` 真实路径先 `getCampusProfile()` 再 `saveCampusProfile`，一次绑定 = 2 个请求（`session.ts:816-834`），弱网可能超时导致"绑定失败但未提示"（返回 false 静默）；
3. 实名认证为强阻塞入口，但附近首页的帖子/活动/兴趣圈在未认证（仅登录）时也已加载逻辑（`nearby/index.vue:96-100` 仅判 `getToken()`），与"实名后解锁核心入口"的产品规则存在张力，需在正式设计确认是否收紧。
