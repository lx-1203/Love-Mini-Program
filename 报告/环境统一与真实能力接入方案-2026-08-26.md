## 1. 现状与根因

### 1.1 构建与产物

- 微信开发者工具加载目录：根 `project.config.json` → `miniprogramRoot: apps/client/dist/build/mp-weixin`
- 2026-08-26 18:16 产物已验证包含新功能（`sortNearbyFirst`、`nearbyEmptyTitle`、`请先登录后再使用该功能`）
- 结论：产物没问题，工具需要手动「编译」/清缓存

### 1.2 为什么点击"没反应"

- `apps/client/.env.mp-weixin`：`VITE_API_MODE=real`、`VITE_API_BASE_URL=http://127.0.0.1:8080/api`（本地联调直连）
- 前端 real 模式下所有业务请求都打到 8080；后端必须真实可用，否则登录/列表/读写全部失败（表现为点了没反应）
- 实测：8080 有 java 进程（17:26 启动）且 `/api/v1/location/ip-city` 返回 200"南京"，但 `apps/api/target` 无 jar ⇒ 该进程来源不可复现，且与当前前端契约可能不一致
- 关键坑（pom.xml 已确认）：**fat jar 打包时 maven-jar-plugin 排除 `com/campuslove/api/mock/**`**，`java -jar xxx.jar --spring.profiles.active=mock` 是无效启动方式；正确 mock 运行方式为 `spring-boot:run`（跑 target/classes，mock 类仍在）

### 1.3 前后端对齐现状（实测）

| 维度 | 现状 |
| --- | --- |
| 前端分发 | `services/api.ts`：`useMock() = isMockMode()`；mock 走本地 fixtures（零网络），real 走 8080 |
| 后端接口 | 90+ Controller 面齐全（auth/third-party/security/media/verification/voice/village/chat/wallet/vip/shop/…），real profile 需 MySQL+Redis（+可选 RabbitMQ）+密钥 |
| mock profile | 排除了 DB/Redis/JPA/Flyway（application-mock.yml），本地零依赖可跑 |
| 缺口 | `target/` 无构建产物；无"一键跑通"脚本；无产物指纹自检 |

## 3.5 阶段二·B：小程序 ↔ 管理后台对应打通（数据全链路）

> 后台 = 管理员 Web（apps/admin），经 vite proxy `/api` → 后端 8080（admin 的 http.ts 已含幂等键/超时/401/下载能力）。
> 目标：小程序产生的数据后台能看能管，后台的配置/审核结果小程序能实时看到——"数据的流畅传输和查看"。

### 3.5.1 总体数据流（双向闭环）

```
① 小程序 →（业务 API）→ 后端 →（管理 API）→ 后台：查看 / 审核 / 下架 / 统计
② 后台 →（写配置/审核）→ 后端 →（app-config / 业务查询）→ 小程序：开关生效 / 状态回显
```

### 3.5.3 审核/下架闭环示例（实名认证）

1. 小程序提交实名申请 → 后端落库 `PENDING` → 小程序「认证中心」显示"审核中"
2. 后台 certifications.ts 拉取待审列表 → 查看证件图（经 media 鉴权代理）→ `review` 通过/驳回
3. 后台通过 → 后端状态 `APPROVED` → 小程序刷新后「认证中心」/个人页展示认证徽章
4. 驳回 → 后端 `REJECTED` + 原因 → 小程序提示并可重新提交

### 3.5.4 后台配置下发闭环示例（功能开关/站点）

1. 后台 config.ts 修改 `switches`（如关闭注册 `register_open=false`）
2. 小程序启动/切 Tab 拉 `/api/v1/app-config`（前端 useAppConfigStore 按 TTL 消费）
3. 登录页注册入口隐藏/禁用、开关即时生效（B6 机制已实现）

### 3.5.5 "流畅传输和查看"工程要点（验收基线）

- **分页契约统一**：后端 `AdminPageView{items,total,page,pageSize,totalPages}`，后台已按此解析；小程序端分页接口应口径一致
- **幂等**：admin http.ts 已对写请求注入 `Idempotency-Key`；小程序 http.ts 已有幂等键（API-CONTRACT.md:139 约定）→ 双端一致
- **字段脱敏**：身份证/手机号后端已脱敏响应；后台查看需授权 + 审计日志（AdminAuditLogController）
- **鉴权与会话**：小程序 JWT 与后台 admin token 隔离（`admin_v2_token`）；401 收敛跳转两侧均已实现
- **超时**：小程序请求 15s、上传 30s；后台 15s、长任务 120s
- **同源同库**：前后台数据同源（同一 MySQL），不引入二次同步，保证"看到的就是最新的"

### 3.5.6 双端验收矩阵（mock + real 各跑一遍）

## 4. 阶段三：真实能力接入清单

> 每条按「现状 → 需要准备 → 接入步骤 → 验证 → 成本/资质」说明。标 🔑 的为**需要你先申请/提供的账号或密钥**。

### 4.1 真实地理位置

- **现状**：前端 `utils/location.ts` 已调 `uni.getLocation(gcj02)` + 腾讯逆地理，但：① `manifest.json` 已在 2026-08-10 移除 location 权限声明 ⇒ 真机直接失败；② 逆地理 key 为写死的 `YOUR_KEY`；③ 后端仅有 IP 反查城市（`/location/ip-city`），无保存经纬度
- **需要准备**：
  - 🔑 腾讯位置服务 Key（lbs.qq.com「微信小程序专用 Key」，免费），用于逆地理编码
  - 微信小程序后台：配置 `request` 合法域名 `https://apis.map.qq.com`
- **接入步骤**：
  1. `manifest.json` 的 mp-weixin 段补回 `permission.scope.userLocation` + `requiredPrivateInfos: ["getLocation"]`（对应微信最新隐私接口要求）
  2. 更新「用户隐私保护指引」，声明位置用途
  3. `location.ts` 的 `YOUR_KEY` 改为环境变量注入（`import.meta` 不可用 mp-weixin，改用 config/env 新增 `VITE_MAP_KEY`）
  4. 增加 `wx.authorize` 拒绝授权后的引导
  5. 后端：`users/media` 相关表加 `latitude/longitude`（或 GeoHash）字段 + 距离计算端点；「附近」卡片距离由 mock `distanceText` 切换为真实计算
- **验证**：真机授权后首页/附近显示真实城市与距离；拒绝授权时按引导兜底
- **成本**：腾讯位置服务企业认证后免费额度内免费；个人可用基础额度

### 4.2 真实图片

- **现状**：后端 `LocalMediaStorageService` 本地磁盘存储 + `/api/v1/media/upload` + 鉴权代理下载；前端 `uploadFileViaUni`/`resolveMediaUrl` 已接通 ⇒ **本地 dev/mock 已可真实上传、访问**。生产两个限制：本地磁盘不跨实例共享；`?token=` 鉴权是权宜方案
- **需要准备**：
  - 🔑 对象存储（阿里云 OSS 或腾讯云 COS）：Bucket、AccessKey/Secret、自定义域名（HTTPS，可选 CDN）
  - 微信小程序后台：`uploadFile` / `downloadFile` / `request` 合法域名配为对象存储域名
- **接入步骤**：
  1. 实现 `OssMediaStorageService implements MediaStorageService`（按 `app.storage.type` 切换 local/oss）
  2. 媒体鉴权改为签名 URL（短期有效）或对象存储私有读 + 后端代理下载
  3. 图片压缩已用脚本；上传前可加客户端压缩（现有逻辑已限 ≤10MB）
- **验证**：上传照片 → 个人主页/帖子可见且可访问；跨实例（docker 多副本）图片不丢失
- **成本**：OSS 按量计费（存+流量，初期内容少费用极低）；CDN 可选

### 4.3 真实语音

- **现状**：后端 `VoiceMessageController`（real profile）已支持 mp3/aac/m4a、≤60s、上传/删除；前端 `VoiceRecorder` 真实录音 + 上传 + `VoiceMessageBubble` 播放 ⇒ **代码链路已通**，与图片共享存储链
- **需要准备**：同 §4.2（对象存储 + 合法域名）
- **接入步骤**：仅需保证后端以 real profile 部署（controller 对 real 生效）+ 域名配置正确；无需新代码
- **验证**：聊天发语音 → 对方可听；超过 60s 被拒
- **成本**：随媒体存储/流量计费

### 4.4 真实短信（验证码）⚠️ 目前是模拟

- **现状**：后端 `SmsCodeController.sendCode` 为**模拟**（总是"发送成功"并返回 mockCode 供联调输入）；前端已按真实契约调用。短信网关未接
- **需要准备**：
  - 🔑 短信服务商账号：推荐**腾讯云 SMS** 或 **阿里云 SMS**
    - SecretId / SecretKey（访问密钥）
    - **短信签名**（如「校园恋爱」）：审核需营业执照/小程序名称一致；个人主体审核受限，建议企业主体
    - **短信模板**：验证码模板（文案必须含「验证码」「xx分钟内有效」等合规词），得模板 ID
  - 后端接入需加的配置：`SMS_ACCESS_KEY_ID` / `SMS_ACCESS_KEY_SECRET` / `SMS_SIGN_NAME` / `SMS_TEMPLATE_ID`
- **接入步骤**：
  1. pom.xml 增加短信 SDK 依赖（腾讯云 `tencentcloud-sdk-java` sms 模块 或 阿里云 dysmsapi）
  2. 新增 `SmsProvider` 接口 + `TencentSmsProvider`/`AliyunSmsProvider` 实现；`SmsCodeService` 由"本地生成"改为"本地生成→ 短信发送 → 存 Redis/DB + 60s 重发间隔 + 日上限 + 失败降级"
  3. 真实模式下**不再返回 mockCode**（响应去掉该字段，或仅内网/测试 profile 返回）
