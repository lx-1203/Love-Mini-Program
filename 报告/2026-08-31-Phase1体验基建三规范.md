# Phase 1 体验基建三规范（转场 / 键盘 / 空态 CTA）

> 2026-08-31 落地。对标竞品「流畅感」三来源，给出规范 + 已落地的系统级实现。

## 一、转场规范（消灭白屏/反馈真空）

- **页面 loading 一律接骨架**：新页面必须用 `PageStateContainer`（loading 态已内置 `SkeletonBlock` 列表骨架）或显式 `<SkeletonBlock variant="list|profile|chat" />`。禁止裸 spinner、禁止「先白屏后内容」。
- **变体选择**：列表页=list（3 行）；详情/他人主页=profile；聊天=chat（4 行）。
- **按压反馈**：所有可点元素必须有 `hover-class="press-feedback--active"`（文字链同样要），保证点击 1 帧内有按压态。
- **已落地**：PageStateContainer（messages/circles/feedback）、助手聊天进入、兴趣圈、发布页。
- **待接入**：寻觅卡首拉、喜欢与访客列表/详情、编辑资料向导（每页约 5 分钟）。

## 二、键盘适配规范

- 底部输入条（聊天/发布）：容器监听 `keyboardheightchange`，`padding-bottom = 键盘高度`；input 加 `:adjust-position="true"` + `:cursor-spacing="20"`。
- 弹层/抽屉内输入：键盘弹起时弹层整体上移（translateY），禁止被键盘遮住输入焦点。
- 发送按钮：`confirm-type="send"` + `@confirm` 与点击双通道；键盘弹起时按钮保持可见。
- **待办**：全库 input 审计 `cursor-spacing`（一次性 30 分钟）。

## 三、空态 CTA 规范

- **每个空态必须带去路**：`PageStateContainer` 新增 `empty-action-text` + `@empty-action`（本次落地，全接入页生效）；独立 EmptyState 用 `action-text` + `@tap`。
- 文案公式：`发生了什么 + 现在能做什么`（例：「还没有动态 → 去发第一条」）。
- **待办**：给现存空态逐个补 CTA 文案与跳转（活动日历 0 结果、访客空、匹配空）。

## 四、需要什么（回答）

全部为前端代码与规范，**不需要后端/资质/素材**：骨架组件与 CTA 通道本次已建好；剩余为逐页机械接入与新页面规范遵守，建议以「代码评审 checklist」固化（骨架/按压态/空态 CTA/键盘 四项）。
