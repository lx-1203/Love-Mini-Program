# 五类真实能力接入说明书

> 项目：校园恋爱社交小程序（uni-app mp-weixin 客户端 + Spring Boot 后端 `apps/api`）
> 日期：2026-08-31
> 定位：本说明面向**商业化落地**口径，给出每类能力的资质门槛、接入路径、费用模型、项目现状对接点与上线优先级/风险。
> 说明：文中价格参考腾讯云/阿里云公开计费官网，标注「估算」处为区间参考值，实际以供应商当期报价为准。

## 一、地理位置（附近的人 · 同校定位）

| 维度             | 说明                                                                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **能力**         | 微信 `wx.getLocation`（前端定位）+ 腾讯位置服务（逆地理编码 / POI 检索 / 两点距离）；后端距离计算（Haversine / 地理围栏）。                                                             |
| **需什么资质 / 账号** | ① 小程序隐私与用户信息保护合规（上线需通过隐私协议审核、`requiredPrivateInfos` 声明）；② 腾讯位置服务开发者账号（`key` 需绑定 `appid` 并配置服务器请求域名 `apis.map.qq.com`）；③ 涉及「附近的人」需在类目描述中声明定位用途。 |

**接入方式（前端 + 后端）**

* 前端：`uni.getLocation({ type: "gcj02" })` 获取经纬度 → `wx.chooseLocation` 供用户自选位置 → 腾讯地图逆地理 `WS/geocoder/v1` 换城市名。

* 后端：接收经纬度，`DistanceUtil`（Haversine）计算两点距离；可选腾讯POI检索用于「学校/场所搜索」。

* 隐私合规：`scope.userLocation` 弹窗文案 + `<button open-type="openSetting">` 引导重新授权。

**费用模型**

* 腾讯位置服务：个人认证下每日免费调用量（逆地理/POI 免费额度数千次/日，估算）；达到阈值后建议购买**基础版套餐约 3000 元/年/百万次调用（估算）**。校园恋爱低频定位场景通常免费额度足够。

**项目对接点**

* 客户端定位工具已存在：`apps/client/src/utils/location.ts`——`fetchCurrentLocation()` / `reverseGeocode()`（当前 `key=YOUR_KEY` 为占位，需替换并配置请求域名）。

* 权限声明已存在：`apps/client/src/manifest.json` 的 `mp-weixin.permission.scope.userLocation` + `requiredPrivateInfos: ["getLocation"]`，配套 `scope.userLocation.desc` 文案。

* 后端：需新增 `DistanceUtil` 与「附近的人」接口（当前附近功能未接真实定位数据）。

**上线优先级与风险**

* 优先级：中。为「附近的人/同校匹配」地基能力，但依赖隐私审核与定位权限，建议配合校园认证后置上线。

* 风险：微信审核对定位用途审查严格，若实际未使用定位会被问询「声明定位无功能」；需确保功能真实落地后再上线。

## 二、真实图片（头像 / 相册 / 帖子图片）

| 维度             | 说明                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **能力**         | 用户头像 / 相册 / 帖子图片上传 → 服务端存储（`MediaAsset`）→ CDN/对象存储分发；违规检测兜底。                                                                               |
| **需什么资质 / 账号** | ① 微信 `chooseMedia`/`media` 授权（无需额外资质）；② 云存储账号（腾讯云 COS 或阿里云 OSS，需开通 + 授权密钥）＋可选 CDN；③ 内容安全建议接微信 `security.mediaCheckAsync`（免额外费用，需安全接口调用权限）。 |

**接入方式（前端 + 后端）**

* 前端：`wx.chooseMedia` 选图/拍照 → 本地压缩（`wx.compressImage`，建议头像 ≤ 500KB / 帖子图 ≤ 2MB）→ `uni.uploadFile` 上传。

* 后端：`MediaAsset` 落库（库表 + 存储打通现有 media 模块）→ 写入 COS/OSS → 返回 CDN URL → 异步调用 `security.mediaCheckAsync` 鉴黄/违规，违规拉黑该资源并人工复核兜底。

* 尺寸规范：仅接受图片（jpeg/png/webp），按头像/列表/详情三级尺寸裁剪建议。

**费用模型**

* 对象存储**按量付费（估算）**：存储约 0.1–0.2 元/GB·月（估算），外网下行流量约 0.1–0.8 元/GB（估算），请求数另计。

* 搭配 CDN（腾讯云 COS 内置 CDN，回源流量约 0.15–0.3 元/GB·月，估算）。

* 若图量大，可加「原图直传 COS（临时密钥 POST 直传）+ 服务端仅校验/转存 CDN」降低带宽成本。

**项目对接点**

* 后端媒体模块已存在：`apps/api/src/main/java/com/campuslove/api/media/`——`MediaUploadController` / `MediaAssetService` / `LocalMediaStorageService`（当前为本地存储实现，需扩展 COS/OSS `MediaStorageService` 分支）。

* 客户端上传链路已存在：头像/帖子图片均走 `uni.uploadFile` + `Authorization` 头（参考 `apps/client/src/services/voice-upload.ts` 的 `uploadFileViaUni` 规范）。

* 内容安全：当前无 `security.mediaCheckAsync` 调用点，需新增异步检测任务。

**上线优先级与风险**

* 优先级：高。照片是校园恋爱核心内容形态，真实图能力直接决定产品质感。

* 风险：① 内容合规为上线硬门槛，鉴黄不达标会被拒审/下架；② 对象存储密钥若硬编码造成泄露 → 密钥存环境变量并最小授权；③ 原图直传需防越权（用云增临时密钥），避开任意文件上传漏洞。

## 三、语音消息

| 维度             | 说明                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------ |
| **能力**         | 微信 `InnerAudioContext` 录音 / 播放；后端存储 + **60s 时长限制**；可选腾讯云 ASR 一句话识别（语音转文字）。                 |
| **需什么资质 / 账号** | ① 微信录音授权 `scope.record`（免资质）；② 语音文件直接沿用现有对象存储（同「真实图片」的 COS/OSS）；③ 转文字需腾讯云语音识别（ASR）开通并配置密钥。 |

**接入方式（前端 + 后端）**

* 前端：`wx.getRecorderManager()` 录音 → 15s 内缓冲、60s 上限 → 上传 Modal → `uni.createInnerAudioContext()` 播放。

* 后端：校验时长 ≤ 60s、格式（silk/mp3）与大小 → 写入对象存储 → 返回 `{url, duration, size}` → 可选异步 ASR 转文本并入库（便于检索/无障碍、防违规文本）。

* 隐私合规：`scope.record` 授权声明「用于发送语音消息」。

**费用模型**

* 存储：沿用对象存储按量付费（估算，语音体积小、成本极低，基本上可忽略）。

* **腾讯云 ASR 一句话识别**：按调用次数计费（约 0.5–1元/千次，估算），校园恋爱日活下月度成本个位数至几十元级别，可选能力，可后置。

**项目对接点**

* 语音链路已全量具备：`apps/client/src/components/chat/VoiceRecorder.vue`（录音）、`VoiceMessageBubble.vue`（播放气泡）、`apps/client/src/services/voice-upload.ts`（`uploadVoiceFile` 调 `POST /api/v1/chat/voice`，已带 Bearer token）。

* 后端：需确认 `VoiceMessageController` 的时长/大小校验已覆盖 60s 上限；`MediaAssetService` 可复用做语音持久化。

* ASR：当前无转文字逻辑，做语音违规检测时作为增强项接入。

**上线优先级与风险**

* 优先级：中高。语音是提升聊天亲密度/真实感的关键，且现有链路已就绪，接入成本低。

* 风险：① 微信对录音用途类目审查（需说明正常聊天用途）；② 语音违规内容需检测兜底（转文字后过内容安全）；③ 时长/大小校验缺失会导致存储滥用。

## 四、短信服务（验证码）

| 维度             | 说明                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------- |
| **能力**         | 验证码发送（手机号注册/登录/找回）→ 频控（1条/60s/手机号）→ 校验放行。                                                      |
| **需什么资质 / 账号** | ① 短信服务商账号（腾讯云 SMS / 阿里云 SMS，需企业认证）；② 签名审核（个人主体受限，需企业号）；③ **验证码类短信模板免类目资质，仅需企业认证**（营销类模板需类目报备）。 |

**接入方式（前端 + 后端）**

* 前端：输入手机号 → 60s 倒计时按钮 → 发送请求 → 输入验证码登录/注册。

* 后端：`POST /api/v1/sms/send-code` 生成 6 位验证码（Redis 存储 + 5 分钟过期 + 每手机号 1条/60s 频控 + 同 IP 限流）→ 腾讯云 SMS 单发 → 登录/注册接口再校验。

**费用模型**

* 单条验证码约 **0.04–0.05 元/条（估算）**；取号/发送均按量计费，另有腾讯云 SMS 最低充值限制。量级：万级用户注册/验证 ≈ 百元级/月（估算）。

**项目对接点**

* 后端调用点已存在：`apps/api/src/main/java/com/campuslove/api/auth/SmsCodeController`（`POST /api/v1/sms/send-code`，当前为**模拟发送**返回 `mockCode`）、`SmsCodeService`（`sendCode`/`verify`）、`RealAuthService`（注册/登录时校验 `verificationCode`）。

* 限流已存在：`com.campuslove.api.ratelimit` 的 `@RateLimit`（`AuthController` 的 `register`/`phone-login` 已有桶限流）、`RateLimitBucketRegistry`/`RateLimitAspect`；需补手机号维度 `1条/60s`。

* 替换为真实发送：将 `SmsCodeService.sendCode` 的 mock 实现替换为腾讯云/阿里云 SDK，并去掉返回值中的 `mockCode`（生产严禁回显验证码）。

**替代方案（强烈建议）**

* **微信** **`wx.getPhoneNumber`** **一键授权手机号**（`<button open-type="getPhoneNumber">` + code 换手机号）：微信小程序平台普遍采用此方案，**可 0 短信成本完成手机号绑定**，规避短信费用与模板审核。建议将其作为主要路径，SMS 仅作兜底（例如解绑/换绑）。

**上线优先级与风险**

* 优先级：高（登录链路依赖）。优先改用 `getPhoneNumber` 降本，SMS 作冗余兜底。

* 风险：① 未接真实短信则无法商业化（当前 mock 不可上线）；② 频控缺失会被营销短信轰炸刷量；③ 短信模板需通过企业短信审核，变更文案需重审（审批周期数小时–数天）。

## 五、实名认证（真实姓名 + 身份证 + 校园认证）

| 维度             | 说明                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| **能力**         | 校园身份认证（已有 `campus` 认证 + 学信网 CHSI）＋实人认证（真实姓名+身份证：腾讯云 eKYC / 阿里云实人认证）；未成年人保护（年龄门控）。                          |
| **需什么资质 / 账号** | ① 实人认证需**企业资质 + 场景报备**（金融级敏感场景需审批），个人开发者不可；② 学信网 CHSI 认证需院校合作/教育资质；③ 严格遵守《数据安全法》《个人信息保护法》个人信息最小化、敏感信息加密存储。 |

**接入方式（前端 + 后端）**

* 前端：实名页录入姓名+身份证 → 人脸核身 SDK（腾讯云 eKYC 活体检测）→ 校园页核对学籍（邮箱/学号/学信网验证码）。

* 后端：证件号 AES 加密落库（现有 `AesEncryptor`）→ 调用 eKYC/实人认证 API 校验身份证真实性与人脸一致性 → 通过后置 `idCardVerified` → 结合出生日期计算年龄，**未满约定年龄（如 18 岁）触发未成年人门控**（限功能或家长知情同意）。

**费用模型**

* **腾讯云 eKYC 实人认证**：约 1–3 元/次（估算）；阿里云实人认证按次计费（估算区间相近）。校园恋爱属低频高价值认证，仅注册/换绑时调用，成本可控。

* 学信网 CHSI：以院校/机构合作服务方案计费（估算，通常含年度服务费）。

**项目对接点**

* 校园认证模块已存在：`apps/api/src/main/java/com/campuslove/api/campus/`——`CampusCertificationService` / `RealCampusCertificationService` / `CampusController`（当前更多为校园圈子权益）＋学信网 CHSI。

* 实名模块已存在：`com/campuslove/api/verification/`——`RealRealNameCertificationService`（身份证号已过 `AesEncryptor` AES-GCM 加密落库、`maskIdCardNo` 脱敏返回）、`RealNameCertificationController`。

* 加密基建已存在：`com/campuslove/api/config/AesEncryptor.java`（AES-GCM）、`PasswordEncoderConfig`（BCrypt）、`utils/SensitiveDataMasker`。

* 未成年人保护：`apps/api/src/test/java/com/campuslove/api/common/AgePolicyTest` 已存在年龄策略测试，真实认证后可联动门控。

**上线优先级与风险**

* 优先级：高（是「真实校园恋爱」信任地基，也是未成年人保护/实名制合规要求）。建议实名 + 校园认证捆绑为同一信任体系。

* 风险：① 未接入 eKYC 前为「只存证件」模式，合规性弱于「实人核验」；② 人脸/证件为极高敏数据，泄露责任重大——务必加密存储 + 日志脱敏 + 共享敏感数据屏蔽；③ 场景报备不通过则无法使用金融级实人能力，需预留短信/学信网降级路径。

## 五类能力接入时间线建议

| 阶段                        | 周期      | 动作                                                                                                                                        |
| ------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **P0 · 商业化地基（第 1–2 周）**   | 上线前必做   | ① **短信/手机号**：切 `getPhoneNumber` 为主、SMS 兜底，补手机号 1条/60s 频控；② **实名**：接入 eKYC + 校园认证捆绑 + 年龄门控；③ **图片**：COS/OSS 落库 + `mediaCheckAsync` 违规检测兜底。 |
| **P1 · 产品竞争力（第 2–4 周）**   | 上线后首个迭代 | ④ **语音**：完成 60s 校验 + 转文字 + 违规检测；⑤ **定位**：接入附近的人 + 距离计算 + 权限声明复核上线。                                                                        |
| **P2 · 成本与体验优化（1–2 月滚续）** | 运营期     | ASR 增强、地理围栏推荐、实人认证频控、对象存储/CDN 用量与成本看板、降级链路上线。                                                                                             |

**风险总纲**

* 所有外部能力（SMS、eKYC、COS、腾讯位置、ASR）均需**企业资质 + 对应场景报备**，个人开发者无法全部获得 → 上线前完成主体企业认证。

* 敏感/个人信息必须遵循最小化原则，加密存储 + 日志脱敏 + 访问审计（项目已有 AES/BCrypt/Masker/AuditLog 基建）。

* 外部服务加**降级路径**：SMS 断 → 走 `getPhoneNumber`；eKYC 拒 → 走学信网/人工复核；定位失败 → 现有 fallback 文案。
