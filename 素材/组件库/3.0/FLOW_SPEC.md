# 页面与交互流说明

## 01 首页 / 发现
进入：App 启动后默认进入。
用户动作：
- 点筛选：打开底部筛选面板，选择距离、年龄、性别/偏好、学校。
- 点搜索：进入搜索页。
- 点人物卡：进入他人主页。
- 点喜欢：记录喜欢；若对方也喜欢，进入匹配成功。
- 点推荐列表：进入对应主页。
结果：
- 喜欢成功：按钮状态变为已喜欢，并显示轻提示。
- 双向喜欢：进入 08 匹配成功。
- 无更多推荐：显示空状态 + 调整筛选入口。

## 02 附近
二级筛选：附近的人 / 兴趣圈 / 校园 / 活动。
- 附近的人：按距离排序。
- 兴趣圈：按兴趣主题聚合用户。
- 校园：学校列表，再进入学校用户/活动。
- 活动：活动列表，再进入活动详情。
所有列表项统一支持：进入详情、关注、喜欢（在详情页完成）。

## 03 匹配中心
这是全局核心 CTA。
- 开始匹配 → 07 匹配中。
- 匹配成功 → 08 匹配成功。
- 取消 → 返回匹配中心。
- 今日次数用尽 → 显示次数用尽状态，引导完善资料或等待刷新。

## 04 消息
消息分三类：匹配消息、互动消息、系统通知。
点击普通会话 → 09 聊天。
未读消息在底部导航和列表中同步显示。
发送消息失败 → 保留输入内容并显示重试。

## 05 我的主页
模块：头像/认证 → 核心数据 → 资料 → 兴趣 → 动态/照片 → 设置。
- 编辑资料 → 10。
- 兴趣偏好 → 11。
- 校园认证 → 12。
- 设置 → 14。

## 06 他人主页
结构：身份 → 学校/距离 → 标签 → 简介 → 照片 → CTA。
CTA 只保留一个主操作：
- 未匹配：喜欢 TA。
- 已匹配：发消息。
关注属于次操作。
避免同时出现“喜欢、私信、关注、匹配”四个同等级按钮。

## 07 匹配中
这是明确的等待状态，不应堆信息。
- 显示进度/动画。
- 允许取消。
- 成功后自动进入 08。
- 失败/无结果回到 03 并说明原因。

## 08 匹配成功
只做两件事：发消息 / 继续探索。
不要在此页放大量资料。
“发消息”是主 CTA，“继续探索”是次 CTA。

## 09 聊天
消息气泡、时间、输入框、发送。
- 首次匹配可提供一条破冰建议，但不能自动代替用户发送。
- 图片/表情/更多功能从输入栏展开。
- 屏蔽/举报进入更多菜单。

## 10 编辑资料
修改昵称、年龄展示、学校、年级、地区、个人简介。
完成后统一保存并返回我的主页。
未保存离开 → 弹确认。

## 11 兴趣选择
首次注册必须至少选择 3 个兴趣。
编辑时显示已选状态和数量。
完成后更新推荐算法输入。

## 12 校园认证
三种方式：学生证、校园邮箱、人工审核。
认证中必须显示审核状态和预计处理信息。
认证成功后全局出现“已认证”标识。

## 13 搜索
搜索对象：用户、标签、学校。
热门搜索与历史搜索分组。
结果页按类型分组，不要把用户、学校、标签全部混成一条列表。

## 14 设置
账号安全、隐私、通知、帮助反馈、关于、退出。
危险操作使用粉色/红色警示，不使用主绿色。

## 15 活动详情
活动信息 → 发起人 → 报名 → 评论。
报名按钮固定在底部，滚动时保持可见。
评论支持点赞、回复；发起人回复需要明确层级。
