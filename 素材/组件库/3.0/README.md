## 调用原则
1. 页面统一 390×844，适配常见移动端基准稿。
2. 页面左右安全边距 20px；主要内容栅格以 8px 为基础。
3. Primary #34C98A：行动、确认、导航选中、认证。
4. Love #FF6FA3：喜欢、匹配、情绪结果，不要把所有按钮都染成粉色。
5. 背景 #F7FAF9，卡片 #FFFFFF，主文字 #333333，次文字 #8A9694。
6. 图片是内容主体，不能被过度装饰；人物照片保持统一圆角与裁切规则。
7. 一个页面只保留一个主 CTA，避免“关注 / 私信 / 喜欢 / 匹配”同时抢视觉焦点。
8. 匹配流程：发现 → 查看卡片 → 喜欢 → 双方喜欢 → 匹配成功 → 发消息。
9. 认证流程：我的 → 校园认证 → 选择认证方式 → 上传/验证 → 审核中 → 已认证。
10. 消息流程：消息列表 → 会话 → 发送消息 → 未读数更新 → 返回列表。

## 与原稿的核心修正
- 原稿存在多套导航范式：有“首页/缘分/发布/消息/我的”，也有“发现/附近/匹配/消息/我的”，需要统一。
- 原稿把“匹配”同时当作首页卡片按钮、底部中心 Tab、核心功能，语义冲突。统一为“匹配中心”作为底部中心主入口。
- 原稿首页同时出现“附近、不限、18–25岁、匹配优先、搜索、今日缘分、推荐用户、功能入口”，首屏任务过多。重构为：筛选 + 搜索 + 单张核心推荐卡 + 单一 CTA + 推荐列表。
- 原稿视觉存在两套风格：高饱和绿粉渐变的“恋爱产品”和偏灰白、校园工具感的“社区产品”。新稿规定绿=操作、粉=情感、灰=信息，避免角色混乱。
- 原稿部分页面图片风格不一致：真人摄影、AI 人像、插画、纯色头像混用。生产时必须建立统一素材规则：头像优先真实摄影/统一 AI 风格，比例和裁切一致；活动图统一 16:9。
- 原稿“发现/附近/校园/活动”层级混杂。建议“附近”下面再使用二级筛选：附近的人 / 兴趣圈 / 校园 / 活动。
- 原稿个人主页把“关注、粉丝、获赞、标签、视频、相册、资料”一次性铺开，信息密度过高。新稿优先身份 → 核心资料 → 兴趣 → 动态/照片，其他内容进入二级页。
