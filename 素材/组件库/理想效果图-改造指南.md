### 1.2 改造优先级路线图

```
P0（基础层，必须先做）
  ├── Token 色值微调（主色 #3DC994 → #36C99A，粉色 #FF6891 → #FF6B81）

  └── 阴影系统优化（绿色调柔和阴影）

P1（核心页面，重点改造）
  ├── 首页模块样式对齐（7 个模块逐一走查）
  ├── 匹配页三状态样式 + 动效对齐
  ├── 消息页改造（新增顶部通知双卡 + 助手对话增强）
  └── 个人主页改造（自己 + 他人 + 未登录态样式对齐）

P2（完善层，逐步优化）
  ├── 寻觅芽吉祥物组件（6 种表情 + SVG 实现）
  ├── 登录品牌页 + 未登录等待页美化
  ├── 空状态全页面替换（吉祥物插画版）
  ├── 动效优化（匹配动画 / 按钮交互 / 页面转场）
  └── 整体走查与像素级微调
```

### 5.3 微信小程序 SVG 使用注意事项

| 方案 | 优点 | 缺点 | 推荐场景 |
|------|------|------|---------|
| **image 标签引入** | 最简单，兼容性最好 | 不能改色（无法用 currentColor） | Tab 图标 / 彩色插画 |
| **内联 SVG 组件** | 支持 CSS 改色 / 动效 | 小程序 SVG CSS 支持有限 | 需要变色的图标 |
| **SVG 转 PNG** | 兼容性最好 | 放大模糊 / 体积大 | 小图标兜底 |
| **字体图标** | 体积小 / 易改色 | 维护成本高 / 多色困难 | 不推荐 |

**推荐方案**:
1. **Tab 图标 / 彩色插画** → PNG 图片（设计稿导出 2x/3x）
2. **单色功能图标** → 内联 SVG 组件（支持 `currentColor` 改色）
3. **吉祥物 / 复杂插画** → SVG 组件（带动效）

**小程序 SVG 兼容性测试清单**:

## 八、常见问题 FAQ

### Q1：微信小程序支持 SVG 的 `currentColor` 吗？

**答**：部分支持。
- 内联 SVG 中使用 `fill="currentColor"` 在微信小程序中基本可用
- 但 `stroke="currentColor"` 的支持程度因基础库版本而异
- 建议：单色功能图标使用内联 SVG + currentColor；彩色/复杂图标用 PNG 或 image 标签引入 SVG

**验证方法**:
```vue
<!-- 测试 currentColor 是否生效 -->
<view style="color: #36C99A;">
  <svg width="24" height="24" viewBox="0 0 24 24">
    <path fill="currentColor" d="..."/>
  </svg>
</view>
```

### Q2：自定义 TabBar 在小程序中性能如何？

**答**：性能可接受，但需注意以下几点：
- 现有代码已使用 `custom: true` 的自定义 TabBar（`custom-tab-bar/` 目录）
- 小程序原生自定义 TabBar 性能优于页面内自己实现的 TabBar
- 凸起按钮使用 `position: relative` + `margin-top: -36rpx` 实现，无性能问题
- ⚠️ 注意：TabBar 中的动画不要太复杂，避免影响页面帧率

### Q3：匹配页的卡片堆叠滑动怎么实现的？现有实现如何？

**答**: 现有实现位于 `components/discover/CardSwiper.vue`，基于 touch 事件手动实现。

**改造建议**:
- 保留现有滑动逻辑（已验证可用）
- 仅调整卡片圆角、阴影、信息层样式
- 滑动动效曲线可微调，更贴近理想效果图
- 如需要更丝滑的效果，可引入 GSAP 做动画插值

### Q4：吉祥物动效怎么实现？

**答**: 推荐方案：CSS 动画 + SVG 路径变换

| 动效类型 | 实现方式 | 性能 |
|---------|---------|------|
| 呼吸（上下浮动） | CSS `@keyframes` + `transform: translateY()` | 优 |
| 眨眼 | CSS `@keyframes` + `scaleY()` | 优 |
| 挥手 | CSS `@keyframes` + `transform: rotate()` | 优 |
| 表情切换 | v-if 切换不同 SVG 组件 | 优 |
| 路径变形 | SMIL 或 JS 控制 path.d | 中（小程序兼容性一般） |

**推荐**: 以 CSS 动画为主，避免使用 SMIL（小程序不支持）和复杂的 JS 动画。

### Q5：如何保证多端一致性（H5 / 微信小程序 / App）？

**答**:

1. **Token 层统一**：所有色值/圆角/间距通过 CSS 变量引用，不硬编码
2. **条件编译**：使用 `#ifdef MP-WEIXIN` / `#ifdef H5` 处理平台差异
3. **样式隔离**：组件样式使用 `scoped`，平台特定样式放单独文件
4. **测试清单**:
   - [ ] H5 端 Chrome 浏览器测试
   - [ ] 微信开发者工具测试
   - [ ] iOS 真机测试
   - [ ] Android 真机测试
5. **像素级对比工具**：使用截图对比脚本（项目内 `scripts/mp-shoot-*.cjs`）

### Q6：双源 Token（TS + SCSS）如何保证不漂移？

**答**: 项目已有双源同步约定，改造时遵循以下流程：

```
修改顺序：
1. 先改 design-variables.scss（SCSS 是色值源头）
2. 再同步修改 tokens.ts（JS 侧）
3. 最后检查 tokens.scss 的别名是否自动生效

验证方法：
- 运行项目自带的验证脚本（如有）
- 或手动对照两份文件的色值表
- 关键色值建立 checklist，每次修改后打勾
```

### Q7：如何处理设计稿中的渐变和模糊效果？

**答**:

| 效果 | CSS 实现 | 小程序兼容性 |
|------|---------|------------|
| 线性渐变 | `linear-gradient()` | ✅ 完全支持 |
| 径向渐变 | `radial-gradient()` | ✅ 支持 |
| 背景模糊 | `backdrop-filter: blur()` | ⚠️ 小程序部分支持，H5 良好 |
| 毛玻璃效果 | `backdrop-filter + rgba` 背景 | ⚠️ 需测试基础库版本 |
| 文字渐变 | `background-clip: text` | ⚠️ 小程序需加 `-webkit-` 前缀 |
| 投影/光晕 | `box-shadow` / `filter: drop-shadow` | ✅ box-shadow 支持，filter 部分支持 |

**降级方案**:
- `backdrop-filter` 不支持时，使用半透明纯色背景替代
- `drop-shadow` 不支持时，用 `box-shadow` 替代（方形元素）
