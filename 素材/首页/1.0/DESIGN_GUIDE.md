# 寻觅 A+B 融合版设计规范

## 一、核心理念
A「心动绿野」= 清新、校园、真实、社区。
B「心动甜莓」= 浪漫、年轻、情绪、心动。
最终融合：
- 绿色：品牌、校园、附近、可信
- 粉色：喜欢、心动、关系结果
- 紫色：浪漫、特殊兴趣
- 蓝色：消息、互动、辅助信息

不要把整个 App 做成粉色。粉色只在“恋爱动作”出现。

## 二、页面结构
底部固定：首页 / 附近 / 匹配 / 消息 / 我的。

本次重构：
1. 首页：今天值得遇见谁
2. 附近：附近的人 + 兴趣圈 + 校园 + 活动
3. 兴趣圈：同好破冰 + 发帖 + 回复 + 心动
4. 我的：可自由编辑的恋爱名片
5. 他人主页：共同点优先 + 动态 + 喜欢
6. 未登录：价值说明 + 轻登录

## 三、首页
首屏只解决一个问题：“今天可以认识谁？”
顺序：标题 → 搜索 → 今日心动推荐 → 热门圈子/校园内容。
不要恢复原来的大功能宫格；签到等弱功能放到次级位置。

## 四、附近
顶部筛选：附近 / 兴趣圈 / 校园 / 活动。
默认附近。
兴趣圈不是底部 Tab，而是附近中的“认识理由”。
展示：附近的人、热门兴趣圈、附近大学、附近活动。
圈子卡片要强调“共同兴趣”，例如“你们有3个共同兴趣”。

## 五、兴趣圈
不要做成传统论坛。
帖子必须帮助认识人：同校、附近、共同兴趣、回复、心动、活动。
发帖按钮叫“分享一下今天”，降低表达压力。
内容以生活化问题、照片、活动邀约为主。

## 六、我的主页
定位：恋爱名片，不是资料管理。
第一屏：头像、姓名、年龄、学校、简介、认证。
第二层：编辑我的恋爱名片、心动值。
第三层：动态、照片墙、兴趣、圈子。
自由调控：
- 模块显示/隐藏
- 长按拖动排序
- 每个模块设置可见范围
建议模块：简介、照片墙、兴趣、动态、我的圈子、心动值、校园信息。

## 七、他人主页
用户打开别人的主页，只需要回答：
“TA是谁？”、“我们有什么共同点？”、“我要不要互动？”
优先：大图 → 姓名年龄 → 学校/距离/在线 → 一句话 → 共同点 → 动态 → 喜欢/私聊。
身高、收入、职业等相亲资料放到“更多资料”，不要首屏堆砌。

## 八、未登录
不要用“禁止访问”。
用价值说明：
附近的人 / 兴趣圈 / 匹配聊天。
主按钮：“登录并开始探索”。
次按钮：“先逛逛”。

## 九、组件拆分
不要把整页转成一个 SVG。
建议：
icons/
  home, nearby, heart, users, chat, profile, search, plus, edit, back, more
components/
  bottom-nav
  interest-tag
  common-points
  circle-card
  post-card
pages/
  home
  nearby
  circle
  my-profile
  other-profile
  login

照片、头像、数量、文字、匹配率必须由 WXML 动态渲染。
SVG 负责固定图形、边框、背景和图标。

## 十、微信小程序实现
示例：
<image class="icon" src="/assets/icons/heart.svg" mode="aspectFit" />
<image class="nav" src="/assets/components/bottom-nav.svg" mode="aspectFit" />

WXSS：
.icon { width: 44rpx; height: 44rpx; }
.card { border-radius: 24rpx; background:#fff; }
.page { background:#F7FAF9; }

更推荐将 SVG 内部固定文字改成 WXML，SVG 只做视觉 shell；这样后续用户数据、学校、标签、动态都能实时变化。

## 十一、产品判断标准
一个页面最多 2~3 个视觉重点。
照片 > 人名/关系信息 > 共同点 > 次级资料。
恋爱动作使用粉色。
品牌动作使用绿色。
卡片用留白，不要靠大量阴影。
最终让用户感觉“这是恋爱社交空间”，而不是“校园信息管理工具”。
