# 寻觅设计系统 · 项目改造指南

> 适用对象：已有微信小程序代码库，希望接入「寻觅」设计系统进行视觉升级的开发团队
> 设计系统版本：v1.0
> 最后更新：2026-08

---

## 一、整体改造思路

### 1.1 改造原则

**渐进式改造，先全局后局部。** 不要试图一次改完所有页面，而是按照「全局基础 → 通用组件 → 页面细节」的顺序逐步推进，每一步都可以独立验证效果。

核心原则：
- **Token 优先**：先统一颜色、字体、间距等设计变量，后续组件和页面改造才能有据可依
- **组件复用**：优先改造通用组件，一次改造处处受益
- **页面兜底**：最后处理页面级细节，确保整体风格统一
- **兼容过渡**：改造期间新旧样式可共存，逐步替换而非一刀切

### 1.2 三步法

```
第一步：接入设计 Token
    ↓
第二步：替换基础组件
    ↓
第三步：页面级重构
```

| 阶段 | 目标 | 预计工作量 | 验证标准 |
|------|------|-----------|----------|
| 第一步 | 全局颜色/字体/圆角/阴影统一 | 0.5 天 | 全局无硬编码颜色，全部走 CSS 变量 |
| 第二步 | 6 个核心组件替换完成 | 2-3 天 | Button/Card/Avatar/Chip/Input/BottomNav 全部使用新样式 |
| 第三步 | 核心页面视觉升级完成 | 3-5 天 | 首页/匹配页/消息页/个人主页视觉统一 |

### 1.3 影响范围评估

改造前请先评估以下内容，制定适合团队的改造计划：

**低风险（可直接替换）：**
- 全局颜色变量（替换硬编码色值）
- 按钮样式（统一类名）
- 卡片统一样式
- TabBar 图标替换

**中风险（需逐一核对）：**
- 输入框样式改造（涉及表单校验逻辑）
- 头像组件（涉及状态点、认证标识）
- 标签/Chip 样式（涉及多种语义变体）

**高风险（需充分测试）：**
- 底部导航中间凸起按钮（涉及自定义 TabBar）
- 匹配页卡片滑动动效（涉及交互逻辑）
- 个人主页大头像区域（涉及复杂布局）

## 二、第一步：接入设计 Token

### 2.1 引入 colors_and_type.css

设计系统的所有 Token 都定义在 `colors_and_type.css` 中，包含颜色、字体、间距、圆角、阴影、动效等全部基础变量。

#### 接入步骤

**方式一：全局引入（推荐）**

在小程序根目录的 `app.wxss` 中通过 `@import` 引入：

```css
/* app.wxss */
@import "./styles/colors_and_type.wxss";

/* 其余全局样式 */
page {
  background-color: var(--color-background);
  color: var(--color-on-surface);
  font-family: var(--font-body);
  font-size: var(--font-size-body);
  line-height: var(--line-height-body);
}
```

> 注意：微信小程序中 CSS 文件后缀为 `.wxss`，请将 `colors_and_type.css` 重命名为 `colors_and_type.wxss` 后放入项目的 `styles/` 目录。

**方式二：按需引入**

如果只需要部分 Token，可以拆分成多个文件按需引入，但不推荐——维护成本会增加。

#### 微信小程序 CSS 变量支持说明

微信小程序基础库 **2.2.3 及以上版本** 支持 CSS 自定义属性（CSS Variables），覆盖目前 99% 以上的用户设备，可以放心使用。

使用限制：
- `page` 选择器上定义的变量全局可用（等同于 `:root`）
- 不支持 `@supports` 规则检测变量支持
- 变量不能用于 `wx:if` 等模板语法中，只能用于样式

#### 如何使用 CSS 变量

```css
/* 错误：硬编码颜色 */
.btn {
  background-color: #36C99A;
  color: #ffffff;
  border-radius: 22px;
}

/* 正确：使用设计 Token */
.btn {
  background-color: var(--color-primary);
  color: var(--color-on-primary);
  border-radius: var(--radius-full);
}
```

**命名约定：**
- 颜色变量：`--color-*`（如 `--color-primary`、`--color-accent`、`--color-surface`）
- 字体变量：`--font-*` / `--font-size-*` / `--font-weight-*` / `--line-height-*`
- 间距变量：`--space-*`（4px 基准，`--space-1` = 4px）
- 圆角变量：`--radius-*`（sm/md/lg/xl/2xl/full）
- 阴影变量：`--shadow-*`（1-5 级）
- 组件尺寸：`--size-*`（按钮、输入框、图标等）

#### 全局搜索替换建议

可以使用以下正则表达式在项目中全局搜索硬编码颜色，逐一确认后替换：

```
搜索：#[0-9A-Fa-f]{3,8}
```

替换优先级：
1. **先替换主色和心动粉** — 品牌色替换后视觉变化最明显
2. **再替换文字色和背景色** — 奠定整体基调
3. **最后替换边框和语义色** — 完善细节

> 注意：不要盲目全量替换！有些颜色可能用于特殊场景（如遮罩、渐变），需要逐一确认。

### 2.3 字体与字号

#### 字体栈设置

在 `app.wxss` 中统一设置全局字体：

```css
/* app.wxss */
page {
  font-family: 'PingFang SC', 'PingFang SC Regular', 'Microsoft YaHei', 'Hiragino Sans GB', sans-serif;
}
```

字体回退策略：
- **iOS**：PingFang SC（系统原生，最优效果）
- **Android**：Microsoft YaHei → 系统默认 sans-serif
- **开发者工具**：取决于系统安装的字体

### 2.4 圆角与阴影

#### 圆角规范

| Token | 数值 | 使用场景 | 示例 |
|-------|------|----------|------|
| `--radius-sm` | 8px | 小标签、图标按钮、紧凑输入框 | Chip 小标签 |
| `--radius-md` | 12px | 输入框、图片缩略图、次级卡片 | 搜索框、卡片内图片 |
| `--radius-lg` | 16px | 大输入框、弹窗、中等卡片 | 底部弹窗 |
| `--radius-xl` | 20px | 主卡片（卡片默认圆角） | 用户卡片、动态卡片 |
| `--radius-2xl` | 24px | 大容器、全出血元素 | 顶部 Banner |
| `--radius-full` | 9999px | 按钮、头像、标签、药丸元素 | 所有按钮、Chip |

**核心规则：**
- 所有按钮统一使用 `--radius-full`（药丸形），这是寻觅设计系统的标志性特征
- 所有卡片统一使用 `--radius-xl`（20px）
- 输入框使用 `--radius-md`（12px），消息输入框使用 `--radius-full`

#### 阴影规范

寻觅设计系统采用 5 级柔和阴影体系，全部使用暖灰色调，避免冷硬的黑色阴影。

| 级别 | Token | 使用场景 | 特点 |
|------|-------|----------|------|
| 1 级 | `--shadow-1` | 卡片默认态 | 极淡，仅用于区分层次 |
| 2 级 | `--shadow-2` | 卡片悬浮/按压态 | 轻微抬起，增加交互感 |
| 3 级 | `--shadow-3` | 浮动元素、底部导航凸起按钮 | 明显悬浮，有存在感 |
| 4 级 | `--shadow-4` | 弹窗、底部弹层 | 较强层级感 |
| 5 级 | `--shadow-5` | 全屏覆盖层、顶级 Toast | 最高层级 |

**阴影 CSS 速查：**

```css
/* 卡片默认阴影 */
.card {
  box-shadow: var(--shadow-1);
}

/* 卡片悬浮阴影 */
.card:hover {
  box-shadow: var(--shadow-2);
}

/* 浮动按钮阴影 */
.fab {
  box-shadow: var(--shadow-3);
}

/* 弹窗阴影 */
.modal {
  box-shadow: var(--shadow-4);
}
```

## 三、第二步：替换基础组件

完成 Token 接入后，开始替换核心组件。建议按照「使用频率从高到低」的顺序进行。

### 3.1 Button 按钮

#### 改造步骤

1. **在 `app.wxss` 中引入按钮样式**（从 `components.css` 提取 Button 部分）
2. **统一页面中的按钮类名**，替换为 `btn` + 变体类名
3. **逐一核对按钮类型**，确保语义正确

#### 按钮类型与使用场景

| 类型 | 类名 | 视觉 | 使用场景 |
|------|------|------|----------|
| 主按钮 | `btn btn-primary` | 薄荷绿填充 + 白字 | 核心行动：开始匹配、打招呼、提交 |
| 次按钮 | `btn btn-secondary` | 浅灰填充 + 深灰字 | 次要操作：取消、返回、跳过 |
| 描边按钮 | `btn btn-outline` | 透明背景 + 1px 描边 | 第三层级操作：查看更多、筛选 |
| 文字按钮 | `btn btn-ghost` | 透明背景 + 薄荷绿字 | 行内操作：查看详情、更多 |
| 心动按钮 | `btn btn-danger` | 心动粉填充 + 白字 | 心动/喜欢类操作：喜欢、超级喜欢 |

> 注意：`btn-danger` 在设计系统中是"心动粉"而非"危险"，因为恋爱社交产品中粉色承载的是心动语义。使用时请理解为"情感强调按钮"。

#### 按钮尺寸

| 尺寸 | 类名 | 高度 | 左右内边距 | 使用场景 |
|------|------|------|-----------|----------|
| 大 | `btn-lg` | 52px | 32px | 页面底部主操作、引导页 CTA |
| 中 | `btn-md` | 44px | 24px | 默认尺寸，卡片内按钮 |
| 小 | `btn-sm` | 36px | 16px | 紧凑区域、标签栏操作 |

#### 代码示例（WXML + WXSS）

**WXML：**

```xml
<!-- 主按钮 -->
<button class="btn btn-md btn-primary" bindtap="onMatch">
  开始匹配
</button>

<!-- 带图标的心动按钮 -->
<button class="btn btn-md btn-danger" bindtap="onLike">
  <text class="btn-icon">♡</text>
  喜欢
</button>

<!-- 次按钮 -->
<button class="btn btn-md btn-secondary" bindtap="onSkip">
  跳过
</button>

<!-- 描边按钮 -->
<button class="btn btn-sm btn-outline" bindtap="onFilter">
  筛选
</button>

<!-- 大尺寸主按钮（页面底部） -->
<button class="btn btn-lg btn-primary" style="width: 100%" bindtap="onSubmit">
  完成资料
</button>
```

**WXSS（按钮样式，放入全局或组件样式）：**

```css

  display: inline-flex;
  align-items: center;
  justify-content: center;

  white-space: nowrap;
  border-radius: var(--radius-full);

/* 尺寸 */

/* 主按钮 */

  background: var(--color-primary);

/* 次按钮 */

}

/* 描边按钮 */
.btn-outline {
  background: transparent;
  color: var(--color-on-surface);
  border: 1px solid var(--color-border);
}
.btn-outline:active {
  background: var(--interactive-hover);
  border-color: var(--color-primary);

/* 文字按钮 */

/* 心动按钮 */

  background: var(--color-accent);

  background: var(--color-accent-hover);
```

#### 改造 Checklist

- [ ] 所有按钮使用 `btn` 基类 + 变体类
- [ ] 按钮全部为药丸形（`radius-full`），无方角按钮
- [ ] 喜欢/心动类操作使用 `btn-danger`（心动粉）
- [ ] 主按钮使用薄荷绿 `btn-primary`
- [ ] 同一页面主按钮不超过 2 个
- [ ] 按钮有按压反馈（`scale(0.98)`）

### 3.2 Card 卡片

#### 卡片统一规范

所有卡片遵循以下基础规则：
- **圆角**：`--radius-xl`（20px）
- **背景**：`--color-surface`（纯白）
- **默认阴影**：`--shadow-1`
- **悬浮阴影**：`--shadow-2`
- **内边距**：默认 20px（`--space-5`）

#### 4 种卡片类型改造

##### 1. 用户卡片（card-user）

用于匹配页、推荐列表、附近的人等场景。

**结构：**
```
┌─────────────────────────────┐
│  ┌──┐  姓名 · 年龄 · 距离   │  ← card-header
│  │头│  身份标签             │
│  └──┘                       │
│  个人简介（最多两行）        │  ← card-body
│                             │
│  [ 喜欢 ]  [ 跳过 ]         │  ← card-footer
└─────────────────────────────┘
```

**WXML 示例：**

```xml
<view class="card card-user">
  <view class="card-header">
    <image class="avatar" src="{{user.avatar}}" mode="aspectFill"></image>
    <view class="user-info">
      <view class="user-name">{{user.name}}</view>
      <view class="user-meta">
        <text>{{user.age}}岁</text>
        <text class="dot"></text>
        <text>{{user.distance}}</text>
      </view>
    </view>
  </view>
  <view class="card-body">
    <text class="bio">{{user.bio}}</text>
  </view>
  <view class="card-footer">
    <button class="btn-like" bindtap="onLike">喜欢</button>
    <button class="btn-pass" bindtap="onPass">✕</button>
  </view>
</view>
```

##### 2. 动态卡片（card-feed）

## 五、SVG 素材库使用指南

### 5.1 SVG 在小程序中的使用方式

微信小程序对 SVG 的支持有一定限制，以下是三种常用方案：

#### 方式一：作为 image 引入（推荐）

直接将 SVG 文件放入项目，通过 `<image>` 标签引用：

```xml
<image src="/images/icons/heart.svg" mode="aspectFit" style="width: 24px; height: 24px;" />
```

**优点：**
- 使用简单，和普通图片一样
- 支持本地文件和 CDN 资源

**缺点：**
- 无法通过 CSS `color` 属性改色
- 需要为每种颜色准备一份 SVG 文件

**适用场景：** TabBar 图标、Logo、不需要换色的装饰元素

#### 方式二：转为 base64

将 SVG 转为 base64 编码，直接内联到 CSS 或 WXML 中：

```css
.icon-heart {
  width: 24px;
  height: 24px;
  background-image: url('data:image/svg+xml;base64,PHN2ZyB4bWxucz0iaHR0cDovL3d3dy53My5vcmcvMjAwMC9zdmci...');
  background-size: contain;
  background-repeat: no-repeat;
}
```

**优点：**
- 减少网络请求
- 可用于伪元素背景

**缺点：**
- 同样无法动态改色
- 代码可读性差

**适用场景：** 小图标、频繁使用的装饰元素

#### 方式三：使用 SVG 图标组件库

安装 `mini-program-icon` 等第三方图标组件库，或自己封装 SVG 图标组件：

```xml
<!-- 自定义 icon 组件 -->
<icon name="heart" size="24" color="#36C99A" />
```

实现原理：在组件内部根据 `name` 渲染对应的 SVG 代码，通过 `currentColor` 或 `fill` 属性控制颜色。

**优点：**
- 支持动态改色
- 使用方便，组件化管理

**缺点：**
- 需要额外开发或引入组件库
- SVG 代码会打包进 JS，增加包体积

**适用场景：** 功能图标、需要换色的图标

#### 微信小程序 SVG 注意事项

1. **不支持的 SVG 特性：**
   - `<style>` 标签内的 CSS 选择器（部分支持）
   - `<script>` 标签（完全不支持）
   - 外部引用的字体
   - 复杂的 filter 效果（部分支持）

2. **兼容性建议：**
   - 优先使用基础 SVG 特性（path、circle、rect 等）
   - 避免使用 SVG 2.0 新特性
   - 使用前在真机上测试

3. **文件大小优化：**
   - 使用 SVGOMG 等工具压缩 SVG
   - 移除不必要的注释和 metadata
   - 简化 path 数据

## 六、新增组件开发指南

### 6.1 如何新增一个组件

当设计系统提供的 6 个基础组件不够用时，可以按照以下规范新增组件。

#### 组件目录结构

在小程序的 `components/` 目录下创建新组件：

```
components/
  xunmi-button/          ← 前缀 xunmi- 表示设计系统组件
    index.js
    index.json
    index.wxml
    index.wxss
  xunmi-card/
    index.js
    index.json
    index.wxml
    index.wxss
  ...
```

> 建议使用 `xunmi-` 前缀命名设计系统组件，与业务组件区分开。

#### 组件开发流程

1. **明确组件用途和使用场景**
   - 这个组件解决什么问题？
   - 在哪些页面使用？
   - 有哪些变体和状态？

2. **对照设计规范**
   - 颜色：是否使用了 Token 中的颜色？
   - 圆角：是否符合圆角规范？
   - 阴影：是否使用了正确的阴影级别？
   - 间距：是否遵循 4px 基准间距？
   - 字体：是否使用了预设的字号层级？

3. **编写组件代码**
   - WXML：语义化结构
   - WXSS：使用 CSS 变量，不硬编码
   - JS：必要的交互逻辑
   - JSON：组件配置

4. **编写使用文档**
   - 组件说明
   - Props / Events 列表
   - 使用示例代码

#### Token 使用规范

**必须使用 Token 的场景：**
- 所有颜色值（背景、文字、边框）
- 所有圆角值
- 所有阴影值
- 所有间距值
- 所有字号和行高
- 所有动画时长和缓动函数

**禁止硬编码：**

```css
/* 错误 */
.xunmi-component {
  background: #36C99A;
  color: white;
  border-radius: 20px;
  padding: 16px;
  font-size: 16px;
  box-shadow: 0 2px 8px rgba(0,0,0,0.1);
}

/* 正确 */
.xunmi-component {
  background: var(--color-primary);
  color: var(--color-on-primary);
  border-radius: var(--radius-xl);
  padding: var(--space-4);
  font-size: var(--font-size-body);
  box-shadow: var(--shadow-1);
}
```

### 6.2 组件开发 Checklist

开发完成后，请对照以下 Checklist 检查：

- [ ] **颜色**：所有颜色都使用 CSS 变量，无硬编码色值
- [ ] **圆角**：圆角符合规范（卡片 20px、按钮 full、输入框 12px）
- [ ] **阴影**：使用 5 级阴影体系，不自定义阴影参数
- [ ] **间距**：使用 `--space-*` 变量，遵循 4px 基准
- [ ] **字体**：使用 `--font-size-*` 和 `--font-weight-*` 变量
- [ ] **字号层级**：文字大小符合预设的 9 级字号体系
- [ ] **按钮形态**：所有按钮都是药丸形（`radius-full`）
- [ ] **交互反馈**：有 hover / active 状态反馈
- [ ] **禁用态**：有 disabled 状态，透明度 0.45
- [ ] **无障碍**：文字颜色对比度足够（正文 ≥ 4.5:1）
- [ ] **响应式**：在不同屏幕尺寸下表现正常
- [ ] **深色模式**（如需要）：提供深色模式变量覆盖

## 七、常见问题 FAQ

### Q: 微信小程序支持 CSS 变量吗？

**A: 支持。** 微信小程序基础库 2.2.3 及以上版本全面支持 CSS 自定义属性（CSS Variables）。目前该版本覆盖率超过 99%，可以放心使用。

使用时注意：
- 在 `page` 选择器或组件根元素上定义的变量，其后代都可以使用
- CSS 变量不能用于 `wx:if`、`style="{{...}}"` 等模板语法
- 动态切换主题可以通过切换根元素的 class 实现

### Q: SVG 在小程序中不显示怎么办？

**A: 常见原因和解决方法：**

1. **SVG 文件格式问题**
   - 检查 SVG 代码是否包含 `<script>` 标签（小程序不支持）
   - 检查是否引用了外部资源（如外部字体、外部图片）
   - 使用 SVGOMG 工具重新导出纯净版 SVG

2. **image 标签问题**
   - 确认设置了 `width` 和 `height`
   - 确认 `mode` 属性设置正确（通常用 `aspectFit`）
   - 确认文件路径正确（相对路径 vs 绝对路径）

3. **Base64 方案兜底**
   - 如果本地 SVG 始终无法显示，尝试转为 base64
   - 在线转换工具：https://www.svgbackgrounds.com/tools/svg-to-css/

4. **PNG 兜底方案**
   - 对于关键位置的图标（如 TabBar），建议同时准备 PNG 版本作为兜底
   - 尺寸：@2x 和 @3x 各一份

### Q: 如何实现图标换色？

**A: 有以下几种方案：**

**方案一：多份 SVG 文件（最简单）**
- 为每种颜色准备一份 SVG（默认色、选中色、禁用色）
- 通过条件渲染切换不同的 SVG 文件
- 适合：TabBar 图标等颜色状态固定的场景

```xml
<image src="{{active ? '/icons/home-active.svg' : '/icons/home.svg'}}" />
```

**方案二：CSS mask（推荐）**
- 将 SVG 作为 mask-image，通过 background-color 控制颜色
- 适合：功能图标、需要动态换色的场景

```css
.icon {
  width: 24px;
  height: 24px;
  background-color: var(--color-primary);
  -webkit-mask-image: url('/icons/heart.svg');
  mask-image: url('/icons/heart.svg');
  -webkit-mask-size: contain;
  mask-size: contain;
  -webkit-mask-repeat: no-repeat;
  mask-repeat: no-repeat;
}
```

**方案三：自定义图标组件**
- 封装 icon 组件，内部渲染 SVG path
- 通过 props 传入颜色
- 适合：图标数量多、需要灵活换色的场景

### Q: 渐变背景怎么实现？

**A: CSS linear-gradient 完全支持。**

寻觅设计系统中常用的渐变：

```css
/* 品牌渐变（主色 → 心动粉）*/
.gradient-brand {
  background: linear-gradient(135deg, var(--color-primary), var(--color-accent));
}

/* 主色渐变（深 → 浅）*/
.gradient-primary {
  background: linear-gradient(135deg, var(--color-primary), var(--xunmi-primary-400));
}

/* 心动粉渐变（深 → 浅）*/
.gradient-accent {
  background: linear-gradient(135deg, var(--color-accent), var(--xunmi-accent-400));
}

/* 头像渐变环 */
.gradient-avatar-ring {
  background: linear-gradient(135deg, var(--color-primary), var(--color-accent));
}

/* 背景柔和渐变（用于页面顶部装饰）*/
.gradient-bg-soft {
  background: linear-gradient(180deg, var(--color-primary-container) 0%, transparent 100%);
}
```

### Q: 底部导航中间凸起怎么实现？

**A: 必须使用自定义 TabBar。**

实现步骤：
1. `app.json` 中设置 `"tabBar": { "custom": true }`
2. 创建 `custom-tab-bar/` 目录和组件文件
3. 中间位置使用 `position: absolute` + `top: -20px` 实现凸起效果
4. 中间按钮使用渐变背景 + 阴影增加悬浮感

注意事项：
- 自定义 TabBar 的每个页面都需要在 `onShow` 中手动设置选中态
- 适配 iPhone 等机型的底部安全区域（`env(safe-area-inset-bottom)`）
- 中间凸起按钮的点击区域要足够大（至少 44x44pt）

### Q: 设计系统的组件和我现有组件命名冲突怎么办？

**A: 建议使用前缀区分。**

- 设计系统组件使用 `xunmi-` 前缀（如 `xunmi-button`、`xunmi-card`）
- 业务组件保持原有命名
- 逐步替换业务组件中使用的样式，最终迁移到统一的设计系统组件

### Q: 改造期间如何保证新旧样式共存？

**A: 使用命名空间隔离。**

1. 新样式全部加前缀（如 `.xunmi-btn` 而非 `.btn`）
2. 老页面继续使用旧样式
3. 新页面 / 新模块直接使用新样式
4. 逐个页面迁移，迁移完成后移除旧样式

## 写在最后

设计系统的接入不是一次性的大改造，而是持续优化的过程。建议团队：

1. **建立组件使用规范**，新增功能优先使用设计系统组件
2. **定期 review**，发现不符合规范的地方及时修正
3. **持续迭代**，根据业务需求扩充组件库
4. **沉淀文档**，让新成员能够快速上手
