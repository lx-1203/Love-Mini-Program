## 4. 多角色深度分析（第十七辑）

### 4.1 👤 用户视角

本辑修复直接可感的三处：
1. **聊天不再双击重发**——弱网下连点发送按钮不再出现两条同样的话（文本发送 in-flight 锁）；
2. **暗色模式不再「明暗割裂」**——系统深色下首页/圈子/村口/个人资料等 30 个面板不再保持刺眼纯白（29 文件 token 化 + 车道C触点文件顺带）；
3. **换账号登录不再「串态」**——A 被强踢/改密/注销后 B 登录，不再继承 A 的签到标记/钱包余额/聊天草稿内存态，WS 也不再推送 A 的私信给 B（会话终结三路收口）。
其余为底层质量面（并发重复会话根治、限流补齐、WS 幽灵重连消除），随使用深度与数据量增长逐渐显现价值。

### 4.2 💼 投资人视角

尽调叙事新增三个维度：
- **「我们的依赖树没有已知漏洞」从此有审计依据**——pnpm audit 全仓递归清零（R17-1），这是第一辑以来首次把依赖安全纳入辑账；
- **「我们的并发面有 DB 级护栏」**——temp_chat 活跃对唯一键是「应用层 check-then-insert 必然存在并发窗口」这一结构性风险的 DB 级根治，尽调可比对迁移文件与恢复代码；
- **「我们的 API 有对外契约且契约被门禁看护」**——9 份 OpenAPI yaml 13 处漂移修复 + 门禁类型判点从 1→3，契约一致性从「手写文档」升级为「门禁看护的交付面」。
路线图维持已知、已排期：法律包+真机材料（外部流程）、七项登记带修法（内部排期）。

### 4.3 👨‍💻 程序员视角

本辑钉死的新认知：
- **分层验收链是新维度的正确载体**——5 车道并行（文件集互斥分区）→ 快验层（编译/typecheck 带修复循环）→ 全量层 → 契约链 → mock/real 双档真实验收；每一层只放行下一层，红门如实上报不伪造（跳过层也如实注明「跳过不伪造」）；
- **范式漏网是规律不是意外**（R16 认知延续）——本轮 3 个 P2 限流漏网端点与 13 处契约漂移全是「团队已有范式但特定入口漏网」，系统性扫描找漏网点而非发明新范式；
- **DB 约束是应用层并发的最后防线**——check-then-insert 的并发窗口只能靠唯一键闭合，应用层捕获回读是幂等语义层，两者缺一不可；
- **@Modifying 批量 DELETE ≠ 派生删除**——派生 deleteByX 是「先 SELECT 再逐行 remove」，N 行仍是 N 条 DELETE；批删必须显式 @Modifying JPQL；
- **契约漂移的结构性成因是「8 份 yaml 无消费者」**——generate:openapi 只吃 feedback yaml 一份，其余是无消费者的「契约孤岛」，漂移能存活的结构性原因；终态口径维持 R17 报告登记的「/v3/api-docs 运行时导出为唯一真相源」。

### 4.4 📊 数据模拟视角

数据模拟脚本（R14 产物 tools/data-simulation-r14.mjs）维持；本辑容量与并发账：
- **主包**：1715KB/2048KB（余量 333KB≈16%）硬闸在 mock/real 构建链强制（车道E复核确认）——本辑主包零新增页面，余量维持；
- **并发账**：temp_chat 活跃对唯一键把「重复活跃会话」从「该对用户持久 500」降为「幂等返回」，每对用户并发开聊的失败率→0；
- **限流账**：敏感端点限流覆盖从 47+ 处补至全域（+15 端点），配额参数集中且不回显（429 固定文案）；
- **依赖账**：audit 6→0。
