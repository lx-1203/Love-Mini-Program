## 附录 A：git 历史瘦身操作手册（P3-5，择窗口执行）

> 前提：团队全员知会；执行前 `git clone --mirror` 备份；执行后强推 + 全员重新 clone。

```bash
pip install git-filter-repo
git clone --mirror git@github.com:lx-1203/Love-Mini-Program.git love-mirror.git
cd love-mirror.git
# 1) 找出体积大头（reports JSON、大 PNG、历史 dump）
git filter-repo --analyze        # 看 .git/filter-repo/analysis/*-all-sizes.csv
# 2) 按路径剥离（示例：历史报告与大图移出历史；现存的先迁 LFS 再剥离旧历史）
git filter-repo --path reports/ --path-glob '*.png' --invert-paths
# 3) 大资产转 LFS（对新提交生效）：
git lfs migrate import --include='*.png,*.jpg,*.psd' --everything
# 4) 校验迁移链仍完整（235 个 V 文件一个不少）后强推
git push --force --mirror
```

预期收益：.git 1.47GB → 主要看 reports/历史 dump 占比；执行后 CI clone 时间与本地磁盘占用同步下降。
