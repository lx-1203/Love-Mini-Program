## (c) Proposed authored hooks + per-row verdict

### Convention first, per file (no new convention invented)

Every proposal below re-uses the BEM/modifier style already present **in that same file**, and all
pass `/^[.#][\w-]+$/` as a single token. The repo also has `id` precedent
(`pages/login/index.vue:714 id="login-phone"`,
`subpackages/profile-extra/verification/index.vue:598 id="verification-student-name"`,
`components/discover/CardDetailOverlay.vue:1023 id="panel-quick"`) — kebab-case, so `#…-switch`
ids are equally legitimate and `apply-ops-cellplans.mjs:116-118` explicitly blesses them.
`cellplan-source-shape`-era recheck note says it outright:
「apply-ops-cellplans.mjs:106-108 允许 #id 形态的 tapTarget，所以最省的诚实修法是给这枚 switch 加一个
id 或修饰类，而不是改判据。」

**Why the base+modifier pair, not just one modifier:** `tokenIn()`
(`apply-ops-cellplans.mjs:58-65`) whole-word-splits `class="…"`, and `settings/index`, `dnd`,
`privacy` each hold **two** switches. A bare shared `…__switch` token would be multi-hit, and
`r-exec-cli.mjs:594-598` drops inferred multi-hit selectors as 「归属不成立」. Only the `--weekly`
/ `--theme` / `--enabled` / `--urgent` / `--allow` / `--receive` modifiers give a unique first match.
(A hand-written `tapTarget` is allowed to be multi-hit — `r-exec-cli.mjs:203-205` `authorityTargets()`
takes it verbatim — but uniqueness is still the honest choice.)

### GATE PRECONDITION the implementation wave must not skip

`nameInBands()` (`apply-ops-cellplans.mjs:66-71`) requires `hit.length === w.per.length`, i.e. the
token must appear **verbatim in every band's `*.wxml`**, and `BANDS` defaults to only
`apps/client/dist/build/mp-weixin` + `mp-weixin-real` (`apply-ops-cellplans.mjs:25`).
Editing the `.vue` source is not enough — **both bands must be rebuilt** or the row is refused with
`新名字在产物里不成立：页 wxml 读不到…` / `只有 N/M 档逐字命中 …`.

### Corrections to the framing in my own brief (verified, not remembered)

1. **The predicate does NOT reject a scoped-hash class.** `^[.#][\w-]+$` matches `-` and `_`, so
   `.data-v-f489de86` passes (empirically tested against the literal regex; `data-v-f489de86` bare
   and `switch` are rejected). No gate in `apply-ops-cellplans.mjs`, `r-exec-cli.mjs` or
   `verify-source-shape.mjs` special-cases `data-v`.
   The real reasons a hash is unusable are elsewhere: it is not an authored/stable name (it is
   derived from the SFC and moves on rebuild), and on `settings/index`, `dnd` and `privacy`
   **both switches share the one hash**, so it cannot disambiguate. Report the blocker that way —
   "no stable authored name", not "rejected by the regex".
2. **Line drift:** the round-7/8 carriers quote the predicate as being at
   `apply-ops-cellplans.mjs:106-108` (see `PT25`/`PR05` recheck notes and
   `cellplan-round8-unverifiable.json` PR05 `why`). In the file on disk today it is at **:115-118**,
   same comment text. Cite `:118`.
3. **Multi-class tapTarget is illegal.** `.menu-item__switch menu-item__switch--weekly` fails the
   predicate (space); `tapTarget` must be the single modifier token.
4. **`BANDS` default excludes showcase** — `apply-ops-cellplans.mjs:25`:
   ```js
   const BANDS = (argAll("bands").join(",") || "apps/client/dist/build/mp-weixin,apps/client/dist/build/mp-weixin-real")
   ```
   Any name for a showcase-only state (VI09) cannot be verified without `--bands`.
5. **The whole-word matcher, `:58-65`** — matters because `tokenIn` is a class-attribute word-split,
   not a substring test: `.post-content` will **not** match `post-content-extra`; and `#foo` is
   checked as `id="foo"` in the wxml. So the proposed `--weekly` / `--theme` / `--enabled` /
   `--urgent` / `--allow` / `--receive` modifiers must actually be authored into the `class`
   attribute (not only into `:class` computed bindings, which compile to `class="{{[...]}}"` and
   land on the `pageWxmlText` axis rather than `pageWxmlExact` — see the `filter-chip` note in
   `cellplan-source-shape`-era rechecks at `unverifiable-recheck-3.json:236`).

**Authoring note for the implementation wave:** add the class as a **static** `class="…"` attribute
on the `<switch>` tag, not via `:class="{…}"`. Static attrs survive into `class="…"` verbatim in the
compiled wxml; computed ones become array-expressions and drop to the weaker text axis.
