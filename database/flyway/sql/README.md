# Flyway 迁移脚本目录

所有版本化迁移脚本（`V{日期}.{序号}__描述.sql`）放置于此目录，由 Flyway 按版本号顺序执行。

## 版本号规范（R4-00416）

- 版本号格式：`V2026.06.25.0001`（日期 + 4 位当日序号），当日序号从 `0001` 递增。
- **已应用的历史脚本不得改名/改号/删改内容**（Flyway 按文件内容计算 checksum，
  `validateOnMigrate=true` 下改号或改内容会导致存量库校验失败）。
- **新迁移必须使用大于现有最大版本号的顺序号**，禁止复用/跳过。
- 迁移文件描述段（`__描述`）不得包含双下划线占位符语法（历史上曾误用
  `__xxx__` 占位符与迁移文件名中的 `__` 冲突导致解析失败，见 flyway.toml 注释）。

## 迁移脚本约束

- 迁移必须幂等（可安全重跑）：UPDATE 天然幂等；INSERT 使用
  `WHERE NOT EXISTS` / `ON DUPLICATE KEY` 防重；DDL 依赖 Flyway 单次执行
  （MySQL 不支持 `CREATE INDEX IF NOT EXISTS`，重复执行会报错——依赖
  Flyway 的校验，不要试图在 SQL 里做 DDL 幂等）。
- 含占位符的脚本：占位符使用 `${xxx}` 语法（Flyway 默认），由
  `flyway.toml` / `application-real.yml` 的 `spring.flyway.placeholders` 注入；
  占位符值为空时 Flyway 会失败（fail-fast，禁止弱默认值）。
- 演示种子类迁移使用 `demo_seed` 占位符守卫（默认 `false`，生产不灌演示数据）。
- 破坏性修复迁移（如清理数据）必须在文件头写明备份提示与回滚说明。
