## 审计范围

对 `apps/client/src/` 下所有 162 个文件进行了 i18n 审计。**未检测到任何 i18n 函数调用**（无 `$t()`、无 `i18n.t()`、无自定义 `translate()` 函数、无 `vue-i18n` 依赖）。项目所有面向用户的文本、mock 数据、错误消息、时间格式化等全部为简体中文硬编码。

### 1. services/mocks/fixtures.ts — 200+ 硬编码字符串 (HIGH)
**文件:** `apps/client/src/services/mocks/fixtures.ts`

这是项目中硬编码字符串最集中的文件。所有 mock 数据（用于开发和测试）均为中文：

- 用户假数据 (30+ 字符串): 包含用户昵称、个人简介、标签
  ```typescript
  nickname: "清风徐来",
  bio: "喜欢旅行和摄影的阳光大男孩",
  tags: ["摄影", "旅行", "健身", "美食"]
  ```
- 动态/帖子假数据 (50+ 字符串): 包含帖子正文、评论、回复
  ```typescript
  content: "今天的晚霞特别美，分享给大家",
  comments: [{ content: "好美啊！在哪里拍的？", ... }]
  ```
- 聊天消息假数据 (40+ 字符串): 包含对话内容
  ```typescript
  messages: [
    { text: "你好呀", sender: "other" },
    { text: "你好！很高兴认识你", sender: "me" }
  ]
  ```
- 活动数据 (20+ 字符串): 包含活动名称和描述
- 系统通知假数据 (15+ 字符串)

**影响:** 即使项目引入 i18n，mock 数据中的中文仍需要额外处理。建议 mock 数据也使用 i18n key 或分离到语言包中。

## 修复优先级建议

1. **立即规划:** 引入 `vue-i18n` 框架，创建 `zh-CN` 语言包结构，确定 key 命名规范（如 `pages.login.agreement`）
2. **重点文件首批迁移:**
   - `login/index.vue`（用户协议法律文本）
   - `services/mocks/fixtures.ts`（影响所有开发环境）
   - `utils/time.ts`（被所有页面使用的时间格式化）
3. **Store 错误消息迁移:** 为 14 个 Store 文件创建统一的错误消息模块
4. **分批迁移:** 按功能模块（chat、discover、profile、village、settings）分批次迁移
5. **CI 集成:** 添加 ESLint 规则禁止在 `<template>` 和 JS 中出现中文字符（除 i18n key 外）
